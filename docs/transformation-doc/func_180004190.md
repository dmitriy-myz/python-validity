# sub_180004190 — scatter-mark a presence/occupancy byte-map from an index list

A tiny leaf helper. It walks a list of `n` byte-sized *indices* and, for each index
value `idx`, writes `1` into a destination byte array at `dst[idx]`. In other words it
builds a boolean "seen / present / used" lookup table (a 256-entry-or-smaller bitmap-as-bytes)
from a list of small integer IDs.

This is **not** transform math.** It contains no fixed-point arithmetic, no matrix/affine
ops, no trig, no sorting and no coordinate computation. It is a pure memory-scatter
("set membership flag") idiom that a *caller* uses, e.g. to dedupe or mark which keypoint /
tile / index IDs are already present before building the geometry. Relevance to `sec0_pre`
frame registration is at most indirect (a marking pass used by a transform-building caller).

## Signature

The function takes **four register args** by the x64 Windows ABI (rcx, rdx, r8, r9) but it
*ignores* the incoming `rcx` (immediately zeroed and reused as the loop counter) and instead
reads its real source pointer and count from the **stack** slots `[rsp+0x30]` and `[rsp+0x38]`.
Those stack slots are the *home/shadow space* of the 4th and 5th arguments respectively, i.e.
the caller passed at least `r9` (4th arg) and a 5th stack arg, and the prologue-less callee
re-reads them from memory. Faithful inferred signature:

```c
// rcx (1st reg arg): IGNORED on entry (overwritten with 0, used as loop index i)
// rdx (2nd reg arg): uint8_t *dst   — destination presence map; dst[idx] gets set to 1
// r8  (3rd reg arg): == [rsp+0x30] at call site (4th-arg home) = const uint8_t *src (index list)
// r9  (4th reg arg): == [rsp+0x38] at call site (5th-arg home) = int32_t n (count of indices)
//
// NOTE on calling convention: the body reads src from [rsp+0x30] and n from [rsp+0x38].
// Under the standard x64 home-space layout those are the homes of the 4th and 5th args.
// The cleanest reading is that the *intended* prototype is the 5-arg form below and the
// first two reg args (the original rcx, and r8) are unused/dead on this path.
void sub_180004190(
    void    *unused_rcx,          // overwritten immediately, not read
    uint8_t *dst,                 // rdx  — base of the byte presence/occupancy map  [GUESS name]
    void    *unused_r8,           // r8   — dead (real src comes from stack home below)
    int32_t  unused_r9,           // r9   — overwritten from [rsp+0x38]
    const uint8_t *src,           // [rsp+0x30] — list of byte indices to mark        [GUESS name]
    int32_t  n                    // [rsp+0x38] — number of indices (signed)          [GUESS name]
);
// Effective behaviour:  for (i = 0; i < n; i++) dst[ src[i] ] = 1;
// Return: ret 0  (no return value; `ret 0x0` = stdcall-style 0-byte stack cleanup)
```

> Because the 4th/5th args are fetched from `[rsp+0x30]`/`[rsp+0x38]`, the *register* names
> `r8`/`r9` shown by the disassembler for those slots are coincidental homes — treat
> **`src = [rsp+0x30]`** and **`n = [rsp+0x38]`** as the authoritative inputs.

## Pseudocode

```c
// ---- entry: 0x180004190 ----
int64_t  n   = (int32_t)*(int32_t*)(rsp + 0x38);   // 0x180004190  movsxd r9,[rsp+0x38]  (SIGNED)
int64_t  i   = 0;                                  // 0x180004195  xor ecx,ecx           (loop index)
if (n <= 0) goto L_ret;                            // 0x180004197/0x18000419a test r9,r9 / jle  (SIGNED <=)

uint8_t *src = (uint8_t*)*(void**)(rsp + 0x30);    // 0x18000419c  mov r8,[rsp+0x30]     (index list base)
// 0x1800041a1..0x1800041ac: data16/nop padding — loop-alignment only, no effect

// ---- loop body: 0x1800041b0 ----
do {
    uint64_t idx = (uint8_t)src[i];                // 0x1800041b0  movzx eax,byte[rcx+r8]  (ZERO-extend; idx in 0..255)
    i += 1;                                        // 0x1800041b5  add rcx,1
    // cmp i, n                                    // 0x1800041b9  cmp rcx,r9
    dst[idx] = 1;                                  // 0x1800041bc  mov byte[rax+rdx],1     (*** the scatter write ***)
} while (i < n);                                   // 0x1800041c0  jl 0x1800041b0          (SIGNED <)

// ---- exit ----
L_ret:                                             // 0x1800041c2
return;                                            // 0x1800041c2  ret 0x0
```

Notes:
- `movsxd` (entry) is a **signed** 32→64 widen of `n`; `jle`/`jl` are **signed** compares, so a
  negative `n` (or `n==0`) skips the loop entirely.
- `movzx eax, byte[...]` is a **zero**-extend: every index is treated as an unsigned byte `0..255`.
  Combined with `mov byte[rax+rdx],1`, the destination buffer must be at least `max(idx)+1` bytes
  (caller-guaranteed; typically a 256-byte table or a buffer sized to the index domain).
- The write is unconditional and idempotent (writing `1` repeatedly is harmless), so this is a
  classic "build a membership/occupancy flag array" pass.

## GDB verification hooks

To verify a Python re-implementation (`for i in range(n): dst[src[i]] = 1`) produces identical
state, set these breakpoints and dump:

- `break *0x180004190` (entry) — capture inputs **before** the loop:
  - `x/1dw $rsp+0x38`  → `n` (signed count). Expect `> 0` to enter the loop.
  - `x/1gx $rsp+0x30`  → `src` pointer value.
  - `p/x $rdx`         → `dst` base pointer.
  - `x/<n>bx <src_ptr>` → dump the whole input index list; this is the ground-truth input.

- `break *0x1800041b0` (top of loop body) — fires once per element. On each hit:
  - `p $rcx`            → current index `i` (0,1,2,…).
  - `x/1bx $rcx+$r8`    → `src[i]`, the index about to be marked (compare to your `src[i]`).
  - `p/x $r8`           → confirm `src` base is stable across iterations.

- `break *0x1800041bc` (the scatter write) — the load-bearing line. On each hit:
  - `p $rax`            → `idx` (the zero-extended byte just read). This is the offset being set.
  - `p/x ($rdx + $rax)` → absolute address of the byte being written `= 1`.
  - (optional) after stepping, `x/1bx $rdx+$rax` should read `0x01`.

- `break *0x1800041c2` (exit) — verify final map:
  - `x/<DOMAIN>bx <dst_ptr>` (e.g. `x/256bx`) → dump the complete presence map; every byte that
    corresponds to a value appearing in `src` must be `0x01`, all others unchanged from entry.
  - Cross-check: number of `0x01` bytes equals the number of **distinct** values in `src`.

Recommended one-shot capture: log `($rax)` at `0x1800041bc` for every hit → that ordered list of
indices is exactly what your port must reproduce (and the dedup'd set is the final map).

## Confidence & open questions

**Solid (high confidence):**
- Control flow and arithmetic are unambiguous: a `for (i=0; i<n; i++) dst[src[i]] = 1;` scatter.
- `n` is **signed** (movsxd + jle/jl); indices are **unsigned bytes** (movzx). The written flag is
  literally `1`. No callees, no fixed-point, no transform/geometry math. This function is **not**
  part of the rigid-transform computation itself.
- The body's effective inputs are `dst` (rdx), `src` (`[rsp+0x30]`), `n` (`[rsp+0x38]`).

**Inferred / open:**
- **Names** `dst`/`src`/`n` are semantic guesses; the disasm only proves "byte map", "byte list",
  "count". What domain the indices live in (keypoint IDs? tile IDs? section indices?) is *not*
  determinable from this function alone — it must be read at the **call site**.
- The mismatch between the register-ABI args (`rcx`,`r8`,`r9`) and the stack reads
  (`[rsp+0x30]`,`[rsp+0x38]`) is the one subtlety. The two clean explanations: (a) the intended
  prototype really has 5 args and the callee re-reads the 4th/5th from their home slots (so the
  caller may pass them only on the stack), or (b) this is a tail/fall-through fragment of a larger
  routine whose prologue stored those args. Either way the **observable behaviour** is fixed:
  source list from `[rsp+0x30]`, count from `[rsp+0x38]`, destination from `rdx`. Confirm by
  inspecting the caller's argument setup at the call site.
- **Buffer size of `dst`** is caller-guaranteed (must cover `max(src[i])`); commonly 256 bytes if
  indices are full bytes, but could be smaller if the index domain is bounded — verify at caller.
