# sub_1800095c0 — generic `qsort` (median-of-3 quicksort with custom comparator)

**Verdict: this is NOT transform/geometry math.** It is a faithful copy of the MSVC CRT
`qsort()` (Bentley-McIlroy 3-way partition, median-of-3 pivot, recurse-on-smaller /
loop-on-larger, with an alignment/width-driven swap dispatcher). It sorts an array of
fixed-width records in place using a caller-supplied comparator function pointer.

It is *relevant to* sec0_pre / template building only insofar as some caller uses it to
sort keypoints / candidate records before transform fitting — but the function itself
computes no coordinates, no fixed-point, no matrices. There is no `>>16`, `*65536`,
`0x8000`, `atan2`, `sqrt`, or affine arithmetic anywhere in its 2443 bytes; the only
arithmetic on data is integer division by `width` to convert byte-offsets back to element
indices for the recursive call.

---

## Signature

Standard `qsort` ABI. Inferred C signature:

```c
void sub_1800095c0(
    void*  base,        // rcx  : pointer to array start
    int    num,         // edx  : element count  (recursion passes a sub-count here)
    int    width,       // r8d  : size of one element in bytes
    int  (*compar)(const void* a, const void* b)   // r9 : comparator, <0 / 0 / >0
);
```

Notes / guesses:
- `num` (`edx`/`ebp`) is the element count of the (sub)range being sorted. The recursive
  self-call at `0x180009c96` and the tail-loop re-entry at `0x180009cd4` both feed a
  *sub-count* here.
- `compar` is invoked indirectly the whole time — stored on the stack at `[rsp+0x98]`
  (the home/spill slot for the 4th arg `r9`) and frequently re-loaded into `r10` before
  `call r10`. Its contract is the libc one: returns sign(a−b).
- Return type is `void` (eax holds comparator results transiently; nothing meaningful is
  returned). Both `ret` sites (`0x180009e1b`, `0x180009f4b`) leave eax undefined-by-design.

This matches the classic `void qsort(void*, size_t, size_t, int(*)(const void*,const void*))`.

## Pseudocode

Conventions used below:
- `base` = the array pointer for the current (sub)range = `rcx`/`r9` (`[rsp+0x28]` is its spill).
- `n`    = element count of current range (`ebp` at entry).
- `w`    = `width` (`r8d`/`r11d`; spill at `[rsp+0x90]`).
- `cmp`  = comparator (`[rsp+0x98]`, loaded to `r10`).
- `swap_mode` ∈ {0,1,2} chosen at entry, spilled to `[rsp+0x20]`.
- `did_swap` flag spilled to `[rsp+0x80]` (set when partition actually swapped — controls a
  fast-path optimisation, exactly like CRT qsort's `swapped` heuristic).
- All `swap(p,q)` helpers exchange `w` bytes; the three inlined variants only differ by
  granularity (1 dword / N dwords / N bytes) — see "swap idiom" note.

```c
void qsort(void *base /*rcx*/, int n /*edx*/, int w /*r8d*/, cmpfn cmp /*r9*/) {
    // ---- prologue / arg spill ----                              // 0x1800095c0
    spill r9->[rsp+0x20]; r8d->[rsp+0x18]; edx->[rsp+0x10];        // 0x1800095c0..0x1800095ca
    save rbx,rbp,rsi,rdi; sub rsp,0x58;                           // 0x1800095ce..0x1800095d2
    r10 = cmp;  r11 = w;  ebp = n;  r9 = base;                    // 0x1800095d6..0x1800095de
    [rsp+0x28] = base;                                            // 0x1800095e1

  L_TOP: // recursion/tail-loop re-entry target                  // 0x1800095e6 (jmp target from 0x180009cd4)
    // ---- choose swap granularity (alignment + width) ----
    if ((base & 3) != 0 || (w & 3) != 0)                          // 0x1800095e6 / 0x1800095ec
        swap_mode = 2;                                            // 0x1800095fd  (byte swap)
    else
        swap_mode = (w != 4) ? 1 : 0;                             // 0x1800095f4..0x1800095f8
    did_swap = 0;                                                 // 0x18000960b ([rsp+0x80]=eax=0)
    [rsp+0x20] = swap_mode;                                       // 0x180009607
    [rsp+0x38] = (int64)swap_mode;                                // 0x180009612..0x180009615  (sign-extended)

    if (n < 7) goto L_INSERTION;        // unsigned cmp ebp,7     // 0x180009604 / 0x18000961a -> 0x180009e1c

    // mid = base + (n>>1)*w    (pivot slot)                      // 0x180009620..0x180009628
    rbx = mid = base + (n>>1)*w;

    if (n <= 7) goto L_PIVOT_DONE;       // (unsigned)            // 0x18000962b -> 0x18000982f
    // ---- median-of-3 (and median-of-9 for large n) pivot ----
    rdi = hi = base + (n-1)*w;           // last element         // 0x180009634..0x18000963e
    rsi = lo = base;                                             // 0x180009637
    if (n <= 0x28 /*40*/) goto L_MED3;   // small: plain med-of-3 // 0x180009641 -> 0x1800097c8

    // --- median-of-9 (ninther) for n > 40 ---                  // 0x18000964a
    rcx = (n>>3)*w;                       // 1/8-span step (bytes)// 0x18000964a..0x18000964f
    [rsp+0x48] = 2*step ; rbp = base + 2*step;                   // 0x180009653..0x18000965d
    [rsp+0x40] = step   ; rsi = base + step;                     // 0x180009661..0x18000966b
    // sort the triple (lo=base, rsi=base+step, rbp=base+2*step) by cmp,
    // leaving rsi = their median:                               // 0x180009670..0x1800096ca
    median3(&base, &rsi, &rbp) -> rsi;     // calls cmp up to 3x  // 0x180009673..0x1800096ca
    // sort the triple around mid (rbx): rax=mid-2step, rbx pivot, rbp=mid-step ... -> rbx median
    median3(rbx-2step, rbx, rbx-step) -> rbx;                    // 0x1800096ca..0x18000973f
    // sort the triple around hi (rdi): rax=hi-2step, rbp=hi-step, rdi ... -> rdi median
    median3(hi-2step, hi-step, hi) -> rdi;                       // 0x18000973f..0x1800097c0
    r10 = cmp;                                                   // 0x1800097c0

  L_MED3: // pick median of (rsi, rbx, rdi) into rbx as pivot     // 0x1800097c8
    if (cmp(rsi, rbx) < 0) { ...  } else { ... }   // 3-way order // 0x1800097c8..0x18000980f
    // result: rbx points at the chosen pivot element

  L_PIVOT_DONE: // ensure pivot is at base[0]                     // 0x18000982f
    r10 = cmp; base = [rsp+0x28]; w = [rsp+0x90];                // 0x18000981a..0x18000982e
    if (swap_mode == 0) {                 // dword swap pivot<->base[0]   // 0x18000982f..0x180009835
        swap_dword(rbx, base);                                   // 0x180009837..0x18000983f
    } else if (swap_mode == 1) {          // pivot<->base, w/4 dwords     // 0x180009843..0x18000986b
        for (k = w/4; k>0; k--) swap_dword(rbx+4k, base+4k);     // 0x18000984b..0x180009869
    } else {                              // swap_mode==2, w bytes        // 0x18000986d..0x180009889
        for (k = w;   k>0; k--) swap_byte (rbx+k,  base+k);      // 0x180009870..0x180009889
    }
    // pivot now lives at base[0]; set partition fingers
    n--;                                                          // 0x18000988b (ebp += -1)
    rbx = lo = base + w;                  // first unknown (left) // 0x18000988e..0x180009891
    [rsp+0x30] = w;                                               // 0x180009895
    rbp = hi = base + (n)*w;              // last unknown (right) // 0x18000989a..0x18000989e
    rdi = lo;  [rsp+0x40] = lo;                                   // 0x1800098a1..0x1800098a4
    rsi = hi;                                                     // 0x1800098a9

  // ================= 3-way (Bentley-McIlroy) partition =========
  L_OUTER: // 0x1800098b0
    if (lo > hi) goto L_PART_DONE;        // (unsigned ja)        // 0x1800098b0 -> 0x180009a95

    // ---- scan lo upward while cmp(lo, pivot) <= 0 ----
  L_SCAN_LO: // 0x1800098c0
    c = cmp(lo /*rcx=rbx*/, base /*rdx=r9*/);                     // 0x1800098c0..0x1800098c6
    if (c > 0) goto L_SCAN_HI_FROM_LO;                           // 0x1800098cb -> 0x1800099af
    if (c != 0) {                          // c < 0 : just advance// 0x1800098d1 -> 0x18000998c
        rax = w; goto L_LO_ADVANCE;                               // 0x18000998c
    }
    // c == 0 : equal element -> swap into the left "equal" zone (rdi)
    did_swap = 1;                                                 // 0x1800098dc
    if ([rsp+0x38]/*swap_mode*/ == 0)                            // 0x1800098d7..0x1800098ea
        swap_dword(rbx /*lo*/, rdi);                              // 0x1800098ec..0x1800098f7
    else if (==1) for(k=w/4)  swap_dword(...);                   // 0x180009906..0x180009948
    else          for(k=w)    swap_byte (...);                   // 0x18000994a..0x18000998a
    rdi += w;  [rsp+0x40] = rdi;          // grow left-equal zone // 0x1800098f9 / 0x18000993b / 0x18000997d
  L_LO_ADVANCE: // 0x180009991
    base = [rsp+0x28];                                            // 0x180009991
    lo (rbx) += w;                                               // 0x180009996
    if (lo > hi) goto L_PART_DONE;        // (unsigned ja)        // 0x180009999 -> 0x180009a8d
    r10 = cmp;                                                    // 0x1800099a2
    goto L_SCAN_LO;                                              // 0x1800099aa -> 0x1800098c0

    // ---- scan hi downward while cmp(pivot, hi) <= 0 ----
  L_SCAN_HI_FROM_LO: // 0x1800099af   (reached when cmp(lo,piv)>0)
    if (lo > hi) goto L_PART_DONE2;                              // 0x1800099b2 -> 0x180009a88
  L_SCAN_HI: // 0x1800099c0
    c = cmp(base /*pivot*/, hi /*rsi*/);                         // 0x1800099c0..0x1800099c8
    if (c < 0) goto L_DO_SWAP_LOHI;                              // 0x1800099d1 -> 0x180009b10
    if (c != 0) { rax = w; goto L_HI_ADVANCE; }   // c>0 advance // 0x1800099d7 -> 0x180009a77
    // c == 0 : equal element at hi -> swap into right "equal" zone (rbp)
    did_swap = 1;                                                // 0x1800099e2
    if ([rsp+0x38]==0) swap_dword(hi, rbp);                      // 0x1800099f2..0x1800099fe
    else if(==1) for(k=w/4) swap_dword(...);                     // 0x180009a06..0x180009a43
    else         for(k=w)   swap_byte (...);                     // 0x180009a45..0x180009a75
    rbp -= w;                              // shrink right-equal  // 0x180009a01 / 0x180009a40 / 0x180009a72
  L_HI_ADVANCE: // 0x180009a7c
    hi (rsi) -= w;                                               // 0x180009a7c
    if (lo <= hi) goto L_SCAN_HI;          // (unsigned jbe)      // 0x180009a7f -> 0x1800099c0
    goto L_PART_DONE2;                                           // 0x180009a88

  L_DO_SWAP_LOHI: // 0x180009b10  (cmp(lo,piv)>0 AND cmp(piv,hi)<0): swap lo<->hi
    if (lo > hi) goto L_PART_DONE2;                              // 0x180009b13 -> 0x180009a88
    if ([rsp+0x38]==0) swap_dword(lo, hi);                       // 0x180009b19..0x180009b33
    else if(==1) for(k=w/4) swap_dword(...);                     // 0x180009b35..0x180009b6b
    else         for(k=w)   swap_byte (...);                     // 0x180009b6d..0x180009b9b
    base = [rsp+0x28]; r10 = cmp;                                // 0x180009ba2..0x180009bae
    lo  += w;                                                    // 0x180009baf
    did_swap = 1;                                                // 0x180009bb2
    hi  -= w;                                                    // 0x180009bbd
    goto L_OUTER;                                                // 0x180009bc0 -> 0x1800098b0

  // ================= post-partition: move equal runs to middle ===
  L_PART_DONE: // 0x180009a95
    base = [rsp+0x28]; w = [rsp+0x90];                          // 0x180009a88..0x180009a94 (fallthrough)
    if (did_swap == 0) goto L_NO_SWAP_PATH;  // never swapped → insertion sort // 0x180009a95..0x180009a9e -> 0x180009cd9

    // --- block-swap the left-equal run [base .. rdi) down to the pivot boundary ---
    rdi2 = base + did_swap?*?... ; (edi = [rsp+0x88]*w + base)   // 0x180009aa4..0x180009aba
    leftEqBytes = lo - leftStart ; m = min(leftEqBytes, lo-rdi)  // 0x180009aab..0x180009ac6 (cmovl)
    if (m > 0)                                                  // 0x180009aca -> else 0x180009bed
        block_swap_n_elems(base, lo - m, m);   // dword or byte  // 0x180009ad3..0x180009b0b
  L_AFTER_LEFT_EQ: // 0x180009bed
    // --- block-swap the right-equal run (rbp .. ] up similarly ---
    r9 = rdi - w ; rax = rbp - hi ; r9 -= rbp ; m2 = min(rax, r9)// 0x180009bed..0x180009c07 (cmovl)
    if (m2 > 0)                                                 // 0x180009c0b -> else 0x180009c6d
        block_swap_n_elems(rdi, rbx, m2);      // dword or byte  // 0x180009c10..0x180009c6b

    // --- recurse on LEFT sub-array, loop on RIGHT (smaller-first idiom) ---
  L_RECURSE_LEFT: // 0x180009c6d
    ebx = (lo - base);  w = [rsp+0x90];                         // 0x180009c6d..0x180009c77
    if (ebx > w) {                          // left part has >1 elem  // 0x180009c78 -> skip 0x180009ca3
        edx = (lo-base)/w;                  // count = bytes/width (unsigned div) // 0x180009c8a..0x180009c94
        // qsort(base, count, w, cmp)  -- RECURSIVE CALL          // 0x180009c96
        sub_1800095c0(base, count, w, cmp); // call 0x1800095c0
        w = [rsp+0x90];                                          // 0x180009c9b
    }
  L_TAILLOOP_RIGHT: // 0x180009ca3
    ebp = (hi_end - rsi_end);              // right part byte span // 0x180009ca3
    if (ebp <= w) goto L_DONE;             // <=1 elem: finished  // 0x180009ca5 -> 0x180009f43
    rcx = (int64)ebp; r9 = rdi_end - rcx;  // right sub-array base // 0x180009cb6..0x180009cc0
    n = ebp / w;                            // right count (unsigned div) // 0x180009cc3..0x180009cc6
    [rsp+0x88] = n;  [rsp+0x28] = r9 (right base);              // 0x180009cc8..0x180009ccf
    goto L_TOP;          // tail-call: re-sort right sub-array    // 0x180009cd4 -> 0x1800095e6

  // ================= insertion sort for small ranges ===========
  L_NO_SWAP_PATH: // 0x180009cd9   (n>=7 but partition made no swaps)
    // and L_INSERTION below share the same insertion-sort kernel.
    n = [rsp+0x88]; rsi = w; rbp = hi = base + w; [rsp+0x40]=hi;// 0x180009cd9..0x180009ce7
    end = base + n*w; [rsp+0x80] = end;                         // 0x180009cec..0x180009cf6
    if (hi >= end) goto L_DONE;                                 // 0x180009cfe -> 0x180009f43
    for (cur = hi; cur < end; cur += w) {                      // 0x180009d20 outer / 0x180009e00 incr
        for (j = cur; j > base && cmp(j-w, j) > 0; j -= w)     // 0x180009d40 cmp / 0x180009d4d
            swap(j-w, j);                  // dword/byte variant  // 0x180009d55..0x180009dcb
    }
    goto L_DONE;                                               // 0x180009df.. -> 0x180009f43

  L_INSERTION: // 0x180009e1c   (entry path when n < 7)
    n = [rsp+0x88]; rsi = w; rbp = base + w; end = base + n*w;  // 0x180009e1c..0x180009e36
    if (rbp >= end) goto L_DONE;                               // 0x180009e41 -> 0x180009f43
    for (cur = base+w; cur < end; cur += w) {                  // 0x180009e60 outer / 0x180009f30 incr
        for (j = cur; j > base && cmp(j-w, j) > 0; j -= w)     // 0x180009e77 cmp / 0x180009e82
            swap(j-w, j);                  // dword/byte variant  // 0x180009e88..0x180009eeb
    }
    // fallthrough
  L_DONE: // 0x180009f43 (and the alt epilogue at 0x180009e13)
    add rsp,0x58; pop rdi; pop rsi; pop rbp; pop rbx; ret;      // 0x180009f43..0x180009f4b
}
```

### swap idiom (appears ~9 times, all identical in shape)
Each inlined "swap two elements of width `w`" picks one of three loops based on
`swap_mode` / `[rsp+0x38]`:
- **mode 0** (`width==4`, aligned): single 32-bit exchange — `tmp=*p32; *p=*q; *q=tmp;`
- **mode 1** (`width%4==0`, `width!=4`, aligned): loop `width/4` times exchanging dwords.
- **mode 2** (unaligned or `width%4!=0`): loop `width` times exchanging bytes.

These are pure data moves; they carry no arithmetic meaning for transforms.

## Struct fields & constants

There are **no struct field reads** here — `base` is an opaque `void*` array; the only
dereferences are element loads/stores during swaps and comparator argument passing. All
"offsets" are stack home/spill slots, listed for gdb:

| Location        | Meaning |
|-----------------|---------|
| `[rsp+0x10]`    | spill of `num` (edx) — entry only |
| `[rsp+0x18]`    | spill of `width` (r8d) — entry only |
| `[rsp+0x20]`    | `swap_mode` (0/1/2) for current range |
| `[rsp+0x28]`    | `base` pointer of current (sub)range (updated for right-tail recursion) |
| `[rsp+0x30]`    | scratch = `width` (and other temporaries during block-swaps) |
| `[rsp+0x38]`    | sign-extended `swap_mode` (used as the 0/1/2 selector inside partition swaps) |
| `[rsp+0x40]`    | `rdi`/left-equal-zone finger spill |
| `[rsp+0x48]`    | `2*step` byte span (median-of-9 only) |
| `[rsp+0x80]`    | `did_swap` flag (0/1); reused as `end` pointer in insertion-sort blocks |
| `[rsp+0x88]`    | element count `n` of current range (recursion carries it here) |
| `[rsp+0x90]`    | `width` (canonical spill, reloaded constantly) |
| `[rsp+0x98]`    | `compar` function pointer (4th arg home slot) — **the comparator** |

Magic constants (all are quicksort tuning thresholds / shift math, none are fixed-point):

| Constant | Role |
|----------|------|
| `0x3` (`test r9b,0x3`) | 4-byte alignment / width-multiple-of-4 test |
| `0x4` (`cmp r11d,4`)   | special-cased element width == 4 |
| `0x7` (`cmp ebp,7`)    | cutoff: ranges with `< 7` (and `<= 7`) elements use insertion sort / skip ninther |
| `0x28` = 40            | cutoff: ranges `> 40` elements use median-of-9 (ninther) instead of median-of-3 |
| `>>1` (`shr ebx,1`)    | `n/2` → middle element index for pivot |
| `>>3` (`shr ecx,3`)    | `n/8` → 1/8 span step for the ninther samples |
| `>>2` (`shr ...,2`)    | `width/4` → dword count for mode-1 swaps |
| `div r11d`             | unsigned `byteSpan / width` → element count for the recursive/tail sub-call |

These thresholds (7 and 40, median-of-3 vs median-of-9) are the textbook signature of the
MSVC CRT `qsort`.

## GDB verification hooks

This routine has no transform math to cross-check numerically. To verify a Python
re-implementation (or just confirm it really is qsort and capture the comparator), set:

- **`break *0x1800095c0`** (entry). Dump the args:
  - `rcx` = `base` (array pointer)
  - `edx` = `num` (element count)
  - `r8d` = `width` (element size, bytes)
  - `r9`  = `compar` (**comparator function address** — symbolicate this; it is the real
    payload of interest for the pipeline). Cross-reference with the module base to map it
    to a `sub_180XXXXXX`.
  - Dump the first few elements: `x/<num*width>xb $rcx`.

- **`break *0x180009c96`** (recursive self-call). Dump `rcx`(left base), `edx`(left count),
  `r8d`(width), `r9`(comparator) to confirm the recurse-on-left / loop-on-right split sizes.

- **`break *0x180009cd4`** (tail-loop jmp to L_TOP). Dump `[rsp+0x28]`(right base) and
  `[rsp+0x88]`(right count) to confirm the right sub-array bounds.

- **`break *0x1800098c6`** and **`break *0x1800099c8`** (the two partition comparator calls).
  Dump `rcx`,`rdx` (the two element pointers being compared) and on return `eax` (sign).
  Use these to verify your Python comparator reproduces identical decisions — the *order of
  comparisons* is what makes the final permutation byte-exact.

- **`break *0x180009f43`** and **`break *0x180009e1b`** (the two `ret` sites). Dump the full
  array `x/<num*width>xb <base>` to compare the final sorted bytes against the Python port.

To validate end-to-end: capture `(base, num, width, comparator-addr)` at entry and the array
bytes at the matching `ret`; a correct port (using the same comparator semantics) must
produce byte-identical output. The intermediate comparator-call sequence at `0x1800098c6`/
`0x1800099c8` is the tie-breaker if outputs ever diverge (equal-key ordering).

## Confidence & open questions

**Solid (high confidence):**
- This is `qsort`: median-of-3 / median-of-9 pivot, Bentley-McIlroy 3-way partition with
  equal-element gathering, recurse-smaller / loop-larger, insertion-sort cutoff at 7,
  ninther cutoff at 40, and the 4-byte/aligned vs byte swap dispatcher. Matches MSVC CRT
  `qsort` instruction-for-instruction in structure.
- Argument mapping `(base, num, width, compar)` per the recursive call shape and the
  `byteSpan/width` divisions.
- **It is not transform/geometry/fixed-point math.** No matrix, no `<<16`/`>>16`, no trig,
  no rounding constant `0x8000`. Mark `is_transform_math = false`.

**Inferred / open:**
- The exact "left-equal / right-equal block-swap to middle" byte arithmetic around
  `0x180009aa4..0x180009c6b` is transcribed structurally; the precise `min()` operands
  (`cmovl`) follow the standard B-M scheme but were not exhaustively algebraically proven
  here — they don't affect the conclusion (it's still qsort).
- **The only pipeline-relevant unknown is the comparator's identity** (`[rsp+0x98]`), which
  is set by the caller and not visible in this function. That belongs in the calling
  function's analysis; capture it via the entry hook above.
