# sub_1800067a0 — TLV cursor "advance to next record" (span/iterator step)

Tiny wrapper. Given a TLV stream cursor `{begin, end, ...}` whose current
record header sits at `cursor.begin`, it reads the record's 16-bit length
field, adds it to the *base* pointer, and constructs a fresh
`{begin', end', size'}` span pointing at the **next** record. The new span is
returned by value into a caller-supplied output struct.

It is the "next section advancer" referenced by the recursive TLV tag-scanners
`sub_180006800` / `sub_180006320` / `sub_180005c60`. It is **not** transform
math — it is pure pointer/iterator bookkeeping over a serialized byte stream.

The actual span construction is delegated to `sub_180006680`, which builds a
`{ptr, ptr+4, 0}` triple (so the element header it points to is at least 4
bytes; a u16 tag + u16 len = 4 bytes).

## Signature

```c
// Returns the output span by value (Windows x64: large/by-value struct returned
// via hidden pointer == rcx == arg0; rax := arg0 on exit).
//
// struct Span {            // 0x18 bytes
//     void*    begin;      // +0x00  pointer to current record header
//     void*    end;        // +0x08  begin + 4 (one header's worth)
//     int32_t  size;       // +0x10  always 0 here (set by sub_180006680)
// };
//
// struct Cursor {          // arg1 layout (only the fields touched here)
//     Header*  cur;        // +0x00  -> current record; cur[0]=tag(u16), cur[1]=len(u16)
//     void*    base;       // +0x08  base/start pointer the lengths are added to
//     ...
// };

Span* sub_1800067a0(Span* out /*rcx, hidden return*/, Cursor* cur /*rdx*/);
```

- `out` (rcx) — caller-allocated 0x18-byte output span; filled and returned. (solid)
- `cur` (rdx) — cursor; `*(void**)cur` is the current record header,
  `*(void**)(cur+8)` is the base pointer that lengths are measured from. (solid)

Note: `cur+0x08` is treated as an **absolute base**, and the next pointer is
`base + len16`. So `len16` is an *offset-from-base of the next record*, i.e. the
cumulative end-offset of the current record (it is not added to `cur->cur`).
This matches a TLV layout where each header carries the absolute byte-offset of
its successor. (inferred — see open questions)

## Pseudocode

```c
Span* sub_1800067a0(Span* out, Cursor* cur)              // 0x1800067a0  sub rsp,0x48
{
    Header* rax = *(Header**)cur;            // rax = cur->cur            // 0x1800067a4  mov rax,[rdx]
    Cursor* r8  = cur;                       // save arg1                 // 0x1800067a7  mov r8,rdx
    Span*   r9  = out;                        // save arg0 (output)        // 0x1800067aa  mov r9,rcx

    uint64_t rdx = *(uint16_t*)((char*)rax + 0x2);  // len16 = cur->cur[1] (record length, zero-extended)
                                                                          // 0x1800067ad  movzx edx,WORD PTR [rax+0x2]
    Span* tmp = (Span*)(rsp + 0x20);          // local scratch span        // 0x1800067b1  lea rcx,[rsp+0x20]

    rdx += *(uint64_t*)((char*)r8 + 0x8);     // next = cur->base + len16  // 0x1800067b6  add rdx,[r8+0x8]

    Span* rax2 = sub_180006680(tmp, (void*)rdx);  // build {next, next+4, 0}// 0x1800067ba  call 0x180006680

    // ---- copy 0x18-byte span by value: tmp -> out --------------------
    *(uint64_t*)((char*)r9 + 0x00) = *(uint64_t*)((char*)rax2 + 0x00);     // 0x1800067bf  mov rdx,[rax]; 0x1800067c2 mov [r9],rdx
    *(uint64_t*)((char*)r9 + 0x08) = *(uint64_t*)((char*)rax2 + 0x08);     // 0x1800067c5/0x1800067cd
    *(uint64_t*)((char*)r9 + 0x10) = *(uint64_t*)((char*)rax2 + 0x10);     // 0x1800067c9/0x1800067d1 (covers size@+0x10)

    return r9;                                 // rax = out                 // 0x1800067d5  mov rax,r9
}                                                                          // 0x1800067d8 add rsp,0x48 ; 0x1800067dc ret
```

### Callee `sub_180006680(out=rcx, ptr=rdx)` — referenced, decoded inline

```c
Span* sub_180006680(Span* out, void* ptr)                 // 0x180006680
{
    out->begin = 0; out->end = 0; out->size = 0;          // 0x180006685..0x18000668c (zero 0x18 bytes)
    if (ptr != 0) {                                       // 0x180006682 test rdx,rdx / 0x18000668f je
        out->begin = ptr;                                 // 0x180006695  [rcx]   = rdx
        out->end   = (char*)ptr + 4;                      // 0x180006691/0x180006698  [rcx+8] = rdx+4
    }
    return out;                                            // 0x18000669c
}
```

So when `len16 == 0` AND `base == 0` the resulting span is all-zero
(begin==end==0 → empty/terminator). Otherwise `begin = base+len16`,
`end = base+len16+4`, `size = 0`.

## Struct fields & constants

| Access | Reg/offset | Meaning |
| --- | --- | --- |
| `*(void**)(cur+0x00)` | `[rdx]` → rax | current record header pointer (`cur->cur`) |
| `*(u16*)(rax+0x02)` | `[rax+2]` | record **length / next-offset** field (zero-extended to 64-bit) |
| `*(u64*)(cur+0x08)` | `[r8+8]` | base pointer that the length is added to |
| `out+0x00` | `[r9]` | result span `begin` |
| `out+0x08` | `[r9+8]` | result span `end` (= begin+4) |
| `out+0x10` | `[r9+0x10]` | result span `size` (always 0 here) |
| `[rax2+0/8/0x10]` | tmp span | source of the 0x18-byte by-value copy |

Constants:
- `0x48` — stack frame size (scratch + ABI shadow space; only `[rsp+0x20]` used).
- `0x2` — offset of the u16 length field inside a record header (tag is at +0,
  len at +2 ⇒ 4-byte header, consistent with the `+4` in the callee).
- `0x4` — element/header stride added by `sub_180006680` to form `end`.
- `0x10` — `size` field offset in the `Span` struct (written 0 by callee).

No fixed-point, trig, sqrt, matrix or coordinate arithmetic. The only "math" is
`next = base + len16` (unsigned pointer advance).

## Callees

- `0x180006680` — span/iterator constructor: builds `{ptr, ptr+4, 0}` (or all-zero
  if `ptr==0`). Decoded inline above. Same helper used as iterator-init by
  `sub_180006470`, `sub_180006320`, `sub_180005c60`, `sub_180002240`
  (a.k.a. `make_cursor`). See those `.md` files.

## GDB verification hooks

Set breakpoints under Wine on the loaded module base + RVA (RVA = addr − 0x180000000).

- `break *0x1800067ad` — entry length read.
  - `x/2hx $rax` → the current record header: `[tag_u16][len_u16]`.
  - Record `len16 = *(unsigned short*)($rax+2)`.
- `break *0x1800067ba` — just before the constructor call (next-pointer computed).
  - `p/x $rdx` → **next pointer = base + len16** (the key computed value).
  - `p/x *(unsigned long long*)($r8+8)` → `base`; verify `next == base + len16`.
  - `p/x $rcx` → scratch span address `rsp+0x20`.
- `break *0x1800067d5` — after the by-value copy, result fully written.
  - `p/x *(unsigned long long*)$r9` → `out.begin` (should equal the `next` above).
  - `p/x *(unsigned long long*)($r9+8)` → `out.end` (should be `begin+4`).
  - `p/x *(unsigned int*)($r9+0x10)` → `out.size` (should be 0).
  - `p/x $rax` → returned pointer (== `$r9` == `out`).

For a Python port, the only invariant to match is:
`out = Span(begin = base + len16, end = begin + 4, size = 0)` when
`base + len16 != 0`, else `Span(0,0,0)`.

## Confidence & open questions

- **Solid:** instruction-level decode; the 0x18-byte by-value span copy; the
  delegation to `sub_180006680` and that callee's exact behavior; that this is a
  TLV iterator "advance" step (corroborated by existing repo docs which already
  call `sub_1800067a0` the "next section advancer").
- **Solid:** no transform/fixed-point/coordinate math here.
- **Inferred:** the semantic that `[cur+8]` is an *absolute base* and `len16` is an
  *offset-from-base* (cumulative next-offset) rather than `next = cur->cur + len16`.
  The disasm unambiguously computes `base + len16` (the current header pointer
  `rax` is *not* used in the address arithmetic — it is only read for the length).
  Whether the serializer stores per-record incremental lengths or absolute next
  offsets in that u16 should be confirmed at `0x1800067ba` with a live capture.
- **Open:** field names ("base", "len16") are my naming; the producer side
  (serializer) determines exact semantics. Cross-check against
  `func_180005c60.md` / `func_180006320.md` callers which feed `cur`.
