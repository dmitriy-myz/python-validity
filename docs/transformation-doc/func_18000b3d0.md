# sub_18000b3d0 — byte-range validity predicate (two-bound bool check)

A tiny 18-byte leaf function (8 instructions, no callees). It tests two
unsigned byte arguments against fixed bounds and returns a boolean (1/0).
It is **not** geometry / transform math — it is a pure range-acceptance test,
almost certainly a "is this (a,b) pair in the allowed window?" guard used by
the callers `sub_180007b30` and `sub_1800082a0` (both of which are part of the
sec0_pre / template-build path, but this specific helper only gates them).

## Signature

```c
// Returns 1 iff  (uint8)a > 0x1E (30)  AND  (uint8)b <= 0x31 (49).
// Both compares are UNSIGNED (jbe / ja), so a and b are treated as bytes.
// Only the low byte of each arg is inspected (cl / dl).
BOOL sub_18000b3d0(uint8_t a /*cl*/, uint8_t b /*dl*/);
```

Arg meaning (inferred — exact semantics live in the callers):
- `a` (rcx, low byte `cl`): some count / index / class id that must be **strictly greater than 30**.
- `b` (rdx, low byte `dl`): a second count / index / class id that must be **<= 49**.
- The pair is "valid" (return 1) only when **both** conditions hold; any failure returns 0.

Given the surrounding context (per-frame / per-section counts that we know land
near values like 29,27,17,33,36,33,30,26,19 in the cull stage), a plausible
reading is a bounds check on a (row,col) or (count_lo, count_hi) pair — but that
is a guess; the function itself only encodes the two numeric bounds.

## GDB verification hooks

This function has no intermediate math, so verification is just input/output capture.

- `break *0x18000b3d0` (entry) — dump:
  - `$rcx & 0xff` → `a` (the byte compared against 30)
  - `$rdx & 0xff` → `b` (the byte compared against 49)
  Example gdb: `p/x $rcx & 0xff` and `p/x $rdx & 0xff`.

- `break *0x18000b3da` — reached **only** when both checks pass; if execution
  hits here you expect `a > 30 && b <= 49`. Good place to confirm the
  "accept" branch fires for exactly the inputs your Python port accepts.

- `break *0x18000b3e0` — the "reject" branch (`return 0`). Hitting this means at
  least one bound failed.

- `break *0x18000b3df` and `break *0x18000b3e2` (the two `ret`s) — dump
  `p/x $eax` to read the final boolean (1 = valid, 0 = invalid). This is the
  authoritative output to match in a re-implementation.

A complete oracle test: at entry log `(a,b)`; at the `ret`s log `eax`. The Python
port `f(a,b) = 1 if (a & 0xff) > 0x1E and (b & 0xff) <= 0x31 else 0` must match
byte-for-byte across all captured calls.

## Confidence & open questions

**Solid (high confidence):**
- The exact logic: `return ((uint8)a > 30) && ((uint8)b <= 49);`. The disassembly
  is complete (all 8 instructions present), unambiguous, and has no hidden paths.
- Unsigned byte comparisons (jbe/ja), no fixed-point, no transform/matrix math.
- Leaf function, no side effects, no memory access.

**Inferred / open:**
- The *meaning* of `a` and `b`. The function only encodes "a in (30, ∞) as a byte"
  and "b in [0, 49]". Whether these are counts, indices, dimensions, or class ids
  must be read from the callers (`sub_180007b30`, `sub_1800082a0`, thunk `sub_18000b3f0`).
- Whether callers pass full ints whose high bytes matter — irrelevant here since
  only `cl`/`dl` are inspected, but the caller may have its own wider checks.
- This helper is on the template-build path but does **not** itself compute any
  rigid-transform / Q16 quantities relevant to `sec0_pre` frame registration.
