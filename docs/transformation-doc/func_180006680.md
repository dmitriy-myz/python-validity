# sub_180006680 — 24-byte handle/range struct initializer (+ wrapper that tags it)

This 99-byte span actually contains **two** routines that the disassembler grouped together:

- **`0x180006680`** — the real `sub_180006680`: initializes a 24-byte (0x18) "result" struct in place from a pointer argument. Returns the struct pointer.
- **`0x1800066a0`** — a separate wrapper (call it `sub_1800066a0`) that calls `sub_180006680` on a stack temporary, copies the 24-byte result into the caller's output buffer, then writes a 16-bit tag and zeroes two fields.

**This is NOT transform / geometry math.** There is no fixed-point arithmetic, no matrix/affine ops, no trig, no coordinate loops. It is a plain struct constructor pair — the kind of small "make a {ptr,end,flags}" descriptor / iterator-range / tagged-handle helper that container or serialization code emits. It is relevant to the broader pipeline only as a building block (e.g. constructing an iterator range or a tagged record header), not as part of the rigid-transform computation.

## Signature

```c
// 0x180006680
// Initializes an in-place 24-byte struct describing a range/handle built from `src`.
//   out[0x00] = begin pointer  (= src,        or NULL if src==NULL)
//   out[0x08] = end pointer    (= src + 4,    or NULL if src==NULL)
//   out[0x10] = u32 flags/len  (= 0)
// Returns `out`.
struct range24 { void *begin; void *end; uint32_t f10; };   // 0x18 bytes (f10 occupies 4 of the trailing 8)

struct range24 *sub_180006680(struct range24 *out /*rcx*/, void *src /*rdx*/);
//                                            ^ r8, r9 are ignored by this routine

// 0x1800066a0  (wrapper — distinct entry point)
// dst   = rcx : caller's 24-byte output struct
// src   = rdx : pointer passed through to sub_180006680  (GUESS: same `src` semantics)
// tag   = r8  : only the low 16 bits (r8w) are used — written into *(u16*)dst.begin
// Returns `dst`.
struct range24 *sub_1800066a0(struct range24 *dst /*rcx*/, void *src /*rdx*/, uint16_t tag /*r8w*/);
```

Arg meanings are best-effort. `src` is treated only as an address: the routine stores `src` and `src+4` but never dereferences it, so the `+4` strongly implies the element it points at is 4 bytes wide (a `u32`/`float`), making `{begin,end}` a one-element iterator range. **GUESS.**

## Pseudocode

### sub_180006680 — `0x180006680` .. `0x1800669f`

```c
struct range24 *sub_180006680(struct range24 *out /*rcx*/, void *src /*rdx*/)
{
    // --- entry / zero-init -------------------------------------------------
    eax = 0;                                  // 0x180006680  xor eax,eax
    bool src_null = (src == NULL);            // 0x180006682  test rdx,rdx (sets ZF for the je below)
    out->begin = (void*)0;                    // 0x180006685  mov [rcx+0x00], rax   (rax==0)
    out->end   = (void*)0;                    // 0x180006688  mov [rcx+0x08], rax
    out->f10   = 0;                           // 0x18000668c  mov dword [rcx+0x10], eax

    if (src_null) goto L_ret;                 // 0x18000668f  je 0x18000669c

    // --- non-null path: build a {src, src+4} range -------------------------
    void *end = (char*)src + 4;               // 0x180006691  lea rax,[rdx+0x4]
    out->begin = src;                         // 0x180006695  mov [rcx+0x00], rdx
    out->end   = end;                         // 0x180006698  mov [rcx+0x08], rax
                                              //   (out->f10 stays 0 from the zero-init above)

L_ret:                                        // 0x18000669c
    return out;                               // 0x18000669c  mov rax,rcx
                                              // 0x18000669f  ret
}
```

### sub_1800066a0 — `0x1800066a0` .. `0x1800066e3`  (separate entry)

```c
struct range24 *sub_1800066a0(struct range24 *dst /*rcx*/, void *src /*rdx*/, uint16_t tag /*r8w*/)
{
    sub rsp,0x48;                             // 0x1800066a0  reserve 0x48 stack (home space + temp)
    void *saved_dst = dst;                    // 0x1800066a4  mov r9, rcx        (preserve caller dst in r9)

    struct range24 tmp;  // at [rsp+0x20]
    // Build the range struct into the stack temp.
    //   rcx = &tmp (=[rsp+0x20]); rdx (src) passed through unchanged; r9 holds dst.
    sub_180006680(&tmp /*rcx=rsp+0x20*/, src /*rdx*/);   // 0x1800066a7 lea rcx,[rsp+0x20]
                                                         // 0x1800066ac call 0x180006680
    // rax now points at tmp.

    // --- copy the 24-byte tmp struct into the caller's dst -----------------
    dst->begin = tmp.begin;                   // 0x1800066b1  mov rdx,[rax+0x00]; 0x1800066b4 mov [r9+0x00],rdx
    rdx        = tmp.end;                      // 0x1800066b7  mov rdx,[rax+0x08]
    rax        = *(u64*)((char*)&tmp + 0x10);  // 0x1800066bb  mov rax,[rax+0x10]  (8 bytes: f10 + 4 pad)
    dst->end   = (void*)rdx;                  // 0x1800066bf  mov [r9+0x08],rdx
    *(u64*)((char*)dst + 0x10) = rax;         // 0x1800066c3  mov [r9+0x10],rax   (copies f10 + trailing 4)

    // --- overwrite the *pointed-to* data and re-clear f10 ------------------
    void *p = dst->begin;                     // 0x1800066c7  mov rax,[r9+0x00]   (== src, or NULL)
    *(u16*)p       = tag;                      // 0x1800066ca  mov [rax+0x00], r8w   <-- writes through the stored pointer
    *(u16*)(p + 2) = 0;                       // 0x1800066ce  mov word [rax+0x02], 0x0

    rax = saved_dst;                          // 0x1800066d4  mov rax, r9         (return value = dst)
    dst->f10 = 0;                             // 0x1800066d7  mov dword [r9+0x10], 0x0

    add rsp,0x48;                             // 0x1800066df
    return rax /*== dst*/;                    // 0x1800066e3  ret
}
```

Notes on `sub_1800066a0`:
- It assumes `src != NULL`. The `mov [rax],r8w` / `mov [rax+2],0` at `0x1800066ca`/`0x1800066ce` write **through** `dst->begin`, which is `src`. If `src` were NULL this is a null deref, so callers always pass a valid `src` (a 4-byte slot). It writes a `u16 tag` then a `u16 0` — i.e. it stores `tag` into the low half and clears the high half of the pointed-to 32-bit slot, effectively `*(u32*)src = (u32)tag`.
- The 8-byte copy at `0x1800066bb`/`0x1800066c3` reads/writes `[+0x10]` as a qword, then `f10` is explicitly re-zeroed as a dword at `0x1800066d7` — consistent with the struct being 24 bytes where only the low 4 of the last 8 are meaningful.

## GDB verification hooks

To verify a Python re-implementation produces identical state, set breakpoints and dump these (Wine PID; `break *0xADDR`):

**sub_180006680 (initializer):**
- `break *0x180006680` — at entry dump `rcx` (out struct ptr) and `rdx` (`src`). `rdx==0` selects the NULL path.
- `break *0x18000669f` (the `ret`) — dump the resulting struct:
  - `x/3gx $rcx` → expect `[begin, end, (f10|pad)]`. For non-null `src`: `begin==rdx_in`, `end==rdx_in+4`. For null: all zero.
  - `rax` should equal `rcx` (returns `out`).

**sub_1800066a0 (wrapper):**
- `break *0x1800066a0` — entry: dump `rcx` (dst), `rdx` (src), `r8` (only `r8 & 0xffff` matters as the tag).
- `break *0x1800066b1` — right after the inner call: `x/3gx $rax` is the freshly built temp `{src, src+4, 0}`. Confirms the initializer ran.
- `break *0x1800066ca` — **key write**: `rax` = `dst->begin` (should equal the input `src`); `r8w` = tag about to be stored. After stepping, `x/1wx $rax` should read `tag` (low half set, high half 0).
- `break *0x1800066e3` (ret) — dump `x/3gx $r9` for the final `dst` struct (`{src, src+4, 0}`) and `x/1wx <src>` to confirm `*src == (u32)tag`. `rax` should equal `r9` (returns `dst`).

These cover every memory write the function performs, so byte-for-byte parity can be checked at the `ret` of each routine plus the tag-write at `0x1800066ca`.

## Confidence & open questions

**Solid (high confidence):**
- Control flow, the exact memory writes, the NULL-check branch, and the `{src, src+4, 0}` layout are unambiguous from the disasm.
- This is a struct constructor / range-builder, **not** transform/geometry/fixed-point math. No `>>16`, `*65536`, `0x8000` rounding, matrix, sqrt, atan2, sort, or correspondence loops are present.
- `sub_1800066a0` copies the 24-byte struct, writes a u16 tag through the stored pointer, and returns `dst`.

**Inferred / open (medium-low):**
- The exact *purpose* of the struct (iterator range vs. tagged record header vs. small-vector descriptor) is a GUESS based on the `{ptr, ptr+4, count}` shape. The `+4` strongly suggests a single 4-byte element.
- `tag` (`r8w`) semantics: it is written as a `u16` into `*src` with the upper half zeroed, i.e. an enum/type tag for a 4-byte record. Meaning of the value is unknown without a caller.
- The two routines are almost certainly distinct functions (separate prologue/epilogue, the second establishes a `0x48` frame); the disassembler merged them under one label. `sub_1800066a0` may have its own symbol elsewhere.
- `r8`/`r9` are ignored by `sub_180006680` itself; only the wrapper uses `r8` (as tag) and `r9` (as a scratch copy of `dst`).
