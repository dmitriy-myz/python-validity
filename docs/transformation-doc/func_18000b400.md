# sub_18000b400 — two-byte range/bounds predicate (`a > 30 && b <= 55`)

A tiny leaf predicate (18 bytes, 8 instructions, no callees). It takes two
byte-sized values in the low bytes of `rcx` and `rdx`, performs two **unsigned**
byte comparisons, and returns `1` iff both pass, else `0`. No fixed-point, no
transform math — it is a guard/validation helper called by the transform code
in `sub_1800082a0`, almost certainly a coordinate/index in-bounds test.

//   returns 1  iff  (a > 0x1e /*30*/)  &&  (b <= 0x37 /*55*/)

Notes / guesses:
- The function only reads `cl` (low byte of arg0) and `dl` (low byte of arg1);
  the upper bits of `rcx`/`rdx` are ignored. Callers may pass full ints.
- Comparisons use `jbe`/`ja` ⇒ **unsigned** byte comparisons. So negative
  signed inputs (high bit set) compare as large unsigned values.
- Plausible semantic (inferred, not provable from this function alone):
  `a` and `b` are a grid/cell coordinate pair or counts, and this asserts
  `a` is strictly above a lower bound (30) while `b` is at or below an upper
  bound (55). The `>30` / `<=55` band hints at a region-of-interest / tile
  index check rather than transform arithmetic.
