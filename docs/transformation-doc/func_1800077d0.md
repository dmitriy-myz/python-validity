# sub_1800077d0 — per-frame candidate-correspondence builder: ROI-gate keypoints, compose their pose with a frame transform, and emit (j, idxB) pairs + composed Xforms

This function walks one source keypoint set (the "B" frame, pointer `rsi`) against an
**index list** of reference keypoints (`r13[rbp]`), and for each (reference, source)
candidate that survives a **region-of-interest byte gate** (`sub_18000b3f0` on the
keypoint's first two bytes x,y) it:

1. **composes** the reference keypoint's per-frame transform
   (`transformTable[idxB]`, a 4×int32 Q16 `Xform`) with the **pose embedded in the
   source keypoint record** (the 16 bytes at record offset +4) via the rigid
   similarity-transform composer `sub_180006cc0`, writing the result to an output
   `Xform` array, and
2. records the integer **correspondence pair** `(j, idxB)` into a parallel int32
   output buffer, marking the source slot "used" in a visited-flag buffer so each
   source keypoint is consumed at most once.

It returns the **count of emitted correspondences**. The composed `Xform`s it produces
are exactly the pairwise rigid transforms that later feed `sec0_pre`; this routine is
the *candidate-generation / matching front-end* that decides **which** keypoint pairs
get a composed transform, and the byte gate `[x>30 && y<=49]` is the spatial admissibility
test for those candidates.

> Naming below: outer loop index `rbp = b` iterates the reference index list
> (`r13[b]` → `idxB`); inner loop index `ebx = j` / pointer `rdi` iterates the source
> keypoint set `rsi`. "nA"/"nB" are the two loop bounds (see Signature).

### Notes on the loop / pointer arithmetic

- **`pairOut` write pattern (the load-bearing part):** the source index `j` is written
  via `[r12 + r14]` where `r12 = bufHi - bufLo` (a *difference* of two buffer pointers,
  computed once per outer iteration at 0x180007899) and `r14` is advanced by 4 per emit.
  Then the reference index `idxB` is written via `[r14-4]` *after* `r14 += 4`. Net: each
  kept pair appends **two int32s** — first `j` (into `bufLo + (r14_into_bufHi)` … i.e. a
  parallel "low" buffer), then `idxB` into the running `r14` ("high") buffer. The two
  parallel arrays are `bufLo[]` (source indices) and the `pairOut/bufHi[]` region
  (reference indices), kept index-aligned by the shared advance. **For a Python port the
  simplest faithful model is: `srcIdx.append(j); refIdx.append(idxB)` per kept pair**,
  and the composed `outXf` for that pair is at `[rsp+0x30]` (caller may copy it out — see
  open questions; this fn writes it to its own stack scratch, the caller's frame holds
  the persistent Xform array via `xformTable`/the surrounding `sub_1800082a0` flow).
- **`r14` re-base:** at outer-loop entry `r14 += r15*4` (skip past rows already emitted),
  and at outer-loop bottom `r14 = bufLo` is reloaded — i.e. `r14` walks the "high"
  output region while `r15` counts total emitted rows.
- **`rdi` vs `j`:** both increment together in the inner loop (`rdi` starts 0, `+1` each
  step), so `rdi == j`. `rdi` indexes the **visited-flag buffer** and the **source list
  pointer** `lists[rdi]`; `j` (=ebx) indexes the **reference keypoint** within `listB`
  for the ROI gate and is the value stored into `pairOut`. They are the same number but
  used as two different array indices.

## Callees

- `0x180003320` — **StreamView clone + sub-range carve** (see `func_180003320.md`). Used
  here once at entry to allocate/anchor the **`nA`-rounded-up-to-4 byte visited-flag
  buffer** whose base is left in `[rsp+0x20]`. Not transform math.
- `0x18000b3f0` → tail-jmps `0x18000b3d0` — **ROI byte gate**. `sub_18000b3f0(p)` loads
  `cl=p[0]` (x), `dl=p[1]` (y) and returns `1` iff `x > 0x1e (30)` **and** `y <= 0x31
  (49)`, else `0`. (3-instr thunk + 8-instr comparator.) Spatial admissibility test on
  each reference keypoint.
- `0x180006cc0` — **rigid 2D similarity-transform composition `out = B∘A` in Q16, with
  rotation renormalisation** (see `func_180006cc0.md`). Called as
  `sub_180006cc0(out=&[rsp+0x30], A=&xformTable[idxB], B=&keypoint.pose)`. This is the
  kernel that produces the per-correspondence Q16 transform.

## GDB verification hooks

Windows x64 entry: `rcx`=ctx(unused), `rdx`=pairOut, `r8`=src(KpSet), `r9d`=nB;
`[rsp+0x108]`=nA, `[rsp+0x110]`=scratch. To verify a Python re-implementation produces
identical intermediate values:

1. **Entry** `break *0x1800077d0`
   - `p/d *(int*)($rsp+0x108)` → `nA`; `p/d $r9d` → `nB`.
   - `x/gx $r8+0x18` → `src->lists` base; `x/bu $r8+0x10` → `src->count`.
   - `x/gx $rsp+0x110` → scratch StreamView ptr. Save `$rdx` (pairOut base).

2. **After flag buffer is carved** `break *0x180007823`
   - `x/gx $rsp+0x20` → base of the visited-flag buffer; its length is `(nA+3)&~3`.
     Dump `x/<nA>bu <that ptr>` after PASS 1 to capture the seeded flags
     (`flag[k] = statusBuf[k]!=0`).

3. **PASS-1 flag write** `break *0x180007853`
   - `p/d $r11`(=k+1 at write), `p $cl`(=flag value), `p/x $rax`(=flagBuf). Confirms the
     seeding rule. (`statusBuf` = `$rdx` here, = caller `[rsp+0x28]`.)

4. **ROI gate call** `break *0x1800078c4`
   - `p/x $rcx` → `&kpRef` (the reference keypoint record). `x/2bu $rcx` → `(x,y)`.
     Predict `ok = (x>30 && y<=49)`. Then `break *0x1800078c9` and `p/d $eax` → actual
     gate result. Capture `b`(=`$rbp`), `j`(=`$rbx`), `idxB`(=`$r8` from 0x1800078ac).

5. **COMPOSE call — the transform inputs** `break *0x1800078f4`  ← **primary hook**
   - `x/4wd $rdx` → operand **A** = `xformTable[idxB]` = `{a,b,tx,ty}` (Q16).
   - `x/4wd $r8`  → operand **B** = keypoint pose `{a,b,tx,ty}` (at record +4).
   - `p/x $rcx`   → `&out` (=`$rsp+0x30`). Step over, then `x/4wd $rcx` to read the
     composed `{a,b,tx,ty}` — match against a Python `compose(A,B)` (see
     func_180006cc0.md hooks). `a²+b²` should snap to `0x10000²` after the callee's
     renorm.

6. **Pair emit** `break *0x180007901` (store `j`) and `break *0x180007912` (store `idxB`)
   - At 0x180007901: `p/d $ebx` (=`j`, source index) and `p/x $r12+$r14` (target addr in
     `bufLo` region). At 0x180007912: `p/d $eax` (=`idxB`, reference index) and `p/x
     $r14-4` (target addr in `bufHi`/`pairOut`). Together they reconstruct the
     `(srcIdx[], refIdx[])` correspondence arrays. Also `p/d *(int*)($rsp+0xc8)` for the
     running count.

7. **Visited mark** `break *0x18000791b`
   - `p/d $rdi` (source slot index just consumed) — confirms each source keypoint is used
     at most once.

8. **Exit** `break *0x18000794c` → `p/d $eax` = total emitted correspondences (return).

Priority for the transform port: **#5** (compose inputs/outputs per pair) and **#6**
(the `(j, idxB)` correspondence list) — together they fully determine which composed
Q16 transforms are produced and in what order.

## Confidence & open questions

**Solid (read directly from disasm):**
- Control flow: entry flag-buffer carve, PASS-1 seeding loop, then the nested
  `b`(outer, bound `nB`) × `j`(inner, bound `src->count`) loops, with the visited-flag
  skip, the ROI gate, the compose call, the two-int32 pair emit, and the used-mark. All
  addresses and all loads/stores transcribed.
- Keypoint record stride = **20 bytes**, embedded `Xform` at **+4**, ROI gate bytes are
  record `[0]`(x) / `[1]`(y) with thresholds **>30** / **<=49** (from `sub_18000b3d0`).
- `xformTable` element size **16 bytes**, `lists[]` is a pointer array (×8).
- The compose call delegates the actual Q16 rigid-transform math to `sub_180006cc0`
  (`out = compose(xformTable[idxB], keypoint.pose)`).
- Signedness: `nA`, `nB`, `idxB`, `j` are all sign-extended (`movsxd`); `src->count` is
  unsigned (`movzx` + `jbe`).
- Return value = `[rsp+0xc8]` = count of emitted pairs (0 on either-bound-empty path).

**Inferred / GUESS:**
- `arg1 (rcx)` is saved to `[rsp+0x8]` in the prologue but never re-read in the body —
  marked spare/unused; could be a caller-shared scratch the *compiler* spilled but this
  function ignores it.
- The **`bufLo`/`bufHi` parallel-buffer** interpretation (source indices in one region,
  reference indices in the running `r14` region). The arithmetic `r12 = bufHi - bufLo`
  then `[r12 + r14] = j` is unusual; it stores `j` at the same *offset* into the low
  buffer that `r14` currently is into the high buffer, keeping them index-aligned. A
  Python port can model this simply as two parallel append-lists `srcIdx`/`refIdx`.
- Field names on `KpSet` (`count`/`lists`) and the `statusBuf` seeding source.
- Whether the composed `outXf` at `[rsp+0x30]` is consumed by this function's caller
  (`sub_1800082a0`) after return, or only its side effect (the pair lists + count) is
  used. The caller passes `xformTable`/buffers in and reads the returned count
  (`r11d=eax` at 0x1800087f3) — so the **count and the pair buffers are the persistent
  outputs**; the single `[rsp+0x30]` scratch is overwritten each iteration (so the
  *transform itself* must be consumed by `sub_180006cc0`'s side effects or it is
  recomputed elsewhere — verify with hook #5 whether `[rsp+0x30]` is later copied; in
  this function it is **not**, which suggests the composed transform here is used only
  transiently, e.g. as a validity/admissibility computation, OR the real persistent copy
  happens in the sibling `sub_180007b30` that the caller invokes right after with the
  same buffers).

**Open questions:**
- Exact semantics of `nA` vs `nB`: `nA` sizes the flag buffer (rounded to 4) and `nB`
  bounds the outer reference loop. In the caller both relate to `r15d` (a section index)
  — at the observed call site `nB` came from `[rsp+0xb0]` which was set to `0` just
  before (0x180008884), so this particular call may early-return `0` (RET_EMPTY); confirm
  with hook #8 across real captures which call instances do work.
- The role of `[rsp+0x30]` composed transform (transient vs persisted) — resolve by
  stepping hook #5 and watching whether the bytes at `$rsp+0x30` are read after the
  `sub_180006cc0` return within this frame (they are not, in the disasm) vs by the caller.
