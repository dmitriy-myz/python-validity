# sub_180005c60 — append two 4-byte words into the tag-0x69 TLV field of a section

This is a thin **serializer / field-writer**, not transform arithmetic. Given a container
(a TLV-stream section descriptor), it looks up the entry whose 16-bit tag == `0x69` (='i', 105).
If that field exists (and the section is non-empty), it appends two 4-byte little-endian words —
`*(uint32*)ptrA` then `*(uint32*)ptrB` — into the field's write cursor. If the lookup misses
(empty section), it writes nothing and returns.

In the sec0_pre TLV context this is the kind of helper that emits a pair of 32-bit values
(e.g. a `tx`/`ty` translation pair, or two Q16 transform components, or a `(count,id)` pair)
into the field tagged `0x69`. **It does no fixed-point math, no trig, no matrix ops itself** —
it just moves 4+4 bytes. The *meaning* of the two words is decided by the caller (which supplies
`ptrA`/`ptrB`).

## Signature

```c
// rcx = section       : pointer to a section/container handle.
//                       *section -> header; header[+4] is a u32 element-count (the "is this
//                       section populated?" guard); header[+8] is the TLV byte-stream base.
// rdx = ptrA          : pointer to first  4-byte source word to append   (caller-defined meaning)
// r8  = ptrB          : pointer to second 4-byte source word to append   (caller-defined meaning)
// returns: void (eax holds sub_180006890's hit/miss flag at the je, but the function returns no
//          meaningful value to its caller — the two ret paths just restore rbx/rdi/rsp).
void sub_180005c60(void *section /*rcx*/, const uint32_t *ptrA /*rdx*/, const uint32_t *ptrB /*r8*/);
```

Argument meanings (best effort — `ptrA`/`ptrB` semantics are caller-defined, marked GUESS):

| reg | name      | meaning                                                                 |
|-----|-----------|-------------------------------------------------------------------------|
| rcx | `section` | TLV section/container handle; passed straight to the tag-0x69 lookup.   |
| rdx | `ptrA`    | src of the **first** 4-byte word appended (GUESS: e.g. tx / comp0).     |
| r8  | `ptrB`    | src of the **second** 4-byte word appended (GUESS: e.g. ty / comp1).    |

The literal `edx = 0x69` is the **TLV tag** selected for the lookup (constant, baked in).

## Pseudocode

```c
void sub_180005c60(void *section /*rcx*/, const uint32_t *ptrA /*rdx*/, const uint32_t *ptrB /*r8*/)
{
    // --- prologue ----------------------------------------------------------------- 0x180005c60
    // mov [rsp+8], rbx ; push rdi ; sub rsp,0x40    (frame; 0x40 locals; saves rbx,rdi)
    void   *rbx = ptrB;            // mov rbx, r8                                       // 0x180005c6a  (save ptrB)
    void   *rdi = ptrA;           // mov rdi, rdx                                       // 0x180005c6d  (save ptrA)

    // Local writer/cursor struct lives at [rsp+0x20] (24 bytes: {tag/data, base, offset}).
    // Find the TLV entry with tag 0x69 inside `section`; on hit, populate writer @ [rsp+0x20].
    //   sub_180006890(rcx=section, edx=0x69 (tag), r8=&writer)
    //   r8 = &[rsp+0x20]                            // lea r8,[rsp+0x20]               // 0x180005c70
    //   edx = 0x69                                  // mov edx,0x69                    // 0x180005c75
    int found = sub_180006890(section, /*tag=*/0x69, /*out_writer=*/&local_writer);    // 0x180005c7a  (call 0x180006890)

    if (found == 0)                // test eax,eax ; je 0x180005c9d                     // 0x180005c7f / 0x180005c81
        goto L_done;               //   -> section empty / tag-0x69 not present: write nothing

    // --- HIT: append two 4-byte words into the tag-0x69 field's cursor -------------
    // sub_1800065b0(rcx=&writer, rdx=src) appends 4 bytes at *(writer+8)+*(writer+0x10), cursor += 4.
    sub_1800065b0(&local_writer, ptrA /*rdi*/);     // 1st 4-byte word                 // 0x180005c83..0x180005c8b (call 0x1800065b0)
    sub_1800065b0(&local_writer, ptrB /*rbx*/);     // 2nd 4-byte word                 // 0x180005c90..0x180005c98 (call 0x1800065b0)

L_done:                                              //                                 // 0x180005c9d
    // --- epilogue ----------------------------------------------------------------- 0x180005c9d
    // mov rbx,[rsp+0x50] (restore rbx) ; add rsp,0x40 ; pop rdi ; ret
    return;                                          //                                 // 0x180005ca7
}
```

### What the callees do (so the reader doesn't have to chase them)

`sub_180006890(rcx=section, edx=tag, r8=&out)` — **TLV find-by-tag**:
```c
hdr = *section;                                   // mov rax,[rcx]                      // 0x180006894
if (hdr[+4] /*u32 count*/ == 0) return 0;         // cmp [rax+4],0 ; ja                 // 0x18000689a/0x18000689e
cursor = make_cursor(section[+8]);                // sub_180006680 -> {ptr, ptr+4, 0}   // 0x1800068b0
out{+0,+8,+0x10} = cursor{+0,+8,+0x10};           // 24-byte copy to [rsp+0x20]         // 0x1800068ba..0x1800068cc
return sub_180006800(&copy, edx=tag, r8=&out);    // recursive tag scan, fills out      // 0x1800068d8
```
`sub_180006800` walks TLV entries: reads `movzx WORD PTR [entry]` (the 16-bit tag), compares to
`tag`; on match writes the entry into `out` and returns 1; if the entry tag == 1 (terminator)
returns 0; else advances via `sub_1800067a0` and tail-recurses.

`sub_1800065b0(rcx=writer, rdx=src)` — **append 4 bytes & bump cursor**:
```c
dst = writer[+8] + writer[+0x10];                 // base + current offset              // 0x1800065b9/0x1800065bf
sub_1800031e0(dst, src, 4);                       // memcpy 4 bytes                      // 0x1800065cc
writer[+0x10] += 4;                               // advance cursor by 4                // 0x1800065d1
```

## Struct fields & constants

`section` (rcx) — TLV section handle, dereferenced by the callee `sub_180006890`:

| access            | where        | inferred meaning                                              |
|-------------------|--------------|---------------------------------------------------------------|
| `*(void**)section`        | 6890 @0x6894 | pointer to section header                                     |
| `*(u32*)(hdr + 0x4)`      | 6890 @0x689a | element/entry count; `== 0` ⇒ section empty ⇒ no-op + ret 0   |
| `*(void**)(hdr + 0x8)`    | 6890 @0x68a7 | base pointer of the TLV byte-stream to scan                   |

`local_writer` @ `[rsp+0x20]` — 24-byte write cursor produced by the lookup, consumed by 65b0:

| field            | meaning                                                        |
|------------------|----------------------------------------------------------------|
| `writer[+0x00]`  | found-entry / data start pointer (set by 6890, unused by 65b0) |
| `writer[+0x08]`  | **base** pointer for appended bytes                            |
| `writer[+0x10]`  | **byte offset / cursor** (read, written-back as `+= 4`)        |

Magic constants:

| value     | where        | meaning                                                            |
|-----------|--------------|--------------------------------------------------------------------|
| `0x69`    | 0x180005c75  | **TLV tag** to look up (='i', 105). The field this fn writes into. |
| `4`       | 6b0 @0x65c3  | bytes per append; each call writes exactly one 32-bit word.        |
| `0x40`    | 0x180005c66  | local frame size (holds the 24-byte writer @ +0x20 plus padding).  |

No `>>16`, `*65536`, `0x10000`, `0x8000`, `atan2`, `sqrt`, sort, or matrix ops appear anywhere
in this function or in the `65b0`/`6890`/`6800`/`6680` copy/scan helpers. The two appended words
are opaque 32-bit blobs here.

## Callees

- `0x1800065b0` — **append-4-bytes-and-bump-cursor** into the TLV field's writer (`dst = base+offset; memcpy 4; offset += 4`). Calls `sub_1800031e0`. (Local note; no standalone doc.)
- `0x180006890` — **TLV find-by-tag** wrapper: count-guard on `[hdr+4]`, build a stream cursor (`sub_180006680`), then scan with `sub_180006800` for tag `0x69`; returns 1 on hit and fills the writer. (Local note; calls `0x180006680`, `0x180006800`.)
  - `0x180006680` — cursor/iterator init: zero a 24-byte struct, then if `rdx != 0` set `{rdx, rdx+4, 0}`.
  - `0x180006800` — recursive TLV tag-scan: match 16-bit tag → fill out + ret 1; tag==1 terminator → ret 0; else advance (`0x1800067a0`) and recurse.
  - `0x1800031e0` — see `func_1800031e0.md` (aligned/unaligned block copy, the `memcpy` helper).

## GDB verification hooks

To verify a Python re-implementation produces identical intermediate values:

- `break *0x180005c7a` — at the lookup call. Dump:
  - `rcx` = `section` handle; `*(void**)rcx` = header; `*(uint32*)((*(void**)rcx)+4)` = the count
    guard (if 0 the function is a no-op); `*(void**)((*(void**)rcx)+8)` = TLV stream base.
  - `edx` should read `0x69` (the tag).
- `break *0x180005c7f` — right after the lookup returns. Dump `eax` = hit(1)/miss(0). Also dump the
  populated writer: `x/3gx $rsp+0x20` ⇒ `[+0]=data ptr, [+8]=base, [+0x10]=cursor` (cursor is the
  start byte-offset where the two words will land).
- `break *0x180005c83` — first append. Dump `rdi` = `ptrA` and `*(uint32_t*)rdi` = the **first**
  32-bit word about to be written; cross-check against your Python field bytes.
- `break *0x1800065cc` (inside `sub_1800065b0`, hit twice) — the actual 4-byte memcpy. Dump:
  - `rcx` = dst = `base + offset`; `rdx` = src; `*(uint32_t*)rdx` = the word value.
  - On the **1st** hit `rdx == ptrA`; on the **2nd** hit `rdx == ptrB`. Record both `dst` addresses;
    they must be 4 bytes apart (offset advanced by `add [rbx+0x10],4` @ `0x1800065d1`).
- `break *0x180005c90` — second append; dump `rbx` = `ptrB` and `*(uint32_t*)rbx` = the **second**
  32-bit word. The final tag-0x69 field content = `[*(uint32)ptrA][*(uint32)ptrB]` (8 bytes, LE).
- `break *0x180005c9d` — `L_done`. If reached directly from `0x180005c81` (eax==0), confirm nothing
  was appended (the field cursor in the writer is unchanged).

## Confidence & open questions

**Solid (directly in disasm):**
- Control flow: lookup tag `0x69`; on miss return, on hit append two 4-byte words then return.
- `edx=0x69` is the lookup tag; each `sub_1800065b0` writes exactly 4 bytes and bumps the cursor by 4.
- `ptrA` (rdx) is appended first, `ptrB` (r8) second; both treated as `uint32*` (4-byte copy).
- The function returns nothing meaningful; no fixed-point / trig / matrix math is performed here.

**Inferred / GUESS:**
- The semantic identity of the two 32-bit words (tx/ty vs comp0/comp1 vs count/id). This function is
  blind to it; it must be determined from the *caller* that supplies `ptrA`/`ptrB`. Recommend
  hooking the caller of `sub_180005c60` and dumping `*(int*)rdx`, `*(int*)r8` to learn whether they
  are Q16 fixed-point (look for `>>16`/`*65536` producers upstream) or plain integers.
- Tag `0x69`'s role in the sec0_pre TLV layout — cross-reference `scripts/parse_ws_tlv.py` /
  `scripts/decode_sec0_pre.py` tag tables to map `0x69` to a named field.
- Whether `writer[+0]` (set by the lookup but unread by the appender) matters downstream — here it is
  only carried, not used.
