# sub_180006e10 — 2-point rigid (similarity, scale=1) Q16 transform solver

Given **two point correspondences** (a "src" pair and a "dst" pair), this function
computes the **rotation** (as Q16 `a = cos·65536`, `b = sin·65536`) and the
**Q16 translation** `(tx, ty)` of the rigid transform that maps the dst pair onto
the src pair. Scale is forced to **1** (the magnitudes cancel in the division), so
this is a pure rotation+translation fit from a single edge/segment correspondence.
This is exactly the `R = [[a,-b],[b,a]], t = (tx,ty)` Q16 form that lands in `sec0_pre`.

Returns `1` on success, `0` if the segments are degenerate (zero length).

- `dst` vs `src` orientation is inferred from the algebra (see below): the transform
  maps the `dst` (rsi) midpoint+vector onto the `src` (rbp) midpoint+vector, i.e.
  `src ≈ R·dst + t`. The "previous/current" naming is a plausible guess for the
  enrollment frame-registration context; the math does not name them.
- The four output pointers (`a,b,tx,ty`) are the standard Q16 similarity-transform

## Pseudocode

```c
int sub_180006e10(int32_t *out_a, int32_t *out_b, int32_t *out_tx, int32_t *out_ty,
                  const int32_t *dst, const int32_t *src)
{
    // --- prologue: save rbx,rbp,rsi + push rdi,r12..r15, sub rsp,0x20 ---   // 0x180006e10..0x180006e2c
    //   r15 = out_a (rcx), r14 = out_b (rdx), r13 = out_tx (r8), r12 = out_ty (r9)  // 0x180006e36 / e66 / e63 / e5c
    //   rbp = src = [rsp+0x78]  (6th arg)                                     // 0x180006e2c
    //   rsi = dst = [rsp+0x70]  (5th arg)                                     // 0x180006e31

    // --- displacement vectors (signed int32) ---
    int dx_src = src[2] - src[0];          // P1.x - P0.x                      // 0x180006e39 + 0x180006e43
    int dy_src = src[3] - src[1];          // P1.y - P0.y                      // 0x180006e3c + 0x180006e46
    int dx_dst = dst[2] - dst[0];          // Q1.x - Q0.x                      // 0x180006e3f + 0x180006e49
    int dy_dst = dst[3] - dst[1];          // Q1.y - Q0.y                      // 0x180006e4c + 0x180006e54

    // --- DOT and CROSS of the two displacement vectors (32-bit signed muls) ---
    //   imul are 32-bit (overflow possible if coords are large; coords are small px deltas)
    int CROSS = dy_src*dx_dst - dx_src*dy_dst;   // ebx                        // 0x180006e58,e69,e6d
    int DOT   = dx_src*dx_dst + dy_src*dy_dst;   // edi                        // 0x180006e5f,e6f,e73

    // --- denominator = isqrt(DOT^2 + CROSS^2) = |Vsrc|*|Vdst| ---
    int ss = CROSS*CROSS + DOT*DOT;        // ecx (sum of squares)             // 0x180006e79,e7c,e7f
    int denom = isqrt_u32(ss);             // r11d = sub_180003060(ecx)        // 0x180006e81 (call 0x180003060)
                                           //   (isqrt returns floor(sqrt(unsigned ecx)))
    if (denom <= 0) {                      // test eax,eax; jg                 // 0x180006e86 / e8b
        return 0;                          // xor eax,eax; jmp epilogue        // 0x180006e8d / e8f -> 0x180006eff
    }

    // --- rotation as Q16: a = cos*65536, b = sin*65536 (scale cancels => =1) ---
    //   theta = angle(Vdst) - angle(Vsrc); a = DOT/(|Vsrc||Vdst|), b = CROSS/(|Vsrc||Vdst|)
    int a = ((int64_t? signed)(DOT   << 16)) / denom;  // idiv r11d, signed    // 0x180006e91,e97,e99(cdq),e9a
    *out_a = a;                            // mov [r15], r8d (a)               // 0x180006ea2  (a kept in r8d)
    int b = ((signed)(CROSS << 16)) / denom;           // idiv r11d, signed    // 0x180006e94,ea0,ea5(cdq),ea6
    *out_b = b;                            // mov [r14], eax (b)               // 0x180006ea9  (b also kept in r9d @ e b7)
    // r8d = a, r9d = b for the translation below.

    // --- translation TX: T = midpoint_src - R * midpoint_dst, in Q16, then /2 ---
    //   (the /2 because sums P0+P1 and Q0+Q1 are 2*midpoint; SAR by 1 halves once)
    {
        int sumDstX = dst[0] + dst[2];     // Q0.x + Q1.x  (ecx)               // 0x180006eaf,eb1
        int sumDstY = dst[1] + dst[3];     // Q0.y + Q1.y  (edx)               // 0x180006eac,eb4
        int sumSrcX = src[0] + src[2];     // P0.x + P1.x                      // 0x180006ec3,ec6
        // edx = b*sumDstY - a*sumDstX
        int t = b*sumDstY - a*sumDstX;     //                                  // 0x180006eba,ebd,ec1
        t += (sumSrcX << 16);              // add (P0.x+P1.x)<<16              // 0x180006ec9,ecc
        *out_tx = t >> 1;                  // SAR edx,1  -> [r13]              // 0x180006ece,ed0
        //  => TX = ((P0.x+P1.x)<<16 - a*(Q0.x+Q1.x) + b*(Q0.y+Q1.y)) / 2
    }

    // --- translation TY ---
    {
        int sumDstY = dst[1] + dst[3];     // Q0.y + Q1.y  (eax)               // 0x180006ed4,eda
        int sumSrcY = src[1] + src[3];     // P0.y + P1.y  (ecx)               // 0x180006ed7,edd
        int sumDstX = dst[0] + dst[2];     // Q0.x + Q1.x                      // 0x180006ee9,eeb
        int t = (sumSrcY << 16) - a*sumDstY;   // ecx                          // 0x180006ee0,ee3,ee7
        t -= b*sumDstX;                    //                                  // 0x180006eee,ef2
        *out_ty = t >> 1;                  // SAR ecx,1 -> [r12]               // 0x180006ef9,efb
        //  => TY = ((P0.y+P1.y)<<16 - a*(Q0.y+Q1.y) - b*(Q0.x+Q1.x)) / 2
    }

    return 1;                              // mov eax,1 (set @ 0x180006ef4)    // 0x180006ef4
    // --- epilogue: restore rbx/rbp/rsi/r12..r15, ret ---                     // 0x180006eff..0x180006f1b
}
```

### Closed form (the thing to port)

Let `Vsrc = P1-P0`, `Vdst = Q1-Q0`.
```
DOT   = Vsrc · Vdst
CROSS = Vsrc × Vdst    (= dy_src*dx_dst - dx_src*dy_dst, note the sign/order)
denom = isqrt(DOT^2 + CROSS^2)      == |Vsrc| * |Vdst|   (integer floor sqrt)
if denom <= 0: return 0

a = (DOT   << 16) / denom            // cos(theta) * 65536  (theta = ∠Vdst - ∠Vsrc)
b = (CROSS << 16) / denom            // sin(theta) * 65536
// |a^2 + b^2| ≈ 65536^2  → similarity with scale 1 (a pure rotation).

R = [[ a, -b],
     [ b,  a]]                       // Q16

// midpoints (×2 form): SS = P0+P1 (src), SD = Q0+Q1 (dst)
tx = ((P0.x+P1.x) << 16  -  a*(Q0.x+Q1.x)  +  b*(Q0.y+Q1.y)) >> 1
ty = ((P0.y+P1.y) << 16  -  a*(Q0.y+Q1.y)  -  b*(Q0.x+Q1.x)) >> 1
// i.e.  t = midpoint_src*65536  -  R · midpoint_dst    (all Q16; the >>1 turns the
//        doubled sums into a single midpoint divide).
// So:  src_point*65536  ≈  R · dst_point  +  t.
```

The `<<16` and `>>1` are **arithmetic/signed** (SAR), and the two `idiv` are
**signed** (preceded by `cdq`). The 32-bit `imul`s truncate to 32 bits.

## GDB verification hooks

Attach to the Wine process and break at these addresses to capture intermediate values
for a Python port (`break *0x...`). Registers are 32-bit unless noted.

1. **Entry — capture inputs** `break *0x180006e36`
   - `rcx` = out_a ptr, `rdx` = out_b ptr, `r8` = out_tx ptr, `r9` = out_ty ptr.
   - `*(int*)$rsp+0x70`-derived: dump `dst` and `src` after the next two loads. Easiest: break at **`0x180006e39`** and dump `x/4dw $rsi` (= dst: Q0.x,Q0.y,Q1.x,Q1.y) and `x/4dw $rbp` (= src: P0.x,P0.y,P1.x,P1.y).

2. **After DOT/CROSS** `break *0x180006e81` (right before the isqrt call)
   - `edi` = `DOT` (Vsrc·Vdst), `ebx` = `CROSS` (Vsrc×Vdst), `ecx` = `ss` = DOT²+CROSS² (the isqrt input). Verify your DOT/CROSS signs and the 32-bit product truncation.

3. **isqrt result / degeneracy gate** `break *0x180006e86`
   - `eax` (= `r11d`) = `denom` = floor(sqrt(ss)) = |Vsrc|·|Vdst|. If `eax <= 0` the function returns 0 here — confirm your degenerate-segment handling matches.

4. **Rotation written** `break *0x180006ea9`
   - `r8d` = `a` (just stored to `[r15]` = *out_a). `eax` = `b` (about to store to `[r14]` = *out_b). These are `cos·65536` and `sin·65536`. Also dump `x/1dw $r15` to confirm the `a` store landed.
   - Sanity: `a*a + b*b` should be ≈ `65536*65536` (= 0x100000000), confirming scale=1.

5. **TX written** `break *0x180006ed4` (just after `mov [r13],edx`)
   - `x/1dw $r13` = `*out_tx` (Q16). Compare to `((P0.x+P1.x)<<16 - a*(Q0.x+Q1.x) + b*(Q0.y+Q1.y)) >> 1`.

6. **TY written / return** `break *0x180006eff` (epilogue entry, after `mov [r12],ecx`)
   - `x/1dw $r12` = `*out_ty` (Q16). `eax` = return (1 on success).
   - Dump all four outputs together: `x/1dw $r15`, `x/1dw $r14`, `x/1dw $r13`, `x/1dw $r12` → (a, b, tx, ty). NOTE r15..r12 are restored *after* this point, so set the break exactly at `0x180006eff` before the pops.

To capture across many calls, log at hooks #1 (inputs), #4 (a,b), and #6 (tx,ty,ret).

## Confidence & open questions

**Solid (high confidence):**
- The full arithmetic: DOT/CROSS of the two segment vectors, `denom = isqrt(DOT²+CROSS²)`, `a=(DOT<<16)/denom`, `b=(CROSS<<16)/denom`, and the two translation formulas. Every line is traced to an address; signedness (`cdq`/`idiv`, `sar`) and the Q16 `<<16` / `>>1` are explicit in the disasm.
- `0x180003060` is a floor integer square root (independently disassembled).
- Output mapping `r15→a, r14→b, r13→tx, r12→ty`, and inputs `rsi=dst (arg5)`, `rbp=src (arg6)`.
- This produces a **scale-1 similarity** (`a²+b²≈65536²`) — a pure rotation+translation — solved from exactly **one segment correspondence** (2 point pairs).

**Inferred / open:**
- The semantic labels "src/previous" vs "dst/current": chosen so that `src ≈ R·dst + t`
  (the rotation angle is `∠Vdst − ∠Vsrc`, and `t = mid_src·65536 − R·mid_dst`). Whether
  the caller treats `rbp` as the reference frame or the moving frame is a caller-level
  question; verify against the caller of `sub_180006e10`.
- The `imul`s are 32-bit and can overflow for large coordinates. Given fingerprint tile
  pixel coordinates (small), this is fine, but a faithful Python port should mask to
  `int32` (wrap) to be byte-exact in pathological cases. The intermediate `DOT<<16`,
  `CROSS<<16`, and `sum<<16` are also taken mod 2³² then signed-divided — replicate with
  `int32` wrap + truncating (C-style) division, not Python floor division.
- No struct-offset ambiguity, no loops, no RANSAC/voting here — this is the inner
  closed-form 2-point solver; any voting/argmax happens in a caller.
