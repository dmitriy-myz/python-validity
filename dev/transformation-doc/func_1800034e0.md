# sub_1800034e0 — Hamming distance between two byte buffers (XOR + popcount-LUT sum)

This is **not** transform/geometry math. It is the descriptor-distance primitive: given two
equal-length byte buffers (binary fingerprint descriptors), it XORs them word-by-word and sums
the number of differing bits (Hamming weight of `A XOR B`) using a 256-entry popcount lookup
table. The result is the integer Hamming distance, which the matcher uses to compare descriptors.

The table at `0x18011ebd0` was extracted from `/tmp/syna.dll` (`.rdata`, file offset `0x11d7d0`)
and byte-for-byte equals `popcount(i) for i in 0..255` — **confirmed**.

---

## Signature

```c
// Returns the Hamming distance (count of differing bits) between buf_a and buf_b
// over the word range [start_word, total_bytes/4).
//
// rcx = a            : const uint32_t* buf_a   (treated as 32-bit words)
// rdx = b            : const uint32_t* buf_b   (treated as 32-bit words)
// r8d = start_word   : uint32_t, index (in 32-bit words) where comparison begins  (GUESS: a resume offset)
// r9d = total_bytes  : uint32_t, total byte length; converted to word count via >>2
//
// NOTE: r9d is shifted right by 2 at entry, so the caller passes a BYTE length and the
//       function reinterprets it as a count of 4-byte words. start_word (r8d) is already
//       in word units (it is NOT shifted).
int sub_1800034e0(const uint32_t *a,    // rcx
                  const uint32_t *b,    // rdx
                  uint32_t start_word,  // r8d
                  uint32_t total_bytes);// r9d  -> word_count = total_bytes >> 2
```

The two trailing stack slots `[rsp+0x28]`/`[rsp+0x30]` are **not parameters** here — they are the
home/spill slots the function restores `rbp` and `rsi` from on the way out (see prologue note).
Actually the prologue saves rbx/rbp/rsi into the *caller-provided* shadow space at
`[rsp+0x10..0x20]` and then reloads rbp/rsi from `[rsp+0x28]/[rsp+0x30]` at exit — this is the
standard MSVC frameless prologue where the saved-reg slots and shadow space overlap; treat them
as register save/restore, not arguments.

## Pseudocode

```c
int sub_1800034e0(uint32_t *a, uint32_t *b, uint32_t start_word, uint32_t total_bytes)
{
    // ---- prologue / save regs ----                                  // 0x1800034e0
    // [rsp+0x10]=rbx, [rsp+0x18]=rbp, [rsp+0x20]=rsi ; push r12, r13   // 0x1800034e0..0x1800034f1
    uint32_t sum_b   = 0;            // ebx  (running accumulator #1)   // 0x1800034f3 xor ebx,ebx
    uint32_t wcount  = total_bytes >> 2;   // r9d : word count          // 0x1800034f5 shr r9d,2
    uint32_t i       = start_word;   // r11d : current word index       // 0x1800034f9 mov r11d,r8d
    uint32_t rem     = wcount - start_word; // eax (words remaining)    // 0x1800034fc/0x180003505
    uint32_t sum_r12 = 0;            // r12d (running accumulator #2)   // 0x1800034ff
    uint32_t sum_r10 = 0;            // r10d (tail accumulator)         // 0x180003502

    uint32_t *pa = &a[start_word];   // rsi = rcx + start_word*4        // 0x180003508 lea rsi,[rcx+r11*4]
    uint32_t *pb = &b[start_word];   // rbp = rdx + start_word*4        // 0x18000350c lea rbp,[rdx+r11*4]
    const uint8_t *POP = (uint8_t*)0x18011ebd0; // popcount LUT (r13)   // 0x180003513 lea r13,[rip+0x11b6b6]

    if ((int)rem < 2) goto TAIL;     // signed compare eax,2            // 0x180003510/0x18000351a jl 0x1800035dc

    // ---- compute unrolled-by-2 trip count ----                      // 0x180003520
    // [rsp+0x18] now also spills rdi (saved)                          // 0x180003523 mov [rsp+0x18],rdi
    uint32_t n2 = ((wcount - i) - 2) >> 1 + 1;  // edi : loop trips     // 0x180003528..0x180003533
    //   eax = wcount - start_word; eax -= 2; eax >>= 1; eax += 1; edi = eax
    i += 2 * n2;                     // r11d advanced past the loop     // 0x180003535 lea r11d,[r11+rax*2]
    uint32_t trips = n2;             // rdi

    // ---- MAIN LOOP: process 2 words per iteration ----              // 0x180003540  (loop head)
    do {
        // ---- word #0 ----
        uint32_t x = pb[0] ^ pa[0];  // eax = *rbp ^ *(rsi)             // 0x180003540 / 0x18000354b
        pa++;  pb++; // both advanced by 8 bytes (=2 words) below...    // 0x180003543/0x180003547 add rsi/rbp,8
        uint32_t d = x;              // edx = full 32-bit xor (word #0) // 0x18000354e

        //  popcount of each of the 4 bytes of x, summed into r8d, plus
        //  the byte-0 popcount folded into sum_b (ebx):
        uint8_t b2 = (x >> 16) & 0xff;                                 // 0x180003550/0x180003554
        uint32_t s = POP[b2];        // r8d = POP[byte2]                // 0x18000355a
        uint8_t b1 = (x >> 8)  & 0xff;                                 // 0x18000355f/0x180003563
        s += POP[b1];                                                  // 0x180003566/0x18000356b
        uint8_t b3 = (x >> 24) & 0xff;                                 // 0x18000356e/0x180003571
        s += POP[b3];                                                  // 0x180003575/0x18000357a
        uint8_t b0 = x & 0xff;                                         // 0x18000357d
        sum_b += POP[b0];            // ebx += POP[byte0]               // 0x180003580/0x180003585
        sum_b += s;                  // ebx += (POP[b1]+POP[b2]+POP[b3])// 0x18000358d add ebx,r8d
        // => sum_b += popcount(x) for word #0

        // ---- word #1 ----  (note: reads [rbp-4]/[rsi-4] because both ptrs
        //                      were already advanced by 8 above)
        uint32_t x2 = pb[-1] ^ pa[-1]; // eax = *(rbp-4) ^ *(rsi-4)     // 0x180003587/0x18000358a
        uint32_t d2 = x2;            // edx                             // 0x180003590
        uint8_t c2 = (x2 >> 16) & 0xff;                                // 0x180003592/0x180003596
        uint32_t s2 = POP[c2];      // r8d                             // 0x18000359c
        uint8_t c1 = (x2 >> 8)  & 0xff;                                // 0x1800035a1/0x1800035a5
        s2 += POP[c1];                                                 // 0x1800035a8/0x1800035ad
        uint8_t c3 = (x2 >> 24) & 0xff;                                // 0x1800035b0/0x1800035b3
        s2 += POP[c3];                                                 // 0x1800035b7/0x1800035bc
        uint8_t c0 = x2 & 0xff;                                        // 0x1800035bf
        sum_r12 += POP[c0];         // r12d += POP[byte0 of word#1]     // 0x1800035c2/0x1800035c7
        sum_r12 += s2;              // r12d += rest                     // 0x1800035ca
        // => sum_r12 += popcount(x2) for word #1

    } while (--trips != 0);          // sub rdi,1 ; jne 0x180003540     // 0x1800035cd/0x1800035d1

    rdi = saved_rdi; // [rsp+0x18]                                     // 0x1800035d7

TAIL:                                                                  // 0x1800035dc
    // ---- handle 0 or 1 leftover word ----
    if (i < wcount) {                // cmp r11d,r9d ; jae 0x180003620  // 0x1800035dc/0x1800035df
        uint32_t x = pb[0] ^ pa[0];  // eax = *rbp ^ *rsi               // 0x1800035e1/0x1800035e4
        uint32_t d = x;              // edx                             // 0x1800035e6
        uint8_t b2 = (x >> 16) & 0xff;                                 // 0x1800035e8/0x1800035ec
        sum_r10  = POP[b2];          // r10d = POP[byte2]               // 0x1800035f2
        uint8_t b1 = (x >> 8) & 0xff;                                  // 0x1800035f7/0x1800035fb
        sum_r10 += POP[b1];                                            // 0x1800035fe/0x180003603
        uint8_t b3 = (x >> 24) & 0xff;                                 // 0x180003606/0x180003609
        sum_r10 += POP[b3];                                            // 0x18000360d/0x180003612
        uint8_t b0 = x & 0xff;                                         // 0x180003615
        sum_r10 += POP[b0];                                            // 0x180003618/0x18000361d
        // => sum_r10 = popcount(x) for the single tail word
    }

    // ---- epilogue / combine partial sums ----                       // 0x180003620
    rbp = [rsp+0x28];  rsi = [rsp+0x30];   // restore                   // 0x180003620/0x180003625
    int result = sum_r12 + sum_b;          // lea eax,[r12+rbx*1]       // 0x18000362a
    rbx = [rsp+0x20];                      // restore                   // 0x18000362e
    result += sum_r10;                     // add eax,r10d              // 0x180003633
    // pop r13 ; pop r12                                                // 0x180003636/0x180003638
    return result;                         // ret                      // 0x18000363a
}
```

### Net effect (the readable version)

```c
int hamming_distance(const uint32_t *a, const uint32_t *b,
                     uint32_t start_word, uint32_t total_bytes)
{
    uint32_t wcount = total_bytes >> 2;     // number of 32-bit words
    int dist = 0;
    for (uint32_t i = start_word; i < wcount; ++i)
        dist += popcount(a[i] ^ b[i]);      // POP[] is the 256-byte popcount LUT
    return dist;
}
```

The three accumulators (`sum_b`/`ebx`, `sum_r12`/`r12d`, `sum_r10`/`r10d`) are purely a
loop-unrolling/pipelining artifact — even-index words go into `sum_b`, odd-index into `sum_r12`,
and the optional final odd word into `sum_r10`; they are summed at the end. The math is exactly
the popcount of the XOR over `[start_word, wcount)`.

| Access | Reg | Meaning |
|---|---|---|
| `rcx` (arg0) | base `a` | pointer to buffer A (32-bit-word view) |
| `rdx` (arg1) | base `b` | pointer to buffer B (32-bit-word view) |
| `r8d` (arg2) | `start_word` | starting **word** index (not byte) |

| `[rcx + r11*4]` | `rsi`=`pa` | `&a[start_word]`, advanced by 8 (2 words) per iter |
| `[rdx + r11*4]` | `rbp`=`pb` | `&b[start_word]`, advanced by 8 (2 words) per iter |
| `[rsi-8]`,`[rsi-4]`,`[rsi]` | — | words of A (word#0, word#1, tail) |
| `[rbp+0]`,`[rbp-4]`,`[rbp]` | — | words of B (word#0, word#1, tail) |
| `[byteval + r13*1]` | `r13`=`POP` | popcount LUT lookup, one per byte of the XOR |

Magic constants:

| Const | Where | Meaning |
|---|---|---|
| `>>2` (`shr r9d,2`) | 0x1800034f5 | bytes → 32-bit-word count |
| `0x11b6b6` (rip-rel) | 0x180003513 | → absolute `0x18011ebd0`, **256-byte popcount LUT** |
| `0x18011ebd0` | `.rdata` | `POP[i] = popcount(i)`, verified vs syna.dll |
| `cmp eax,2` / `jl` | 0x180003510 | if fewer than 2 words remain, skip the unrolled loop |
| shifts `>>8/>>16/>>24` + `&0xff` | loop body | extract the 4 bytes of each XOR word |
| `>>1`, `+1` (trip count) | 0x18000352e..0x180003530 | `((rem-2)/2)+1` iterations of the by-2 loop |

There is **no fixed-point, no Q16, no trig, no matrix/affine, no rounding constant** (no `0x8000`,
no `*65536`). The only shifts are byte extraction (`>>8/16/24`) and the byte→word `>>2`.

## GDB verification hooks

To verify a Python re-implementation produces identical intermediate values:

- `break *0x1800034e0` — entry. Dump args:
  - `rcx` = `a` ptr, `rdx` = `b` ptr, `r8d` = `start_word`, `r9d` = `total_bytes` (BEFORE the `>>2`).
  - After stepping past `0x1800034f5`, `r9d` = word count.
- `break *0x180003508` — confirm `rsi = rcx + start_word*4` (`&a[start_word]`).
- `break *0x18000350c` — confirm `rbp = rdx + start_word*4` (`&b[start_word]`).
- `break *0x180003513` — confirm `r13 == 0x18011ebd0` (popcount table base).
- `break *0x18000354b` — first XOR of the loop. Dump `eax` = `a[i] ^ b[i]` for word#0; this is the
  per-word value whose bits we count.
- `break *0x18000358d` — `ebx` (sum_b) right after folding word#0's popcount. Watch `ebx` grow by
  `popcount(word#0)` each iteration.
- `break *0x1800035ca` — `r12d` (sum_r12) after folding word#1's popcount each iteration.
- `break *0x1800035d1` — loop back-edge. Dump `rdi` (remaining trips), `r11d` (current word index),
  `ebx`, `r12d`. Lets you reconstruct the running total at every step.
- `break *0x1800035e4` — tail single-word XOR (`eax`); `r10d` afterward = `popcount(tail word)`.
- `break *0x18000362a` — `lea eax,[r12+rbx]`: partial sum `sum_r12+sum_b`.
- `break *0x18000363a` (or read `eax` at the `ret`) — **final return = Hamming distance**. This is
  the single number to match against `sum(popcount(a[i]^b[i]) for i in range(start_word, wcount))`.

Suggested gdb one-liner at exit:
`break *0x180003633` then `finish`/inspect `eax` = total before the last add; `eax` at `0x18000363a` = full result.

## Confidence & open questions

**Solid (high confidence):**
- The function computes `sum over words i in [start_word, total_bytes/4) of popcount(a[i] ^ b[i])`,
  i.e. the **Hamming distance** between two byte buffers. The `0x18011ebd0` table is verified to be
  the exact 256-entry popcount LUT (extracted from `/tmp/syna.dll`).
- `total_bytes` (r9d) is a byte length reinterpreted as words via `>>2`; `start_word` (r8d) is in
  word units and is NOT shifted.
- The three accumulators are a 2x-unroll + tail artifact; the result is order-independent and equals
  the simple loop above. No geometry/fixed-point/transform math is present.

**Inferred / open:**
- The semantic meaning of `start_word` (r8d) — labeled here as a "resume offset". In the matcher
  context it most likely lets the caller skip a header or compare only a sub-range of a descriptor.
  The disasm only shows it as the loop start index; its caller-side meaning is a GUESS.
- Argument *names* (a/b are interchangeable since XOR is symmetric). Which buffer is the probe vs
  template descriptor is not determinable from this function alone.
- This function is **irrelevant to sec0_pre rigid-transform registration**; it is a descriptor
  comparison helper. (`is_transform_math = false`.)
