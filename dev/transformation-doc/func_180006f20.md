# sub_180006f20 — 2D similarity (rigid+scale) transform fit between two equal-length point sets (Q16 output)

This is the core least-squares estimator that, given two arrays of N 2D integer points
(`A[i]` and `B[i]`, the matched correspondences), computes the 2D **similarity transform**
that maps one set onto the other. It returns the rotation cosine/sine (normalized to Q16 via
the helper `0x180006c40`) and the translation, plus a per-component scale, into caller-provided
output pointers. These are exactly the `R=[[a,-b],[b,a]], t=(tx,ty)` Q16 transforms that land in
`sec0_pre`.

The algorithm is the closed-form 2D Procrustes/Kabsch solution done in integer fixed-point:
1. Pass 1: compute the centroids (means) of both point sets (sum / N).
2. Pass 2: accumulate the cross-covariance terms of the centered points
   (`Sxx`-style products: `Σ dx_B·dx_A`, `Σ dy_B·dy_A`, `Σ dx_B·dy_A − dy_B·dx_A`, …).
3. Combine into a 2-vector `(numerator_cos, numerator_sin)`, normalize it to unit length
   via `0x180006c40` (→ Q16 cos/sin), then derive translation and scale and write 4–5 outputs.

- The 4 register args (`rcx,rdx,r8,r9`) are only spilled to the shadow area at entry

- The real inputs are the **stack arguments** at `[rsp+0xe0]`, `[rsp+0xe8]`, `[rsp+0xf0]`,

    // ================= WRITE OUTPUTS =================

    *out_sin = b;   // *[rsp+0xc8] = b                                       // 0x1800072f5/0x180007300

        // NOTE: slot28 here holds meanBx-class value (the dst-x mean). see open-q.

    ecx = b * meanBx2;                                     // 0x1800072fd/03  ecx = b*meanX
    eax = a;                                                                  // 0x180007307
    r12d (meanAx?) <<= 16;  r13d (meanAy?) <<= 16;        // 0x18000730a/0e  centroids to Q16
    r11d = a * meanBx2;                                    // 0x180007312     r11 = a*meanX
    r8d  = b' * meanBy;     // ebp = meanBy                // 0x180007316
    r13d = (meanAy<<16) - r11d - r8d;   // ty numerator    // 0x18000731a/1d
    eax  = a * ebp(meanBy);                                // 0x180007320
    ecx -= eax;                                            // 0x180007323     ecx = b*meanX - a*meanY

    *out_tx = eax / N;   // *[rsp+0xd0]                    // 0x180007329..0x180007334  idiv ebx=N
    *out_ty = r13d / N;  // *[rsp+0xd8]                    // 0x180007336..0x180007344  idiv ebx=N

    return 1;                                              // 0x180007346  eax=1
    // epilogue: restore callee-saved, add rsp,0xb8, ret  // 0x18000734b..0x180007382
}

### What the math is (clean summary, ignoring fixed-point bookkeeping)

Let `Ā=(Āx,Āy)` and `B̄=(B̄x,B̄y)` be the centroids of the two point sets (computed in pass 1
as integer means). For the centered points `a_i = A_i − Ā`, `b_i = B_i − B̄`, pass 2 accumulates
the standard 2D Procrustes sums:

```
S_c = Σ ( b_i.x·a_i.x + b_i.y·a_i.y )      // "dot" term  → numerator of cos
S_s = Σ ( b_i.x·a_i.y − b_i.y·a_i.x )      // "cross" term → numerator of sin
```

(the four stack accumulators slot44/slot40/slot30/slot3c plus the odd-element leftovers
fold into exactly these two sums). Then:

```
cosN = S_c / N ;  sinN = S_s / N
mag  = isqrt(cosN² + sinN²)
a = cos*2^16 = (cosN<<16)/mag ;  b = sin*2^16 = (sinN<<16)/mag      // Q16, then re-normalized by 0x180006c40
tx = ((Āx<<16) + b·B̄x − a·B̄y) / N    // ≈ Āx·2^16 − (a·B̄x − ... )  rounding aside
ty = ((Āy<<16) − a·B̄x − b·B̄y) / N
```

i.e. the rigid map `A ≈ R·B + t` with `R=[[a,−b],[b,a]]` (Q16). The final `/N` on the
translations is unusual and is flagged below as an open question (it may be that the centroid
sums were left un-divided in those branches — worth checking on hardware).

## Struct fields & constants

Inputs are **flat arrays of points**, element stride 8 bytes = `{int32 x; int32 y;}`.
Two parallel arrays indexed by the same `i`.

Magic constants:
- `0x10000` / `<<16` — Q16 fixed-point promotion (the transform precision). At `0x1800072a9`,
  `0x1800072ac`, `0x18000730a`, `0x18000730e`.
- `idiv ebx` where `ebx = N` — repeated integer mean/normalize divides (signed; `cdq` before each).
- `0x40000000` (in callee `0x180003060`) — isqrt seed (top bit of a 31-bit radicand).
- `shl ...,0xe` (=`<<14`, callee `0x180006c40`) — Q14 promotion inside the unit-vector normalizer.

## Callees

- `0x180003060` — **integer square root** (`isqrt`). Input `ecx` = radicand (here `cosN²+sinN²`),
  returns `eax = floor(sqrt(ecx))`. Classic restoring-sqrt with `0x40000000` seed, `>>2` per step.
  Self-contained, no further calls. (see also func_180003060.S)
- `0x180006c40` — **2D vector unit-normalizer (Q14/Q16)**. Args `rcx`→cosptr, `rdx`→sinptr.
  Reads `(x,y)=(*cos,*sin)`, halves each (`sar 1`), computes `mag=isqrt(x²+y²)` via `0x180003060`,
  then if `mag>>1 != 0` rewrites `*cos=(x<<14)/(mag>>1)`, `*sin=(y<<14)/(mag>>1)` — i.e. renormalizes
  the (cos,sin) pair to a fixed magnitude (rounds the Q16 cos/sin onto the unit circle); else leaves
  the halved values. (see func_180006c40.S)

## GDB verification hooks

Run under the Wine gdb harness (`GDB_DUMP_* gdb -p <PID> -x dev/gdb_dump.py`). Suggested breakpoints
and what to dump (all the load-bearing transform values):

1. `break *0x180006f3b` — **entry**: dump `*(int*)($rsp+0xf0)` = N, and `$rsp+0xe0`/`$rsp+0xe8`
   (pointers A,B). Then `x/8wd` each array start to capture the input points.
2. `break *0x1800070b0` — **after centroid divides start**: step to `0x1800070eb` and dump
   `$eax`/the slots `[rsp+0x48]`(meanAx), `[rsp+0x4c]`(meanBx), `[rsp+0x20]`(meanAy),
   `[rsp+0x38]`(meanBy). These are the integer centroids — verify against `sum/N` in Python.
3. `break *0x180007259` — **right before combine**: dump `[rsp+0x44]`,`[rsp+0x40]`,`[rsp+0x3c]`,
   `[rsp+0x30]`, `$r11d`, `$r10d`. These are the four covariance accumulators + the two leftovers
   that fold into `S_c` (cos numerator) and `S_s` (sin numerator).
4. `break *0x180007289` — **the isqrt call** (`call 0x180003060`): dump `$ecx` = `cosN²+sinN²`
   (radicand) on entry, and `$eax` on return (= `mag`). Also dump `$edi`=cosN and `$esi`=sinN just
   before (they are alive). This is THE key place to confirm the rotation numerators.
5. `break *0x1800072d3` — **the normalizer call** (`call 0x180006c40`): dump `*(int*)($rsp+0xf0)`
   (cosQ16 pre-normalize) and `*(int*)($rsp+0x20)` (sinQ16 pre-normalize); set a second break at
   `0x1800072d8` to dump the same two slots **after** normalization → final `a`,`b` (Q16 cos/sin).
6. `break *0x1800072f2` — **out_cos write**: dump `$r11d` (a) and the dest `*(void**)($rsp+0xc0)`.
   `break *0x180007300` for `$r8d` (b) + dest `[rsp+0xc8]`.
7. `break *0x180007334` — **out_tx write**: dump `$eax` (tx) and dest ptr `[rsp+0xd0]`.
   `break *0x180007344` — **out_ty write**: dump `$eax` (ty) and dest ptr `[rsp+0xd8]`.
8. `break *0x180007346` vs `0x1800072a2` — success(ret 1) vs underflow(ret 0) path, to confirm
   the `mag<=0` guard fires as your port expects.

For a Python re-implementation, the cross-check sequence is: inputs (hook 1) → centroids (hook 2) →
S_c/S_s accumulators (hook 3) → radicand+mag (hook 4) → a,b before/after normalize (hook 5) →
tx,ty (hook 7). Matching all of these byte-exact validates the whole estimator.

## Confidence & open questions

**Solid:**
- Overall shape: 2-pass (centroid then cross-covariance) closed-form 2D similarity/Procrustes fit,
  output in Q16, normalized via isqrt + unit-vector helper. The `<<16`/idiv-by-N/isqrt structure is
  unambiguous.
- Element layout `{int32 x, int32 y}`, stride 8, two parallel arrays at `[rsp+0xe0]` (A) and
  `[rsp+0xe8]` (B); N at `[rsp+0xf0]`; four out-pointers at `[rsp+0xc0..0xd8]`.
- Callee roles (`0x180003060`=isqrt, `0x180006c40`=2-vector renormalize) are certain from their bodies.
- The `mag<=0 → return 0` and `N<=0 → return 0` guards.

**Inferred / to verify on hardware:**
- The exact A-vs-B (which array is "src" vs "dst") and the precise sign assignment of the cross
  term `S_s`. The heavy register juggling between the unrolled iterations (e.g. the swapped
  mean subtractions `B.x − meanAx`, `A.x − meanBy`) means a couple of the per-component
  mean-subtraction pairings could be transposed from what's transcribed; the *aggregate* S_c/S_s
  are correct but verify component pairing with hooks 2–3 on real data.
- The trailing `/N` (`idiv ebx`) on **tx and ty** at `0x180007332`/`0x180007342`. With centroids
  already divided by N, dividing the translation by N again looks suspicious. Either (a) the
  centroid sums feeding the translation were the *un-divided* sums (so this /N is the centroid
  division for the translation path), or (b) it is genuinely an extra /N. Resolve with hook 7 +
  hook 2 on known input.
- `[rsp+0x28]` reused at `0x1800072ed` as `r10d` for the translation multiply (`b·X`): labeled
  meanBx-class here; confirm it is the dst/src centroid-x with hook 5/7.
- The 4 register args (rcx/rdx/r8/r9) are treated as unused; if a caller relies on side effects via
  them, that would contradict this (none observed — pure shadow store).
- Possible 2× over/under-count in the odd-N leftover folding (the `(N-2)/2+1` unrolling plus the
  separate odd-element block). The math handles even N cleanly; odd N exercises the `L_7031`/`L_7213`
  blocks — verify with an odd N test vector.
