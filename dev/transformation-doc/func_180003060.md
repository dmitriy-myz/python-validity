# sub_180003060 — integer square root (radix-4, isqrt of a uint32)

A tiny leaf helper (61 bytes, 23 instructions, **no callees**) that computes the
**integer square root** `floor(sqrt(n))` of a 32-bit unsigned input using the
classic "two-bits-at-a-time" / radix-4 digit-by-digit algorithm. It is pure
integer arithmetic — no fixed-point shifts of a Q16 value, no trig, no matrix
math. In the transform pipeline this is the scalar `isqrt` primitive used to turn
a squared magnitude (e.g. `dx*dx + dy*dy`) into a length/distance. It is **not**
itself the rigid-transform/affine math, but it is a building block those routines
call to get vector norms.

## Signature

```c
// best-effort; arg is unsigned because all compares (jae/jb/ja) are unsigned
uint32_t sub_180003060(uint32_t n /* ecx: value to take sqrt of */);
// returns floor(sqrt(n)) in eax
```

- `ecx` = `n`, the unsigned 32-bit radicand (consumed/decremented in place as the
  "remainder").
- return `eax` = `isqrt(n)` = largest `r` with `r*r <= n`.

## Pseudocode

Faithful, structured. `bit` lives in `edx`, `result` in `r8d`, `n`/remainder in `ecx`.

```c
uint32_t sub_180003060(uint32_t n /* ecx */)
{
    uint32_t bit    = 0x40000000;   // edx = 2^30 (highest even power-of-4 <= 2^31)  // 0x180003060
    uint32_t result = 0;            // r8d = 0                                        // 0x180003065

    // if n is already >= 2^30, the leading "bit" is valid as-is: skip the
    // scan-down and jump straight into the main loop.
    if (n >= bit) goto L_main;      // cmp ecx,edx ; jae 0x180003080                  // 0x180003068 / 0x18000306a

    // ---- scale 'bit' down to the largest power-of-4 that is <= n ----
L_scan:                                                                               // 0x180003070
    bit >>= 2;                      // edx >>= 2 (divide by 4)                         // 0x180003070
    if (bit > n) goto L_scan;       // cmp edx,ecx ; ja 0x180003070  (unsigned)        // 0x180003073 / 0x180003075

    // 'bit' now <= n (or 0 if n==0). Fall through with ZF set from the compare?
    // No — re-test bit explicitly, then enter the loop-tail dispatcher.
    test_zf = (bit == 0);           // test edx,edx                                    // 0x180003077
    goto L_tail;                    // jmp 0x180003098                                 // 0x180003079

    // ================= main digit-extraction loop =================
L_main:                                                                               // 0x180003080
    {
        uint32_t t = bit + result;  // eax = rdx + r8                                  // 0x180003080
        if (n < t) goto L_shift;    // cmp ecx,eax ; jb 0x180003092 (unsigned)         // 0x180003084 / 0x180003086

        t = bit + result;           // eax = rdx + r8 (recomputed)                     // 0x180003088
        result += 2 * bit;          // r8d = r8 + rdx*2  (lea r8d,[r8+rdx*2])          // 0x18000308c
        n -= t;                     // ecx -= (bit + result_old)                       // 0x180003090
    }

L_shift:                                                                               // 0x180003092
    result >>= 1;                   // r8d >>= 1                                        // 0x180003092
    bit    >>= 2;                   // edx >>= 2                                         // 0x180003095

L_tail:                                                                                 // 0x180003098
    if (bit != 0) goto L_main;      // jne 0x180003080 (uses ZF from the last shr/test) // 0x180003098

    return result;                  // mov eax,r8d ; ret                                // 0x18000309a / 0x18000309d
}
```

### Why this is `isqrt`

The recurrence is the textbook binary/radix-4 square-root:

- `bit` walks down the powers of four (2^30, 2^28, … , 1).
- Trial root candidate is `result + bit`.
- If `n >= result + bit`, subtract it from the remainder and set this digit
  (`result += 2*bit`, i.e. add the digit then it gets halved on the next line).
- Always `result >>= 1` after testing this digit so `result` tracks the partial
  square root; `bit >>= 2` advances to the next radix-4 digit.

The pre-loop `L_scan` is the standard "find the highest set radix-4 bit <= n"
initialization (skipped when `n >= 2^30`).

Spot-checks: `n=0 -> 0`, `n=1 -> 1`, `n=15 -> 3`, `n=16 -> 4`, `n=0xFFFFFFFF -> 0xFFFF`.

## Struct fields & constants

No memory operands at all — this function touches **no structs/pointers**. It is
register-only.

| Item | Where | Meaning |
|------|-------|---------|
| `0x40000000` | edx init (0x180003060) | `2^30`, the highest even power of four below 2^31; the starting `bit`. |
| `>> 2` (`shr ...,0x2`) | 0x180003070, 0x180003095 | radix-4 step: advance one square-root digit (divide `bit` by 4). |
| `>> 1` (`shr r8d,1`) | 0x180003092 | halve the partial result after each digit test. |
| `lea r8d,[r8+rdx*2]` | 0x18000308c | `result += 2*bit` (set this root digit). |
| `lea eax,[rdx+r8*1]` | 0x180003080, 0x180003088 | trial candidate `result + bit`. |

All compares are **unsigned** (`jae`/`jb`/`ja`), so `n` is treated as `uint32_t`.

## GDB verification hooks

To verify a Python `isqrt` re-implementation produces identical intermediates:

- `break *0x180003060` — entry. Dump `$rcx & 0xffffffff` = input `n`.
- `break *0x180003080` — top of main loop. Dump:
  - `$edx` = current `bit` (power of four),
  - `$r8d` = current partial `result`,
  - `$ecx` = current remainder `n`.
  These three fully define the loop state; logging them each iteration lets you
  diff against a Python trace of `(bit, result, remainder)`.
- `break *0x18000308c` — the "digit accepted" path. Dump `$r8d` (result before the
  `+= 2*bit`) and `$edx` (bit). Confirms which radix-4 digits get set.
- `break *0x18000309a` — exit. Dump `$r8d` = `floor(sqrt(n))`, the return value.

Suggested one-liner trace at the loop head:
`x/1dw &n`, then per-iter print `edx`, `r8d`, `ecx`.

## Confidence & open questions

- **High confidence**: this is `floor(sqrt(uint32))` via the radix-4
  digit-by-digit method. The instruction shape (`+2*bit`, `>>1` result, `>>2`
  bit, unsigned trial-subtract) is the canonical isqrt; manual traces match for
  0, 1, 15, 16, 0xFFFFFFFF.
- **Solid**: register roles (`edx`=bit, `r8d`=result, `ecx`=remainder/n) and that
  there are no memory/struct accesses and no callees.
- **Inferred (low stakes)**: that this is the scalar norm/length primitive used by
  the surrounding transform code. The function itself only proves "isqrt"; its
  *role* in the geometry pipeline must be confirmed at the call sites (search for
  `call 0x180003060`). The argument is almost certainly a squared magnitude
  `dx*dx+dy*dy` or a squared distance, but that semantic lives in the callers, not
  here.
- **Open**: none internal. The only open question is which callers feed it and what
  the squared input represents — answer by grepping `call .*180003060` in the
  disassembly and checking what builds `ecx`.
