# sub_180003d30 — build two index→payload lookup tables + two byte-keyed sparse maps (correspondence-table init)

This is a small (247-byte, 65-instr) **leaf** function (no callees). It does **no** fixed-point / trig / matrix arithmetic. Its job is pure table marshalling: it copies entries out of two "feature-list" structures (`r8`, `r9`) into two destination buffers (`rcx`/`rdi` and `rdx`/`rsi`) as `{u32 index, u64 payload}` records, stores the two counts at offset `+0xfa0` of each destination, and finally seeds two sparse byte-keyed lookup tables from a pair of parallel byte arrays (`[rsp+0x30]`, `[rsp+0x38]`) of length `[rsp+0x28]`.

It is best understood as the *setup* step that precedes the real geometric transform/voting work done elsewhere — it lays out the correspondence/feature index tables the matcher will later read.

## Signature

```c
// All pointers; "list" structs have layout { void* data @ +0x00; ... ; int32 count @ +0x08; }
// where `data` points to an array of 0x20-byte records, and each record holds a u64 at +0x14.
void sub_180003d30(
    void*       dstA,        // rcx  -> destination A (also holds a 0x10-stride record table at +0, count at +0xfa0,
                             //         and a byte-keyed sparse map whose slots are at dstA + key*16 (+0 and +4))
    void*       dstB,        // rdx  -> destination B (record table at +8 stride 0x10, count at +0xfa0,
                             //         byte-keyed sparse map slots at dstB + key*16 (+0))
    list_t*     srcA,        // r8   -> source list A: srcA->data @ [r8+0x00], srcA->count @ [r8+0x08]
    list_t*     srcB,        // r9   -> source list B: srcB->data @ [r9+0x00], srcB->count @ [r9+0x08]
    int32_t     pairCount,   // [rsp+0x28] -> number of (keyA,keyB) byte pairs to seed (signed, movsxd)
    uint8_t*    keysA,        // [rsp+0x30] -> byte array of A-keys, length pairCount
    uint8_t*    keysB         // [rsp+0x38] -> byte array of B-keys, length pairCount (read via base offset r9 = keysB - keysA)
);
```

Notes / guesses:
- The "list_t" layout (`data @ +0`, `count @ +8`, record stride `0x20`, payload `u64 @ +0x14`) is inferred from the access pattern and is *solid* from the disasm.
- The destination layout (record table stride `0x10` of `{u32, u64}`, count at `+0xfa0`, and the `key*16`-indexed slots) is *solid*; the **semantic** meaning of those fields (e.g. "feature index → original-keypoint payload" and "byte key → 0xFF sentinel") is *inferred*.
- `0xfa0 = 4000` — a fixed field offset inside both destination structures (a fairly large struct; the `key*16` slots also live in the same buffers, so these are big fixed-size arrays, see open questions).

## Pseudocode

```c
void sub_180003d30(void *dstA /*rdi*/, void *dstB /*rsi*/, list_t *srcA /*r8*/,
                   list_t *srcB /*r9*/, /*stack:*/ int pairCount, u8 *keysA, u8 *keysB)
{
    // ---- prologue: save callee-saved regs ----                       // 0x180003d30..0x180003d3a
    //   [rsp+0x8]=rbx, [rsp+0x10]=rsi, [rsp+0x18]=rdi  (home-slot saves)

    int r10d = 0;                                                       // 0x180003d3f  xor r10d,r10d  (running index / loop counter, also constant 0)
    rsi = dstB;                                                         // 0x180003d42  mov rsi,rdx
    rdi = dstA;                                                         // 0x180003d45  mov rdi,rcx

    // =====================================================================
    // BLOCK 1: copy srcA records -> dstA record table (stride 0x10)
    // =====================================================================
    int ebx = r10d;                                                    // 0x180003d48  (ebx = 0, loop counter i)
    if ( srcA->count <= ebx ) goto L_storeCountA;                      // 0x180003d4b cmp [r8+0x8],ebx ; 0x180003d4f jle 0x180003d81

    rcx = 0;                  // byte offset into srcA->data            // 0x180003d51  mov rcx,r10  (=0)
    r11 = dstA;               // write cursor into dstA table           // 0x180003d54  mov r11,rdi
    // (0x180003d57/d5a/d5d are alignment NOPs)

  L_loopA: // 0x180003d60
    rax = srcA->data;                                                  // 0x180003d60  mov rax,[r8]   (reloaded each iter)
    ebx += 1;                 // i++                                    // 0x180003d63  add ebx,0x1
    r11 += 0x10;              // advance dst cursor by one 0x10 record  // 0x180003d66  add r11,0x10
    rdx = *(u64*)(rax + rcx + 0x14);  // srcA->data[ rcx ].field@0x14   // 0x180003d6a  mov rdx,[rax+rcx+0x14]
    *(u32*)(r11 - 0x10) = r10d;       // dst record .index = 0  (!)     // 0x180003d6f  mov [r11-0x10],r10d
    rcx += 0x20;              // advance src by one 0x20 record         // 0x180003d73  add rcx,0x20
    *(u64*)(r11 - 0x8)  = rdx;         // dst record .payload = u64     // 0x180003d77  mov [r11-0x8],rdx
    if ( ebx < srcA->count ) goto L_loopA;                             // 0x180003d7b cmp ebx,[r8+0x8] ; 0x180003d7f jl 0x180003d60

  L_storeCountA: // 0x180003d81
    *(u32*)(dstA + 0xfa0) = srcA->count;                              // 0x180003d81 mov eax,[r8+0x8] ; 0x180003d85 mov [rdi+0xfa0],eax

    // =====================================================================
    // BLOCK 2: copy srcB records -> dstB record table (slots at dstB+0x8, stride 0x10)
    //          r10d still == 0 here (used as loop counter j)
    // =====================================================================
    if ( srcB->count <= r10d ) goto L_storeCountB;                     // 0x180003d8b cmp [r9+0x8],r10d ; 0x180003d8f jle 0x180003dbe

    rdx = 0;                  // byte offset into srcB->data            // 0x180003d91  mov rdx,r10 (=0)
    r8  = dstB + 0x8;         // write cursor (note: +0x8 base!)        // 0x180003d94  lea r8,[rsi+0x8]
    // (0x180003d98/d9c alignment NOPs)

  L_loopB: // 0x180003da0
    rax = srcB->data;                                                  // 0x180003da0  mov rax,[r9]
    r10d += 1;                // j++                                    // 0x180003da3  add r10d,0x1
    r8 += 0x10;               // advance dst cursor                     // 0x180003da7  add r8,0x10
    rcx = *(u64*)(rax + rdx + 0x14);  // srcB->data[ rdx ].field@0x14   // 0x180003dab  mov rcx,[rax+rdx+0x14]
    rdx += 0x20;              // advance src record                     // 0x180003db0  add rdx,0x20
    *(u64*)(r8 - 0x10) = rcx;          // dst .payload (only payload!)  // 0x180003db4  mov [r8-0x10],rcx
    if ( r10d < srcB->count ) goto L_loopB;                            // 0x180003db8 cmp r10d,[r9+0x8] ; 0x180003dbc jl 0x180003da0

  L_storeCountB: // 0x180003dbe
    r8 = (int64_t)pairCount;            // movsxd (SIGNED) from stack   // 0x180003dbe movsxd r8,[rsp+0x28]
    eax = srcB->count;                                                 // 0x180003dc3  mov eax,[r9+0x8]
    test r8;                                                           // 0x180003dc7  test r8,r8
    *(u32*)(dstB + 0xfa0) = srcB->count;                              // 0x180003dca mov [rsi+0xfa0],eax
    if ( r8 <= 0 ) goto L_done;                                        // 0x180003dd0  jle 0x180003e18

    // =====================================================================
    // BLOCK 3: seed byte-keyed sparse maps from parallel key arrays
    // =====================================================================
    rdx = keysA;              // [rsp+0x30]                             // 0x180003dd2  mov rdx,[rsp+0x30]
    r9  = keysB;              // [rsp+0x38]                             // 0x180003dd7  mov r9,[rsp+0x38]
    r9  = keysB - keysA;     // so keysB[k] == *(r9 + (keysA+ k))       // 0x180003ddc  sub r9,rdx
    // (0x180003ddf nop)

  L_loopP: // 0x180003de0
    rax = (u64)(*(u8*)rdx);            // a = keysA[k]                  // 0x180003de0  movzx eax,[rdx]
    rdx += 1;                          // ++keysA ptr                   // 0x180003de3  add rdx,0x1
    rax = rax + rax;                   // a *= 2                        // 0x180003de7  add rax,rax
    *(u32*)(dstA + rax*8) = 0xff;      // dstA[ a*16 + 0 ] = 0xFF       // 0x180003dea  mov [rdi+rax*8],0xff
    rax = (u64)(*(u8*)(r9 + rdx - 1)); // b = keysB[k]  (==*(keysB+k))  // 0x180003df1  movzx eax,[r9+rdx-1]
    rax = rax + rax;                   // b *= 2                        // 0x180003df7  add rax,rax
    *(u32*)(dstB + rax*8) = 0xff;      // dstB[ b*16 + 0 ] = 0xFF       // 0x180003dfa  mov [rsi+rax*8],0xff
    eax = (u32)(*(u8*)(rdx - 1));      // a again (reload current a)    // 0x180003e01  movzx eax,[rdx-1]
    ecx = (u32)(*(u8*)(r9 + rdx - 1)); // b again                       // 0x180003e05  movzx ecx,[r9+rdx-1]
    rax = rax + rax;                   // a *= 2                        // 0x180003e0b  add rax,rax
    r8 -= 1;                            // --pairCount                  // 0x180003e0e  sub r8,0x1
    *(u32*)(dstA + rax*8 + 0x4) = ecx; // dstA[ a*16 + 4 ] = b          // 0x180003e12  mov [rdi+rax*8+0x4],ecx
    if ( r8 != 0 ) goto L_loopP;                                       // 0x180003e16  jne 0x180003de0

  L_done: // 0x180003e18
    rbx = [rsp+0x8]; rsi = [rsp+0x10]; rdi = [rsp+0x18];               // 0x180003e18..0x180003e22 restore
    return;                                                            // 0x180003e27  ret
}
```

### Index/addressing arithmetic (important, easy to mis-port)

- In Block 1 the destination record is **16 bytes** (`r11 += 0x10`), laid out as `{ u32 index @ +0; (pad) ; u64 payload @ +0x8 }` (the `mov [r11-0x10]` writes the u32 at the record start; `mov [r11-0x8]` writes the u64 at +8). The written `index` is `r10d`, which is **always 0** in this function (r10d is never incremented before Block 1). So every dstA record gets `index = 0` and `payload = srcA->data[i].u64@0x14`. (This looks like a slot that is *meant* to be filled by a counter but in this build is hard-zero — see open questions.)
- In Block 2 the destination cursor starts at `dstB + 0x8` and stride `0x10`, and only the `u64` payload is written (`[r8-0x10]`), i.e. `payload @ dstB + 0x8 + i*0x10`. No index field is written in this loop.
- In Block 3 the map index is `key*16`: `rax = key; rax += rax (=> 2*key); addr = base + rax*8 (=> base + key*16)`. Two `u32` lanes per 16-byte slot are touched: lane0 (`+0`) gets `0xFF`, lane1 (`+4`) gets the *other* key. So:
  - `dstA[keyA*16 + 0] = 0xFF`, `dstA[keyA*16 + 4] = keyB`
  - `dstB[keyB*16 + 0] = 0xFF`
  This builds A→B correspondence: for matched pair k, the A-side slot indexed by `keyA` records the partner `keyB` (and a `0xFF` "present" flag), while the B-side slot indexed by `keyB` just gets the `0xFF` "present" flag.

## Callees

None — this is a leaf function (callgraph `"callees": []`). All control flow is internal jumps:
- `0x180003d81` — store-count-A / skip empty A loop
- `0x180003dbe` — store-count-B / skip empty B loop
- `0x180003e18` — epilogue / skip empty pair loop
- `0x180003d60`, `0x180003da0`, `0x180003de0` — the three internal loop heads

## GDB verification hooks

To verify a Python re-implementation produces identical tables, set breakpoints and dump as follows.

1. **Entry — capture all inputs** — `break *0x180003d30`
   - `$rcx` = dstA, `$rdx` = dstB, `$r8` = srcA, `$r9` = srcB.
   - `x/2gx $r8` then `x/wx $r8+8` → srcA.data ptr and srcA.count.
   - `x/2gx $r9` then `x/wx $r9+8` → srcB.data ptr and srcB.count.
   - Stack args: `x/wx $rsp+0x28` (pairCount), `x/2gx $rsp+0x30` (keysA, keysB pointers).
   - Dump the source payloads to compare copies: `set $d=*(long*)$r8`, then `x/<count>gx $d+0x14` is wrong stride — use a loop dumping `*(unsigned long*)($d + i*0x20 + 0x14)` for i in [0,count).

2. **After Block 1 (dstA record table + countA)** — `break *0x180003d8b`
   - dstA record table: for i in [0,srcA.count): `*(unsigned*)($rdi + i*0x10)` (index, expect 0), `*(unsigned long*)($rdi + i*0x10 + 8)` (payload).
   - `x/wx $rdi+0xfa0` → should equal srcA.count.

3. **After Block 2 (dstB record table + countB)** — `break *0x180003dbe`
   - dstB record table: for i in [0,srcB.count): `*(unsigned long*)($rsi + 0x8 + i*0x10)` (payload).
   - `x/wx $rsi+0xfa0` → should equal srcB.count.
   - `$r8` here (after the `movsxd`) = pairCount.

4. **Inside the pair loop — per-pair writes** — `break *0x180003e12` (the dstA partner write) and `break *0x180003dea` / `*0x180003dfa` (the 0xFF flag writes)
   - At `0x180003e12`: `$rax/2` = `keyA` of current pair (since `rax = 2*keyA`); `$ecx` = `keyB`. The write target is `$rdi + $rax*8 + 4`. Log `(keyA, keyB)` each hit to reconstruct the full correspondence list.
   - At `0x180003dea`: target `$rdi + $rax*8`, value `0xff`, `$rax/2 = keyA`.
   - At `0x180003dfa`: target `$rsi + $rax*8`, value `0xff`, `$rax/2 = keyB`.

5. **Exit — final maps** — `break *0x180003e18`
   - Walk both sparse maps over the set of seen keys: `*(unsigned*)($rdi + keyA*16)` (=0xFF), `*(unsigned*)($rdi + keyA*16 + 4)` (=partner keyB), `*(unsigned*)($rsi + keyB*16)` (=0xFF).
   - These three sets fully define the function's output; compare them byte-for-byte against the Python port.

Recommended priority: hooks **4** and **5** (they capture the actual correspondence content), then **2/3** for the bulk record copies.

## Confidence & open questions

**Solid (directly from disasm):**
- Control flow, the three loops, loop bounds (`< count`, `pairCount` down-counter), and the epilogue.
- Source-record stride `0x20`, payload at `+0x14`, dest stride `0x10`, count at `+0xfa0`.
- `movsxd` ⇒ `pairCount` is **signed** and the loop is skipped when `<= 0`.
- The `key*16` slot addressing and the `0xFF` + partner-key writes.
- This function contains **no** rigid-transform / Q16 / trig / sort / RANSAC math.

**Inferred / guesses:**
- Field *names*/semantics ("payload", "index", "partner", "present flag"). The copied `u64@0x14` is some per-feature handle/ID; its exact meaning lives in the producer of srcA/srcB.
- The dstA record `.index` being written as literal `0` (r10d, never bumped before Block 1) is **suspicious**: typically you'd expect the loop counter. Possibility: (a) the field really is always 0 here and is populated later; (b) it's a pre-clear of a small field while the real index is the implicit array position. Worth confirming with hook 2 — if all indices are 0, semantics (a) holds.
- `0xfa0 = 4000` placement implies both destination buffers are large fixed structs. Given the `key*16` slots must not collide with the `+0xfa0` count field, the max byte key is bounded: `key*16 + 4 < 0xfa0` ⇒ `key <= 0xf9` (249). Keys appear to be small feature indices (consistent with the ~250 keypoint cap noted elsewhere in this project). Confirm the buffer size / key range from the caller.
- Whether `dstA` and `dstB` point into the same enrollment structure at different offsets, or two separate structures — not determinable from this function alone; the caller decides.

**Open question for the transform work:** this function only *prepares* the index/correspondence tables. The actual similarity-transform (R=[[a,-b],[b,a]], t) fitting/voting that lands in `sec0_pre` must be in a consumer of these tables (the `key*16` map is the natural input to a correspondence-driven transform estimator). Trace the caller and whichever function reads `[dst + key*16 + 4]`.
