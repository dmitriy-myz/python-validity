# sub_180004010 — angle-fold accumulator (sum / weighted-sum / count)

Leaf function (no callees). 68 bytes, 20 instructions, single basic block, no
branches except an internal `cmovl`. It takes a small unsigned "angle-like" byte
input, folds it into the range [0,45] via `min(v, 90-v)`, and accumulates three
running totals through three output pointers: a raw sum, a weighted/scaled sum,
and a hit counter. This is **not** a matrix/affine transform; it is a
histogram-style accumulator that almost certainly feeds an orientation /
angular-difference statistic used while scoring frame alignments. The number 90
(degrees) and the fold `min(v,90-v)` strongly suggest the input is an angle
difference in degrees that is symmetric about 45°.

## Signature

```c
// Best-effort inferred signature. arg0..arg2 are int* accumulators that are
// READ-MODIFY-WRITTEN in place. arg3 is the angle byte. arg4 (5th, on stack)
// is a per-call weight byte.
void sub_180004010(
    int   *sum_out,      // rcx (arg0): *sum_out      += clamped          (raw folded-angle sum)
    int   *wsum_out,     // rdx (arg1): *wsum_out     += quotient*weight  (weighted/scaled sum)
    int   *count_out,    // r8  (arg2): *count_out    += 1                 (number of samples)
    uint8_t angle,       // r9b (arg3, low byte only): angle in degrees, treated mod-ish into [0,45]
    uint8_t weight       // [rsp+0x28] (arg4, low byte only): scale/weight multiplier
);
```

Notes / guesses:
- Only the **low byte** of `r9` is used (`movzx eax,r9b`), and only the **low
  byte** of the stack arg is used (`movzx eax,BYTE PTR [rsp+0x28]`). The other
  bytes are ignored — caller may pass full ints, fine.
- `rdx` is copied to `r10` immediately and `rdx`/`edx` is then reused as a scratch
  register for the division; the *pointer* for the weighted sum is `r10` (the
  original `rdx`). So arg1 is the weighted-sum pointer.
- Return value (`eax`) is whatever the last `lea`/`shr` left there — the function
  is `void`-like; `eax` is not meaningfully a result.

## Pseudocode

```c
void sub_180004010(int *sum_out /*rcx*/, int *wsum_out /*rdx*/,
                   int *count_out /*r8*/, uint8_t angle /*r9b*/,
                   uint8_t weight /*[rsp+0x28]*/)
{
    uint32_t v = (uint8_t)angle;                 // 0x180004010  movzx eax,r9b   (zero-extended low byte)
    int *wsum_out = (int*)rdx;                    // 0x180004014  mov r10,rdx     (save arg1 ptr in r10)

    // ---- fold the angle into [0,45]: clamped = min(v, 90 - v) ----
    int32_t comp = 0x5a - (int32_t)v;             // 0x180004017  mov r9d,0x5a (=90)
                                                  // 0x18000401d  sub r9d,eax   -> 90 - v
    // cmp v, (90-v) ; if (v < 90-v) clamped = v else clamped = 90-v
    int32_t clamped;                              // 0x180004020  cmp eax,r9d
    if ((int32_t)v < comp) clamped = (int32_t)v;  // 0x180004023  cmovl r9d,eax
    else                   clamped = comp;        //   => r9d = min(v, 90 - v)

    // eax = signed-division magic for /45 (used below)
    // 0x180004027  mov eax,0xb60b60b7

    // ---- accumulator #1: raw folded-angle sum ----
    *sum_out += clamped;                          // 0x18000402c  add DWORD PTR [rcx],r9d

    // ---- compute quotient = trunc((clamped*100)/45)  ( == trunc(clamped*20/9) ) ----
    int32_t num = clamped * 100;                  // 0x18000402f  imul r9d,r9d,0x64   (*100)
    // 64-bit signed multiply by magic; high 32 bits -> edx
    int64_t prod = (int64_t)(int32_t)0xb60b60b7 * (int64_t)num;  // 0x180004033 imul r9d (edx:eax = eax*r9d)
    int32_t hi   = (int32_t)(prod >> 32);         //   edx = high word of signed product
    hi += num;                                    // 0x180004036  add edx,r9d
    hi >>= 5;                                      // 0x180004039  sar edx,0x5        (arithmetic, ÷32)
    int32_t signbit = (uint32_t)hi >> 31;          // 0x18000403c  mov eax,edx
                                                  // 0x18000403e  shr eax,0x1f
    int32_t quotient = hi + signbit + 100;         // 0x180004041  lea ecx,[rdx+rax*1+0x64]
        // == trunc((clamped*100)/45) + 100        //   (the +100 / 0x64 is a bias added to the quotient)

    // ---- accumulator #2: weighted/scaled sum ----
    uint32_t w = (uint8_t)weight;                 // 0x180004045  movzx eax,BYTE PTR [rsp+0x28]
    int32_t contrib = quotient * (int32_t)w;       // 0x18000404a  imul ecx,eax
    *wsum_out += contrib;                          // 0x18000404d  add DWORD PTR [r10],ecx   (r10 = arg1)

    // ---- accumulator #3: sample counter ----
    *count_out += 1;                              // 0x180004050  add DWORD PTR [r8],0x1
    return;                                        // 0x180004054  ret
}
```

### Exact closed form (verified numerically)

The magic-multiply idiom `(int32) imul 0xB60B60B7 ; +num ; sar 5 ; +signbit`
implements **signed truncating division by 45** (verified exact over the full
range [-5000, 5000] against `trunc(x/45)`). With `num = clamped*100`:

```
quotient = trunc((clamped * 100) / 45) + 100
         = trunc(clamped * 20 / 9)     + 100      // 100/45 == 20/9
```

So the net effect of one call is:

```
clamped     = min(angle&0xFF, 90 - (angle&0xFF))
*sum_out   += clamped
*wsum_out  += ( trunc(clamped*20/9) + 100 ) * (weight&0xFF)
*count_out += 1
```

The `+100` bias means even a `clamped==0` sample contributes `100*weight` to the
weighted sum — i.e. the weighted sum is `100*weight` per sample minus an
angle-dependent reduction is **wrong**: it is `(≈2.22*clamped + 100)*weight`, an
*increasing* function of the folded angle. Treat the constants as opaque tuning
values when porting; just reproduce the formula exactly.

| Constant | Hex | Role |
|---|---|---|
| 90 | `0x5a` | full-scale angle; fold pivot for `min(v, 90-v)` (degrees, symmetric about 45) |
| 100 | `0x64` | numerator multiplier (`clamped*100`) **and** an additive `+100` bias on the quotient (`lea ...+0x64`) |

| 5 | `0x5` | `sar` shift count for the magic division (÷32 part of the /45) |

The only "fixed-point-ish" element is the magic-constant integer division.

def sub_180004010(sum_out, wsum_out, count_out, angle, weight):
    v = angle & 0xFF
    clamped = min(v, 90 - v)
    sum_out[0]   += clamped
    quotient      = (clamped * 100) // 45 + 100   # // is floor; clamped>=0 so == trunc

## Confidence & open questions

**Solid (high confidence):**
- Single basic block, no real control flow; the disasm is fully and
  unambiguously decoded.
- `clamped = min(angle&0xFF, 90 - angle&0xFF)` — direct `cmovl` reading.
- The three accumulator writes (`+= clamped`, `+= quotient*weight`, `+= 1`) and
  which pointer each uses (`rcx`, the saved `rdx`→`r10`, `r8`).
- `quotient = trunc((clamped*100)/45) + 100` — the `0xB60B60B7 / sar 5` idiom was
  numerically verified to be exact signed `÷45` over [-5000,5000]; `100/45 == 20/9`.
- Only the low byte of arg3 and of `[rsp+0x28]` is consumed.

**Inferred / open:**
- Semantic names (`angle`, `weight`, `sum/wsum/count`) are interpretation. The
  `0x5a`(90) fold pivot is the strongest evidence this is an angle in degrees
  (orientation difference), but the units are not proven from this function alone.
- Why the `+100` quotient bias and the `*100`/`/45` (=`*20/9`) scaling: these are
  tuning constants for whatever score this feeds; their meaning must come from
  the caller. Identify the caller (whoever passes these 5 args / reads the three
  accumulators afterward) to recover the statistic's purpose.
- This is **not** part of the rigid Q16 transform fit itself; if it touches
  sec0_pre at all, it would be via an orientation-consistency score computed over
  matched points, not via the R/t matrix arithmetic. Confidence it is transform
  *math* proper: low. Confidence it is an angular-difference accumulator: high.
