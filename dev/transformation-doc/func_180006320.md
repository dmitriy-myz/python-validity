# sub_180006320 — load one frame's geometry record from two TLV sections of a serialized blob

This is a small **wrapper / section-loader**, *not* transform math. Given a serialized
container object (the WS / `sec0_pre`-style blob, accessed as a cursor-based reader) and a
*base section index* `section_base` (passed in `edx`), it does three things:

1. `sub_180005c60(stream, &dstA=r8+0, &dstB=r8+4)` — looks up the **fixed tag `0x69`**
   inside the *sub-section* `section_base` and, if present, reads two consecutive 4-byte
   fields out of it into the two halves of `r8` (the caller's frame struct `r8` / `r8+4`).
   This is the "header / 2 scalar fields" of the frame record.
2. `sub_180006890(stream, tag = section_base + 4, &subreader=[rsp+0x20])` — locates the TLV
   sub-section whose 16-bit tag equals `section_base + 4`, returning a `{base, end, cursor}`
   cursor triple in a local stack slot and a found/not-found flag in `eax`.
3. If found (`eax != 0`), `sub_180005930(&subreader, dst = r8 /*rsi*/)` — runs the per-frame
   keypoint/geometry **record deserializer** (already documented in `func_180005930.md`),
   filling the caller's record struct (`r8`).

So the net effect is: *"populate the frame-geometry struct `r8` from the serialized blob:
first its two scalar header fields (tag 0x69), then its keypoint/geometry body (tag
`section_base+4`)."* The `edx`/`section_base` argument selects **which frame's** section to
pull (each captured frame occupies its own tag block, with the tag = base + 4).

No fixed-point, no trig, no matrix ops here — it is pure container navigation and
delegation. The actual geometry numbers come out of `sub_180005930`.

## Pseudocode

```c
void sub_180006320(StreamReader *rcx, uint32_t edx, void *r8)
{
    // ---- prologue ----                                  // 0x180006320
    // save rbx@[rsp+8], rsi@[rsp+10], push rdi; sub rsp,0x40
    uint32_t section_base = edx;          // ebx = edx     // 0x18000632f  (ebx holds section_base)
    StreamReader *stream  = rcx;          // rdi = rcx     // 0x180006338
    void         *dst     = r8;           // rsi = r8      // 0x180006335

    // ---- step 1: read the 2 scalar header fields (tag 0x69) ----
    // rdx = &dst[+4]  (lea rdx,[r8+4]) -> 2nd 4-byte field slot   // 0x180006331
    //   call sub_180005c60(rcx=stream, rdx=&dst[4], r8=dst)       // 0x18000633b
    //   (sub_180005c60 finds tag 0x69; if present, reads field#0 into dst,
    //    field#1 into dst+4, each via a 4-byte reader that advances the cursor)
    sub_180005c60(stream, /*&dstB*/ (uint8_t*)dst + 4, /*&dstA*/ dst);   // 0x18000633b

    // ---- step 2: locate the body sub-section (tag = section_base + 4) ----
    SubReader sub;                                          // local @ [rsp+0x20]
    // edx = section_base + 4 (lea edx,[rbx+4])              // 0x180006340
    // r8  = &sub  (lea r8,[rsp+0x20])                       // 0x180006343
    // rcx = stream (mov rcx,rdi)                            // 0x180006348
    int found = sub_180006890(stream, section_base + 4, &sub);  // 0x18000634b

    // ---- step 3: if found, deserialize the geometry body into dst ----
    if (found == 0)                       // test eax,eax / je 0x180006361   // 0x180006350,0x180006352
        goto done;
    // rcx = &sub ; rdx = dst (rsi)                          // 0x180006354,0x180006359
    sub_180005930(&sub, dst);             // call            // 0x18000635c

done:
    // ---- epilogue ----                                   // 0x180006361
    // restore rbx@[rsp+0x50], rsi@[rsp+0x58]; add rsp,0x40; pop rdi
    return;                               // ret             // 0x180006370
}
```

### What the helpers do (decoded from their disasm, for the porter)

`sub_180006890(rcx=stream, edx=tag, r8=&out_subreader) -> int found` — TLV section finder:
```c
int sub_180006890(StreamReader *stream, uint32_t tag, SubReader *out) {
    Header *h = *(Header**)stream;            // mov rax,[rcx]          // 0x180006894
    if (*(uint32_t*)((char*)h + 4) == 0)      // cmp [rax+4],0 ; ja     // 0x18000689a
        return 0;                             // empty -> not found
    void *table = *(void**)((char*)stream+8); // mov rdx,[rcx+8]        // 0x1800068a7
    SubReader tmp;
    sub_180006680(&tmp, table);               // wrap table into {base, base+4, 0}   // 0x1800068b0
    SubReader cursor = tmp;                    // copy 0x18 bytes
    return sub_180006800(&cursor, tag, out);  // linear search for tag  // 0x1800068d8
}
```
`sub_180006800(rcx=cursor, edx=tag, r8=&out) -> int` — recursive linear scan over the section
list: compares `WORD PTR [section]` (the 16-bit section tag) to `tag`; on match copies the
section's `{base,end,0}` into `out` and returns 1; if the section's tag is the sentinel `1`,
returns 0 (not found); otherwise advances to the next section (`sub_1800067a0`) and recurses.

`sub_180005c60(rcx=stream, rdx=dstB, r8=dstA)` — same pattern but with **fixed tag `0x69`**;
if found, calls `sub_1800065b0` twice to read two consecutive 4-byte little-endian values
from the section into `dstA` then `dstB`. `sub_1800065b0` reads 4 bytes at
`[section.base + section.cursor]` (via `sub_1800031e0`, a bounded 4-byte LE reader) and then
does `section.cursor += 4`.

No `>>16`, no `*0x10000`, no `0x8000` rounding, no trig — this function contains **no
fixed-point or transform arithmetic**. The only arithmetic is the two `+4` offsets above.

## Callees

- `0x180005c60` — read the 2-scalar header section (tag `0x69`) into `dst` and `dst+4`; uses `sub_1800065b0` (4-byte LE reader, cursor+=4) — see `func_180005c60.md` (to write) / disasm `/tmp/func_180005c60.S`.
- `0x180006890` — TLV **section finder**: given `tag = section_base+4`, populate a `{base,end,cursor}` `SubReader` and return found/not-found; delegates to `sub_180006680` (wrap) + `sub_180006800` (recursive linear tag scan). Disasm `/tmp/func_180006890.S`.
- `0x180005930` — **per-frame keypoint/geometry record deserializer** (the body). Documented in `func_180005930.md`.

## GDB verification hooks

This function has no transform math to validate, but it is the **entry point that fills a
frame's geometry struct**, so hooking it lets you snapshot the inputs/outputs that feed the
real transform code. Set breakpoints (process is under Wine + gdb per memory note "Dynamic
capture = gdb only"):

- `break *0x180006320` (entry):
  - `rcx` = `StreamReader*` (dump `*(void**)$rcx` and `*(uint32_t*)(*(void**)$rcx + 4)` = section count).
  - `edx` = `section_base` (the per-frame selector — log it to correlate which frame is loaded).
  - `r8`  = `dst` record pointer (record the address; you'll re-read it at exit).
- `break *0x180006340` (just before the body lookup): confirm the computed tag.
  - dump `$rbx + 4` (== `section_base + 4`) — this is the 16-bit tag passed to `sub_180006890`.
- `break *0x180006350` (after `sub_180006890`): `eax` = found flag (0 = body section absent, skip).
  - also dump the 0x18 bytes at `$rsp+0x20` = the `SubReader {base, end, cursor}` that step 3 will read.
- `break *0x18000635c` (just before the body deserialize): `rcx`=`&SubReader`, `rdx`=`dst`.
  - dump `*(void**)($rsp+0x20)` (section base) and `*(uint8_t**)($rsp+0x28)` (end) to know the
    byte range `sub_180005930` parses.
- `break *0x180006361` / `*0x180006370` (exit): dump the populated `dst` record (`r8` captured
  at entry) — at minimum the two header u32s at `dst+0x0` and `dst+0x4`, plus the keypoint
  count / vector pointer that `sub_180005930` wrote (see `func_180005930.md` for the layout).
  Compare these bytes against your Python re-implementation's loaded record.

To validate a Python port: drive the same serialized blob and same `section_base`, and assert
that (a) the found flag matches, (b) `dst[0]`/`dst[4]` match the two header scalars, and
(c) the full `dst` record after step 3 is byte-identical to the gdb snapshot at exit.

## Confidence & open questions

**Solid (directly from disasm):**
- Control flow, the three calls, and their argument wiring (`rcx/rdx/r8`) are unambiguous.
- The body-section tag is `section_base + 4` (`lea edx,[rbx+4]`, with `ebx=edx` from entry).
- Step 1 writes the header scalars to `dst` and `dst+4`; step 3 is conditional on the
  finder's `eax`.
- `0x69` is the fixed tag used by `sub_180005c60` (read directly from its disasm).
- No fixed-point / transform arithmetic is present in this frame.

**Inferred (best-effort, marked as guesses):**
- The *semantic* meaning of `edx` as a "per-frame section base index" — the disasm only shows
  it is an integer used as `tag = edx+4`. The "per-frame" interpretation comes from the
  surrounding sec0_pre/WS context, not this function alone.
- Whether `dst+0x0`/`dst+0x4` are e.g. a frame id + flag, a `(width,height)` pair, or a count
  pair — this function just stores two opaque u32s; their meaning lives in tag-`0x69`'s
  producer (`serialize_v30`/`sub_1800051f0` family).

**Open questions:**
- The exact field semantics of the two `0x69` scalars (header) — resolve by decoding the
  writer side or by the gdb exit-dump above.
- Confirm the section-table element layout (16-bit tag at offset 0, payload {base,end}) by
  cross-checking `sub_1800067a0` (the "next section" advancer used by `sub_180006800`).
