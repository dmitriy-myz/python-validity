# sub_1800041d0 — transform-and-sample correspondence builder (per-keypoint reproject + bounds-test + descriptor/orientation compare)

## Signature

This routine walks every keypoint of one captured frame, applies a **Q16 rigid/similarity
transform** (computed elsewhere, passed in `xform`) to map the keypoint's (x,y) into a
*reference* coordinate grid, looks up the per-pixel cell value in a 2-D label map, and — if
the mapped point is in-bounds and the cell is "occupied" (value < 0xFF) — records a
correspondence: it computes a **128-bit descriptor Hamming-style distance** (`sub_1800034e0`)
and an **orientation difference in degrees mod 180** (`sub_180003490`), appending both plus
the matched cell-id into output arrays. Out-of-bounds / empty / collision cases bump reject
counters.

All arguments past the 4th come on the stack (Win64). Reconstructed prototype (field names
are inferred; offsets are exact):

Notes on the stack-arg numbering: at entry the prologue pushes 4 regs then `sub rsp,0x68`.
Combined with the 0x20 shadow space and return address, the first stack argument
(`out_total`) sits at `[rsp+0xb0]` *after* the prologue, matching the loads. The four
register args are spilled to home slots `[rsp+0x8..0x20]` but only `rcx`/`rdx`/`r8`/`r9` homes
are written and never read back as their original values — so the four register parameters are
effectively unused by this function (it operates purely on the stack arguments). `out_total`
(`a5`) is zeroed and the `js` early-out paths jump past the body without touching it.

### Important correction / caveat on the two counters (r13 vs cntp)
- `out_count` (r13, `a6` `[rsp+0xb8]`) is zeroed at `0x18000420a` and incremented **only**
  in the `L_collision` empty-cell path at `0x18000439c` (`add DWORD[r13],1`).
- The **accept path** increments a *different* pointer: `r11 = *(int32_t**)(rsp+0xb0)`
  (loaded at `0x180004338`), i.e. it dereferences the `a5` slot (`out_total`'s storage) as a
  **pointer**, then `++(*r11)` at `0x180004396`, and uses `*r11` to index all four output
  arrays. So the accepted-correspondence running index comes from `*(int32_t**)(rsp+0xb0)`,
  NOT from `out_total`/`out_count` directly. This means `a5` (`[rsp+0xb0]`) is actually a
  `int32_t **` (pointer to the write cursor), and the early `*out_total=0` at `0x180004208`
  zeroes the cursor *storage*, not a count. Treat `a5` as **`int32_t **write_cursor`** and
  `a6`/r13 as the **reject(empty-cell) counter**. (Marked medium confidence — see below.)

## Callees

- `0x180003150` — **atan2(x,y) → fixed-point angle** (calls `0x1800030a0` polynomial core).
  Returns angle where `0x3243f == 180°`, `0x6487e == 360°`. Used once to get the global frame
  orientation from `angle_xy = {Δx, Δy}`.
- `0x180006bc0` — **apply Q16 rigid/similarity transform to a point**: reads `xform[a,b,tx,ty]`
  (`[+0],[+4],[+8],[+0xc]`), computes `col = (a*x - b*y + tx + 0x8000)>>16`,
  `row = (b*x + a*y + ty + 0x8000)>>16` (rounded Q16 product). Writes results to the two out
  pointers (`[rsp+0xb8]`,`[rsp+0xd0]`). This is the core reprojection step.
- `0x1800034e0` — **bit-population / Hamming distance accumulator**: XORs paired dwords of two
  byte buffers and sums per-byte popcounts via the 256-entry table at `0x18011ebd0`; `r9d>>2`
  dword count. Here `count=0x10`, `start=0` → descriptor distance. Returns sum in eax.
- `0x180003490` — **circular orientation difference (mod 180°)**: `sub_180003490(refAngle,
  srcAngle, frameAngleDeg)` reduces `(srcAngle+frameAngleDeg)` mod 180 (`imul …,0xb4`, magic
  `0xb60b60b7` = /180), subtracts `refAngle`, takes `|·|`, then `min(d, 180-d)` → returns
  smallest circular angular distance in degrees.

## GDB verification hooks

Set these `break *0x...` points to dump the exact intermediates a Python port must match:

   `edx`(=Δy) — the inputs `angle_xy[0]`, `angle_xy[1]`.

4. **`break *0x18000429e`** (immediately after the transform call).
   Dump `DWORD [rsp+0xb8]` = `col` and `DWORD [rsp+0xd0]` = `row` — the reprojected integer

7. **`break *0x18000436a`** (after orientation-diff call).
   Dump `al` = orientation diff (deg, 0..90), and inputs `ecx`(refAngle), `edx`(srcAngle),

8. **`break *0x180004396`** (accept commit).
   Dump `DWORD [r11]` *before* the add = current write cursor; dump the 4 written array bases

9. **`break *0x18000439c`** (reject path) — dump `DWORD [r13]` = empty-cell counter.
10. **`break *0x1800043c1`** (exit) — dump final `*[r13]` and final `*(*[rsp+0xb0])` (accepted

## Confidence & open questions

**Solid:**
- Loop structure, bounds tests, kp stride 0x20, the `+0x14/+0x18` (x,y) and `+0xc`
  (orientation) field offsets, and the 0xFF empty-cell sentinel.
- `sub_180006bc0` is a Q16 rigid/affine point transform with `+0x8000`/`>>16` rounding — this
  is the transform-application primitive central to sec0_pre registration.
- `sub_180003150` is atan2 to a fixed-point angular unit (`0x3243f`=180°), and the main
  function rescales it to integer degrees (0..179) via the `*0xb4` / magic-`0x517ccc83`-divide.
- `sub_180003490` returns a circular orientation difference mod 180°; `sub_1800034e0` is a
  table-driven popcount (descriptor Hamming distance over 16 dwords).

**Inferred / open:**
- **The two counters.** The accept path increments `*(int32_t**)(rsp+0xb0)` (a pointer it
  dereferences), while r13 (`[rsp+0xb8]`) is incremented only on empty-cell. I read `a5`
  (`[rsp+0xb0]`) as `int32_t **write_cursor` and `a6` as the reject counter. Worth confirming
  in gdb (hook 8 vs 9) which one tracks accepted matches. (Medium confidence.)
- **`xform_box` (`[rsp+0xc8]`) layout.** I infer `*xform_box` is the base of the *reference*
