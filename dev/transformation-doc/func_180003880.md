# sub_180003880 — keypoint partitioning + dual descriptor-correspondence builder

This function does **not** itself compute a rigid transform. It is the *correspondence
front-end* that feeds the transform/Hough stage: it splits the two input keypoint lists
into "edge/near-boundary" vs "interior" partitions (by index relative to a per-list count
field at `[list+0xc]`), then runs the descriptor matcher (`sub_180003640`) **twice** to
produce a set of point-to-point correspondences (each a 0x1c-byte record holding both
endpoints' coords + a Hamming score). Those correspondences are the input the downstream
similarity-transform / voting stage consumes (Q16 R/t fit lives further up the call chain
in `sub_1800046e0` → `sub_1800043d0`, which is the caller of this function).

The matcher it calls (`sub_180003640`) performs a nearest / second-nearest descriptor
search with **Lowe ratio test** (`*100 / (best+1) <= 0x70`), a **squared-pixel-distance
gate** (`dx²+dy² < 0x24`), and a **best-Hamming gate** (`best < 0x60`), via the popcount
Hamming kernel `sub_1800034e0` (256-entry popcount LUT at `0x18011ebd0`).

Notes on the calling convention inside the body: the function spills its register args to
the *shadow space* of its own frame at entry (`[rsp+0x8]=rcx`, `[rsp+0x10]=rdx`,
`[rsp+0x18]=rbx`) **before** `sub rsp,0x80`, so the "stack args" listed above are read at
the post-prologue offsets `[rsp+0xe0]`, `[rsp+0xe8]`, etc. The two `sub_180003640` calls
take a large arg block staged in `[rsp+0x20..0x38]` plus 4 register args.

                goto A_interior;                          // 0x1800038f7

            // A_edge: indices [0 .. cntField-1]
            uint8_t *base = *(uint8_t**)(rsp+0x40);        // 0x1800038f9  (== buf, A_edge lane)
            uint8_t  idx  = sil;        // cntA_edge        // 0x1800038fe
            sil = sil + 1;                                 // 0x180003902
            base[idx] = (uint8_t)edx;   // store kp index   // 0x180003906  mov [rcx+rax],dl

            edx += 1;                                       // 0x180003915

    // ============ PARTITION LIST B by index vs [listB+0xc] ============
    uint32_t nB    = *(uint32_t*)(rsp+0xe8);              // 0x18000391d  (stack arg)
    KpList  *listB = *(KpList**)(rsp+0xe0);   // r12      // 0x180003924
    uint32_t ecx = 0;                                     // 0x18000392c
    if (nB != 0) {                                        // 0x18000392e test edx(=nB)

            uint8_t cntFieldB = *(uint8_t*)(listB + 0xc); // 0x180003932
            if ((uint32_t)ecx >= cntFieldB)               // 0x180003938 cmp/jae
                goto B_interior;                          // 0x18000393a

            // B_edge
            { uint8_t idx = bpl; bpl = bpl + 1;            // 0x18000393c..0x180003940

    void    *src_descB  = *(void**)(rsp+0xc8);     // rsi        // 0x180003969

    //   [rsp+0x38]=cntB_edge, [rsp+0x30]=cntA_edge, [rsp+0x28]=r8p(B_edge lane),
    //   [rsp+0x20]=*[rsp+0x40](=buf, A_edge lane)
    stack[rsp+0x38] = cntB_edge;                          // 0x180003983
    stack[rsp+0x30] = cntA_edge;                          // 0x18000398c
    stack[rsp+0x28] = r8p;       // B_edge index lane     // 0x180003990
    r9  = listB;     // r12                                // 0x180003995
    rdx = src_descB; // rsi                                // 0x180003998
    r8  = listA;     // r13                                // 0x18000399b
    rcx = out_descB; // rbp                                // 0x18000399e
    stack[rsp+0x20] = *(void**)(rsp+0x40);  // A_edge lane (buf)  // 0x1800039a1
    sub_180003640(rcx, rdx, r8, r9, /*stack*/ A_edge_lane,

        uint32_t cntA_int = (uint32_t)bl;    // ecx                                       // 0x1800039b4
        r9  = listB;  // r12                                                              // 0x1800039b7
        stack[rsp+0x38] = cntB_int;                                                       // 0x1800039ba
        stack[rsp+0x30] = cntA_int;                                                       // 0x1800039be
        r8  = listA;  // r13                                                              // 0x1800039c2
        rcx = out_descB; // rbp                                                           // 0x1800039c5
        rdx = src_descB; // rsi                                                           // 0x1800039c8
        stack[rsp+0x28] = r15;   // B_interior lane                                       // 0x1800039cb
        stack[rsp+0x20] = r14;   // A_interior lane                                       // 0x1800039d0

    // ---- epilogue ----                                  // 0x1800039da..0x1800039f4
    rbx = *(void**)(rsp+0xd0);   // corr_out (returned-ish/restored)   // 0x1800039da
    // add rsp,0x80 ; pop r15,r14,r13,r12,rdi,rsi,rbp ; ret

}

### What `sub_180003640` (the matcher) computes — summary, not transcribed

For each query keypoint `i` in `[0, cntQuery)` (outer loop `L_36a0`, count at `[rsp+0xc0]`,
the lane pointer advances at `[rsp+0xb0]`):
* `r15 = queryDesc[ laneQuery[i] ]` (descriptor ptr; index from the partition lane,
  `<<5` so keypoint records are **0x20 bytes**).                         // 0x1800036a0..0x1800036bc
* `r12 = trainDescBase` (descriptor list B).                             // 0x1800036c0..0x1800036d1
* Inner loop over `cntTrain` (=`ecx`, `[rsp+0xc8]`): call
  `sub_1800034e0(r15, r12, len=0x10, 0)` → 16-byte descriptor **Hamming distance**;
  track `best=esi / bestIdx=r14` and `second=edi / secondIdx=r13`.        // 0x1800036e1..0x18000371c
* Ratio test: `edi = second*0x64; eax = edi / (best+1); if (eax > 0x70) reject`. // 0x180003735..0x180003766 (0x70 = 112 → keep if 100*second/(best+1) ≤ 112)
* Geometric gate: `dx = trainKp.x - bestKp.x` (field +0x14),
  `dy = trainKp.y - bestKp.y` (field +0x18); `if (dx*dx + dy*dy >= 0x24) reject`. // 0x180003748..0x180003777 (0x24 = 36 → radius 6 px)
* Best gate: `if (best >= 0x60) reject`.                                 // 0x18000377d..0x180003780 (0x60 = 96)
* Accept → append a **0x1c (28)-byte** correspondence record at index `*[rdx]` (count),
  storing: train coords qword @+0x0, train field-0xc qword @+0x10... and best-match
  endpoint coords/fields, plus `esi`(best Hamming) at +0x18.             // 0x180003786..0x1800037fd
* `*[rdx]++`; stop when count reaches 0x64 (=100).                       // 0x1800037fd..0x180003803

## Callees

- `0x180003320` — descriptor-slice / clip helper. Copies a 6-qword (0x30) struct from
  `rdx` to `rcx`, and if `[rdx+0x28]!=0 && r8d<=[rdx+0x18]` calls `sub_1800032c0` to compute
  an 8-aligned sub-range offset (stride/length math, not transform math). Returns `rcx`.
  (sub-callee `0x1800032c0` = aligned offset/length computation.)
- `0x180003640` — **descriptor correspondence matcher** (nearest / 2nd-nearest + Lowe ratio
  test + pixel-radius gate + Hamming gate); appends 0x1c-byte correspondence records.
  Sub-callee `0x1800034e0` = **16-byte descriptor Hamming-distance via 256-byte popcount LUT**.

## Confidence & open questions

**Solid (directly from disasm):**
- The two-way partition of each keypoint list by index vs the u8 field `[list+0xc]`, with
  four 250-byte lanes laid out at `buf + {0, 0xfa, 0x1f4, 0x2ee}`. (high)
- The two matcher invocations: edge-vs-edge first, interior-vs-interior second, the second
  gated on correspondence count `< 0x64`. (high)
- Matcher internals: 16-byte-descriptor Hamming via popcount LUT, nearest/second-nearest,
  Lowe ratio `100*2nd/(best+1) ≤ 0x70`, pixel gate `dx²+dy² < 0x24`, best gate `< 0x60`,
  0x1c-byte output records capped at 100. (high — `sub_180003640`/`sub_1800034e0` read in full)
- `0x18011ebd0` is a 256-entry popcount table. (high — classic byte-LUT popcount idiom)

**Inferred / uncertain:**
- Exact identity of `out_descA`(rcx) vs `out_descB`(rbp at `[rsp+0xc0]`) and `src_descB`
  (`[rsp+0xc8]`): I label them by how the matcher uses them (rcx=query-descriptor struct,
  rdx=train-descriptor struct, count lives at `src_descB[0]`). Field-level confirmation
  needs hook #4/#10. (medium)
- The role of `argF0`(`[rsp+0xf0]`) and the slicer `0x3e8` length: the slicer just produces
  the scratch `buf`; whether `argF0` is a descriptor pool or a fresh allocator wrapper is not
  certain from this function alone. (medium)
- The exact byte layout of the 0x1c correspondence record (which qword is A vs B endpoint).
  The disasm writes: `[+0x0]`=train kp+0x14 qword, `[+0x10]`=train kp+0xc dword,
  `[+0x8]`=match kp+0x14 qword, `[+0x14]`=match kp+0xc dword, `[+0x18]`=best Hamming.
  Endpoint A/B labeling is inferred; verify with hook #10. (medium)

**This is NOT transform math itself.** No Q16 fixed-point, no R/t, no atan2/sqrt here. It is
the *correspondence generator* feeding the similarity-transform / Hough stage. The actual
sec0_pre rigid-transform fit is in ancestors (`sub_1800043d0` / `sub_1800046e0`, per the call
graph), which consume the 0x1c-byte correspondence array this function fills.
