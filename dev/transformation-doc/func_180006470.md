# sub_180006470 — guarded TLV-section dispatcher: "if section (id+4) exists, run the per-frame serialize/load for `id`"

This is a tiny (94-byte, 29-instr) **wrapper / guard** function. It is **not** transform
arithmetic. It performs a *presence check* on a TLV-stream section (the WS / `sec0_pre`
container) and, only if that section is present, delegates the actual work to
`sub_180006320`. It returns a boolean success flag.

- It does a "probe" lookup for the 16-bit tag `(id + 4)` via `sub_180006890`.
- The lookup result struct is written to a local scratch buffer (`[rsp+0x20]`, 0x18 bytes)
  but is **discarded** — only the found/not-found `eax` flag is used.
- On hit, it calls `sub_180006320(container, id, ptr)` which does the real append +
  conditional deserialize, then returns `1`.
- On miss, it returns `0` and does nothing.

There is no fixed-point, no matrix/affine, no trig, no sort, no coordinate math in *this*
function. (The geometry/keypoint deserialization lives downstream in `sub_180005930`,
reached only via `sub_180006320`.)

## Signature

```c
// Best-effort. `container` is a TLV-stream/section object (the WS sec0_pre-style blob).
// `id` is a base section identifier; the probed tag is (id+4), and the worker section
// passed to sub_180006320 is `id` (which itself probes (id+4) again internally).
// `ptr` is an opaque pointer forwarded verbatim to the worker (in sub_180006320 it is the
// r8/source the appended words & deserialize are driven from).
//
// Returns 1 if the (id+4) section was present and the worker ran; 0 otherwise.

int sub_180006470(
    uint32_t id,         // rcx (ecx)  — base section id; tag probed = id+4   [GUESS: "section/frame id"]
    void    *container,  // rdx        — TLV-stream container object
    void    *ptr);       // r8         — opaque source/dest forwarded to the worker
```

Note the unusual register usage: the integer `id` arrives in **rcx** (1st arg) but the
**object pointer** arrives in **rdx** (2nd arg). So callers invoke this as
`sub_180006470(id, container, ptr)`, i.e. the scalar is first.

## Pseudocode

```c
int sub_180006470(uint32_t id /*ecx*/, void *container /*rdx*/, void *ptr /*r8*/)
{
    // ---- prologue ----                                  // 0x180006470
    //   save rbx,rsi to shadow space; push rdi; sub rsp,0x40
    //   [rsp+0x08]=rbx  [rsp+0x10]=rsi   (saved-reg homes)
    void  *out[3];               // local 0x18-byte iterator/view scratch @ [rsp+0x20]

    void    *_container = container;     // rbx = rdx       // 0x18000647f
    void    *_ptr       = ptr;           // rsi = r8        // 0x180006482

    uint32_t probe_tag  = id + 4;        // edx = ecx + 4   // 0x180006485  (lea edx,[rcx+0x4])
    uint32_t _id        = id;            // edi = ecx       // 0x180006488
    void   **out_p      = &out[0];       // r8 = &[rsp+0x20]// 0x18000648a
                                         // rcx = container // 0x18000648f

    // Probe: does the container hold a TLV entry whose 16-bit tag == (id+4)?
    // sub_180006890(container, probe_tag, &out) -> nonzero if found (out filled, then ignored).
    int found = sub_180006890(_container, probe_tag, out_p); // 0x180006492  call 0x180006890

    if (found == 0)                       // 0x180006497 test eax,eax
        goto L_miss;                      // 0x180006499 je 0x1800064bd

    // ---- hit path ----                                  // 0x18000649b
    // Run the real worker on section `id`. Arg order: rcx=container, edx=id, r8=ptr.
    //   (sub_180006320 will append two 4-byte words to the tag-0x69 field, re-probe
    //    tag (id+4), and on hit call the geometry deserializer sub_180005930.)
    sub_180006320(_container, _id, _ptr); // r8=rsi; edx=edi; rcx=rbx  // 0x18000649b..0x1800064a3
                                          //                            // call 0x180006320

    int ret = 1;                          // 0x1800064a8 mov eax,1
    // ---- epilogue (shared tail) ----
    //   rbx=[rsp+0x50]; rsi=[rsp+0x58]; add rsp,0x40; pop rdi; ret
    return ret;                           // 0x1800064ad .. 0x1800064bc

L_miss:                                   // 0x1800064bd
    //   rbx=[rsp+0x50]; rsi=[rsp+0x58]
    int ret0 = 0;                         // 0x1800064c7 xor eax,eax
    //   add rsp,0x40; pop rdi
    return ret0;                          // 0x1800064c9 .. 0x1800064ce
}
```

### Notes on the called probe `sub_180006890(container, tag, &out)`
(For context only — see `func_180006890.md` when written.) It:
- early-outs to `0` if `*(uint32*)(*(void**)container + 4) == 0` (empty container). // 0x18000689a
- otherwise builds a 0x18-byte iterator over `*(void**)(container+8)` via `sub_180006680`,
  copies it into a local, then calls `sub_180006800(it, tag, &out)` which walks the TLV
  stream comparing the **16-bit tag word** `*(uint16*)entry` against `tag`, returning 1 +
  filling `out` on the first match (recursion to advance through chained entries).

So `sub_180006470`'s guard is precisely: *"is there a TLV entry tagged `(id+4)` in the
container?"*

## Struct fields & constants

This function touches only stack/scratch and forwards object pointers; no
object-field offsets are dereferenced *inside* sub_180006470 itself.

| Access (in this fn)        | Meaning                                                              |
|----------------------------|---------------------------------------------------------------------|
| `[rsp+0x08]`, `[rsp+0x10]` | shadow-space homes for saved `rbx`, `rsi` (set at entry)            |
| `[rsp+0x20]` (`out[0..2]`) | 0x18-byte local iterator/view filled by `sub_180006890`, then **unused** |
| `[rsp+0x50]`, `[rsp+0x58]` | restore slots for `rbx`, `rsi` on exit (same homes after `sub rsp`) |
| `rcx`/`edi` = `id`         | base section id (1st arg, arrives in rcx)                           |
| `rdx`/`rbx` = `container`  | TLV-stream container object (2nd arg)                              |
| `r8`/`rsi`  = `ptr`        | opaque pointer forwarded to worker (3rd arg)                       |

Magic constants:

| Constant | Where                | Meaning                                                        |
|----------|----------------------|----------------------------------------------------------------|
| `0x4`    | `lea edx,[rcx+0x4]` @0x180006485 | probe-tag offset: the looked-up tag is `id + 4`. (matches `sub_180006320`'s own internal re-probe of `id+4`.) |
| `0x40`   | `sub rsp,0x40`       | local frame size                                               |
| `0x1`    | `mov eax,1` @0x1800064a8 | success return value                                       |
| `0x18`   | (size of `out`)      | iterator/view struct size copied by the probe (3×8 bytes)      |

No `>>16`, `*0x10000`, `0x8000`, `cdq`, `movsxd`, sqrt/atan2, or compare-sort opcodes
appear in this function.

## Callees

- `0x180006890` — TLV-section **presence probe**: returns nonzero if container holds an
  entry tagged `(id+4)`; fills a 0x18-byte iterator/view (discarded here). Internally uses
  `sub_180006680` (iterator init) and `sub_180006800` (recursive 16-bit-tag match). See
  `func_180006890.md` (to be written).
- `0x180006320` — the **worker** (called only on hit): appends two 4-byte words into the
  tag-`0x69` TLV field (`sub_180005c60`), re-probes tag `(id+4)` (`sub_180006890`), and on
  hit invokes the per-frame geometry/keypoint **deserializer** `sub_180005930`. See
  `func_180005c60.md`, `func_180005930.md`, and `func_180006320.md` (to be written).

## GDB verification hooks

The interesting values are the *inputs* and the *branch outcome*; this function computes no
intermediate transform values itself. Hooks to confirm a Python port behaves identically:

- `break *0x180006470` (entry) — dump args:
  - `rcx` (=`ecx`) = `id` (base section id)
  - `rdx` = `container` pointer
  - `r8`  = `ptr` (opaque forwarded pointer)
  - Also `*(uint32_t*)(*(void**)$rdx + 4)` = the container's element-count guard the probe
    will test (probe returns 0 immediately if this is 0).

- `break *0x180006492` (just before `call 0x180006890`) — confirm the probe args:
  - `edx` = `probe_tag` (must equal `id + 4`)
  - `rcx` = `container`
  - `r8`  = `&out` (`$rsp+0x20`)

- `break *0x180006497` (right after the probe returns) — branch decision:
  - `eax` = `found` (0 ⇒ takes the miss path / returns 0; nonzero ⇒ runs worker / returns 1)
  - Optionally dump the filled iterator at `$rsp+0x20` (3×8 bytes): `out[0]`=matched-entry
    ptr, `out[1]`=stream/cursor ptr, `out[2]` (low 4 bytes)=position/flag — to verify the
    probe found the entry your Python expects.

- `break *0x18000649b` (hit path, before `call 0x180006320`) — confirm worker args:
  - `rcx` = `container`, `edx` = `id`, `r8` = `ptr`.

- `break *0x1800064a8` — hit path taken; `eax` about to be set to 1.
- `break *0x1800064c7` — miss path taken; `eax` about to be xored to 0.

To verify end-to-end equivalence, record `(id, container, found, return)` tuples at
`0x180006470`/`0x180006497`/exit across an enrollment run and match them against the port.

## Confidence & open questions

**Solid (high confidence):**
- Control flow is unambiguous: probe → branch → (worker, return 1) | (return 0). The two
  exit blocks and the single `je` are the entire logic.
- The probed tag is exactly `id + 4` (`lea edx,[rcx+0x4]`), and `id` is forwarded *unmodified*
  to the worker (`edx=edi=ecx`).
- This function does **no** transform/geometry math (`is_transform_math = false`). Any
  Q16/affine/trig work happens strictly downstream, reachable only via `sub_180006320 →
  sub_180005930` and is not exercised on the miss path.
- Register-to-arg mapping (id in rcx, container in rdx, ptr in r8) follows directly from
  the x64 ABI and the saves.

**Inferred / lower confidence:**
- Semantic names: `id` ("section/frame id"), `container` ("TLV-stream/sec0_pre object"),
  `ptr` ("source/dest"). These come from the downstream callee docs (`sub_180005c60`
  tag-0x69 field writer, `sub_180005930` per-frame keypoint loader), not from this function.
- The `+4` between the probed tag and the worker id: `sub_180006320` *also* internally
  re-probes `(id+4)` and (on hit) deserializes. So `sub_180006470`'s probe and the worker's
  internal probe look at the *same* tag; this outer guard appears to be a redundant /
  fail-fast presence check before doing the append-and-load. Why the redundancy (caller
  contract vs. defensive double-check) is unresolved.
- Whether `id` is a literal section index or an enum is unknown from this function alone;
  the `(id+4)` suggests a small fixed tag-space offset rather than an arbitrary value.
