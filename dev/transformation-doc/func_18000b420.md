# sub_18000b420 — "is this Q16 rigid transform NON-identity?" predicate

A 34-byte leaf function (no callees). It tests the first four 32-bit words of a
structure against the identity-rotation pattern `{0x10000, 0, 0, 0}` and returns
a boolean:

- returns **0** when the four words are exactly `a=0x10000, b=0, c=0, d=0`
  (i.e. the canonical Q16 identity rotation R = [[1,0],[0,1]] with zero in the
  next two slots),
- returns **1** otherwise (any field differs → "non-identity / real transform").

In sec0_pre terms this is almost certainly the guard "does this frame carry an
actual rigid transform, or is it the identity (the reference/base frame)?".
`0x10000` = 65536 = 1.0 in Q16.16 fixed point, which is the classic value of
`a = cos(0)*65536` for an identity rotation; `b = sin(0)*65536 = 0`.

## Signature

```c
// rcx -> pointer to a 4-word (>=0x10 byte) struct, interpreted as int32[4].
// Layout matches the head of a Q16 rigid-similarity transform:
//   [+0x00] a   (= cos*65536, 0x10000 == 1.0 for identity)
//   [+0x04] b   (= sin*65536, 0 for identity)             [GUESS: could be a 2nd row term]
//   [+0x08] c   (0 for identity)                          [GUESS]
//   [+0x0c] d   (0 for identity)                          [GUESS]
// Returns 0 if the transform header is exactly identity {0x10000,0,0,0}, else 1.
int sub_18000b420(const int32_t *xform /*rcx*/);
```

Notes on the guessed meaning of fields:
- `+0x00` is compared against `0x10000` — strongly implies a Q16 scalar that is
  1.0 for identity, hence the rotation/scale term `a`.
- `+0x04, +0x08, +0x0c` are each compared against `0`. These are the remaining
  rotation entries (`b` and possibly two more matrix slots) which are all zero
  for the identity rotation. The function does **not** examine the translation
  `(tx,ty)` (would be at +0x10/+0x14), so "identity" here means *rotation/scale
  part is identity*, regardless of translation. This is a strong, useful detail
  for the port.

## Pseudocode

```c
int sub_18000b420(const int32_t *rcx)
{
    // --- entry / block L_b420 -------------------------------------------------
    if (*(int32_t *)(rcx + 0x00) != 0x10000)   // cmp [rcx],0x10000 ; jne   0x18000b420 / 0x18000b426
        goto L_b43d;                           //                                       0x18000b426

    if (*(int32_t *)(rcx + 0x04) != 0)         // cmp [rcx+0x4],0 ; jne                   0x18000b428 / 0x18000b42c
        goto L_b43d;                           //                                        0x18000b42c

    if (*(int32_t *)(rcx + 0x08) != 0)         // cmp [rcx+0x8],0 ; jne                   0x18000b42e / 0x18000b432
        goto L_b43d;                           //                                        0x18000b432

    if (*(int32_t *)(rcx + 0x0c) != 0)         // cmp [rcx+0xc],0 ; jne                   0x18000b434 / 0x18000b438
        goto L_b43d;                           //                                        0x18000b438

    // --- all four words matched identity -> return 0 -------------------------
    return 0;                                  // xor eax,eax ; ret                       0x18000b43a / 0x18000b43c

    // --- L_b43d: at least one word differed -> return 1 ----------------------
L_b43d:
    return 1;                                  // mov eax,1 ; ret                         0x18000b43d / 0x18000b442
}
```

Control-flow summary (every `jne` is "field mismatch → fall through to the
`return 1` tail at 0x18000b43d"; reaching 0x18000b43a means every field matched):

```
0x18000b420  cmp  [rcx+0x00], 0x10000
0x18000b426  jne  0x18000b43d
0x18000b428  cmp  [rcx+0x04], 0
0x18000b42c  jne  0x18000b43d
0x18000b42e  cmp  [rcx+0x08], 0
0x18000b432  jne  0x18000b43d
0x18000b434  cmp  [rcx+0x0c], 0
0x18000b438  jne  0x18000b43d
0x18000b43a  xor  eax, eax        ; eax = 0  (IS identity)
0x18000b43c  ret
0x18000b43d  mov  eax, 1          ; eax = 1  (NOT identity)
0x18000b442  ret
```

## Struct fields & constants

| Access (from rcx) | Width | Compared to | Inferred meaning |
|---|---|---|---|
| `[rcx+0x00]` | int32 | `0x10000` | Q16 term `a` (= cos*65536); 1.0 in Q16.16 for identity rotation |
| `[rcx+0x04]` | int32 | `0` | Q16 term `b` (= sin*65536); 0 for identity. *(field role GUESS)* |
| `[rcx+0x08]` | int32 | `0` | next rotation/matrix word; 0 for identity. *(GUESS)* |
| `[rcx+0x0c]` | int32 | `0` | next rotation/matrix word; 0 for identity. *(GUESS)* |

Magic constants:
- `0x10000` = 65536 = **1.0 in Q16.16 fixed point** — the only non-trivial
  constant; the identity value of the rotation/scale term `a`.
- `0` — identity value of the other three header words.
- return values `0` / `1` — boolean: `0 = is identity`, `1 = is non-identity`.

There is **no arithmetic** in this function: no shifts (`>>16`), no multiplies,
no rounding (`0x8000`), no trig, no sqrt, no sort/vote. It is purely four
integer equality comparisons against constants. The fixed-point relevance is
only that the compared constant `0x10000` is the Q16 representation of 1.0.

## GDB verification hooks

This function has no internal computation, so verification is about the
input/output contract:

- `break *0x18000b420` — at entry, dump the 4 words being tested:
  - `x/4dw $rcx` → the int32 quartet `[a, b, c, d]`. For the identity case this
    must read `65536  0  0  0`. (Also worth dumping `x/6dw $rcx` to see the
    following two words at +0x10/+0x14 = the translation `(tx,ty)`, which this
    function deliberately ignores — useful to confirm your port also ignores
    them.)
  - Record `$rcx` so you can correlate which sec0_pre transform row is being
    classified.

- `break *0x18000b43a` — the "IS identity" exit. Hitting this means all four
  words equalled `{0x10000,0,0,0}`. Confirm `$eax`/`$rax` is about to be set 0.

- `break *0x18000b43d` — the "NOT identity" exit. Hitting this means at least
  one word differed. `$eax` will be set to 1. (Set both 0x18000b43a and
  0x18000b43d breakpoints to see which path each call takes.)

- `break *0x18000b442` (and `*0x18000b43c`) — final `ret`s; read `$eax` for the
  returned boolean to cross-check against the Python re-implementation:
  `return 0 if (a==0x10000 and b==0 and c==0 and d==0) else 1`.

To validate a Python port produces identical results, log `(rcx, [a,b,c,d],
return_value)` at each call site and assert the boolean matches
`int(not (a==0x10000 and b==0 and c==0 and d==0))`.

## Confidence & open questions

**Solid (high confidence):**
- The exact control flow, addresses, compared constants, and the boolean
  return semantics (`0` for the `{0x10000,0,0,0}` match, `1` otherwise). The
  disassembly is unambiguous — four `cmp`/`jne` pairs and two `ret`s.
- It reads exactly 16 bytes (four int32) from `rcx` and nothing else; it does
  NOT touch the translation words.
- It performs no arithmetic/transform math itself.

**Inferred / open questions:**
- The semantic labelling of the four words as Q16 rotation terms `a,b,c,d`. The
  `0x10000` comparison makes `[+0x00]=a (cos*65536)` very likely, and `[+0x04]=b
  (sin*65536)` plausible, but `[+0x08]/[+0x0c]` being matrix slots vs. some
  other header field is a guess driven by the surrounding sec0_pre context, not
  proven by this function alone. Confirm by inspecting a caller (e.g. whoever
  passes `rcx` here) and matching the offsets to the known sec0_pre transform
  record layout (a, b, tx, ty …).
- Whether callers use the return to mean literally "skip / treat as base frame"
  when it returns 0. Likely, but determined by the caller, not here.
