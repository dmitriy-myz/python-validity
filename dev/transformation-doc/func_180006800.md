# sub_180006800 — recursive ordered-container lookup (NOT transform math)

This is a small **recursive container-lookup / tree-traversal** function. It walks a
linked structure of fixed-layout nodes, comparing a `u16` key (`edx`) against each
node's header word, and returns a 24-byte "found-element / iterator" triple
`{ptr, ptr, u32}`. It contains **no coordinate, fixed-point, matrix, trig, or
RANSAC math** — it is plumbing (an STL-like `find`/`lower_bound` or an intrusive
tree/skip-list descent) used by the surrounding geometry code to look elements up
by index, not to compute geometry itself.

## Signature

```c
// Returns a pointer to a caller-or-callee-owned 24-byte result triple written into *out.
// The triple layout is: { void* p0; void* p1; uint32_t flag; }  (offsets +0x00, +0x08, +0x10)
struct triple { void* p0; void* p1; uint32_t flag; };   // 24 bytes (16 + 4, padded to 0x18)

// rcx = it    : pointer to a 24-byte "current position / iterator" triple.
//               it->p0 (+0x00) = current node pointer (node header starts with a u16 key/marker).
//               it->p1 (+0x08) = a base/offset value used by the child-iterator helper (sub_1800067a0).
// edx = key   : uint16-range search key (compared against the node's header word at *(u16*)node).
// r8  = out   : pointer to a 24-byte result triple to fill in (the function's "return value by ptr").
triple* sub_180006800(triple* it /*rcx*/, uint32_t key /*edx*/, triple* out /*r8*/);
```

`out` is also returned in `rax` (via the recursive tail path) or written and then
`eax` set to 1 on the exact-match path. The "return in eax = 1" vs "fill triple"
duality is the classic *"found / not-found + iterator"* convention.

## Pseudocode

```c
triple* sub_180006800(triple* it /*rcx*/, uint32_t key /*edx*/, triple* out /*r8*/)
{
    // ---- prologue / arg shuffle ----                              // 0x180006800: sub rsp,0x58
    triple* r10_out = out;                 // r10 = out               // 0x180006804: mov r10,r8
    void*  node     = it->p0;              // r8 = *(rcx)   (current node)   // 0x180006807: mov r8,[rcx]
    uint32_t r11_key = key;               // r11d = edx (save key for recursion) // 0x18000680a: mov r11d,edx
    uint16_t nodeKey = *(uint16_t*)node;  // ax = *(u16*)node (node header word)  // 0x18000680d: movzx eax,[r8]

    if ((uint32_t)key == (uint32_t)nodeKey) {   // exact match        // 0x180006811: cmp edx,eax
                                                                       // 0x180006813: jne 0x180006830
        // ---- EXACT MATCH: return this node as the found element ----
        r10_out->p0   = node;             // out->p0 = current node    // 0x180006815: mov [r10],r8
        void* p1      = it->p1;           // rax = *(rcx+0x8)          // 0x180006818: mov rax,[rcx+0x8]
        r10_out->p1   = p1;               // out->p1 = it->p1          // 0x18000681c: mov [r10+0x8],rax
        r10_out->flag = 0;                // out->flag = 0             // 0x180006820: xor eax / 0x180006822: mov [r10+0x10],eax
        return (triple*)1;                // eax = 1  (FOUND)          // 0x180006826: mov eax,1 / 0x18000682b: add rsp / 0x18000682f: ret
    }

    // 0x180006830: cmp eax,0x1   (compare NODE key, in eax, against 1)
    if (nodeKey == 1) {                   // sentinel / end-of-list    // 0x180006830: cmp eax,0x1
                                                                       // 0x180006833: jne 0x180006847
        // ---- NOT FOUND: clear out, return empty iterator ----
        r10_out->p0   = 0;                                            // 0x180006835: xor eax / 0x180006837: mov [r10],rax
        r10_out->p1   = 0;                                            // 0x18000683a: mov [r10+0x8],rax
        r10_out->flag = 0;                                            // 0x18000683e: mov [r10+0x10],eax
        return out;                       // (eax still 0) NOT FOUND   // 0x180006842: add rsp / 0x180006846: ret
    }

    // ---- DESCEND: build child iterator and recurse ----            // 0x180006847
    // sub_1800067a0(child /*lea rsp+0x38*/, it /*rcx -> rdx*/):
    //   computes a child position from `it` (reads node header u16 @+0x2 plus it->p1 base)
    //   and writes a 24-byte triple at rsp+0x38, returning it in rax.
    triple child;                         // local @ rsp+0x38
    rdx = it;                             // rdx = rcx (pass `it`)     // 0x180006847: mov rdx,rcx
    rcx = &child;                         // rcx = &rsp[0x38]          // 0x18000684a: lea rcx,[rsp+0x38]
    triple* c = sub_1800067a0(&child, it);// rax -> child triple       // 0x18000684f: call 0x1800067a0

    // copy child triple (24 bytes) into a fresh local @ rsp+0x20, the arg for the recursion
    triple next;                          // local @ rsp+0x20         // 0x180006854: lea rdx,[rsp+0x20]
    r8        = r10_out;                  // r8 = out (forward same out)// 0x180006859: mov r8,r10
    next.p0   = c->p0;                                                // 0x18000685c: mov rcx,[rax] / 0x18000685f: mov [rdx],rcx
    next.p1   = c->p1;                                                // 0x180006862/0x180006866
    next.flag = c->flag;                  // (rax = *(c+0x10))        // 0x18000686a / 0x180006873

    rcx = &next;                          // rcx = &rsp[0x20] (new it) // 0x18000686e: lea rcx,[rsp+0x20]
    edx = r11_key;                        // restore original key      // 0x180006877: mov edx,r11d
    return sub_180006800(&next, r11_key, out);  // TAIL recurse        // 0x18000687a: call 0x180006800
                                                                       // 0x18000687f: add rsp / 0x180006883: ret
}
```

### Helper `sub_1800067a0` (child-iterator builder, called at 0x18000684f)

```c
// rcx = out24 (rsp+0x38), rdx = it
triple* sub_1800067a0(triple* out24 /*rcx->r9*/, triple* it /*rdx->r8*/)
{
    void* node = it->p0;                          // rax = *(rdx)        // 0x1800067a4
    // key2 = (u16)node[+0x2]  +  it->p1   (header child-field + base)
    uint64_t key2 = (uint16_t)*(uint16_t*)(node + 0x2)  + it->p1;        // 0x1800067ad / 0x1800067b6
    triple* r = sub_180006680(&local, key2 /*as ptr/idx*/);             // 0x1800067ba: call 0x180006680
    out24->p0 = r->p0; out24->p1 = r->p1; out24->flag = r->flag;        // 0x1800067bf..0x1800067d1
    return out24;                                                        // 0x1800067d5
}
```

### Helper `sub_180006680` (make-iterator-from-node, two entry points)

```c
// Entry 0x180006680: rcx=out24, rdx=node (or NULL)
triple* sub_180006680(triple* out /*rcx*/, void* node /*rdx*/) {
    out->p0 = 0; out->p1 = 0; out->flag = 0;          // 0x180006680..0x18000668c
    if (node != NULL) {                               // 0x180006682 test / 0x18000668f je
        out->p0 = node;                               // 0x180006695
        out->p1 = node + 0x4;                         // 0x180006691 lea rax,[rdx+4] / 0x180006698
    }
    return out;                                       // 0x18000669c
}
// Entry 0x1800066a0 (separate routine in same blob): wraps the above, then
// writes WORD[node]=r8w, WORD[node+2]=0, flag=0 — an "insert/init node header" path.
```

## Struct fields & constants

The container "node" header (pointed to by `it->p0` / `*(rcx)`):

| Access | Address | Inferred meaning |
|---|---|---|
| `*(u16*)(node + 0x00)` | 0x18000680d | Node **key / marker word** compared to search key. Value `1` is the end/sentinel marker. |
| `*(u16*)(node + 0x02)` | 0x1800067ad | Child-link field (an index/offset; added to base `it->p1` to form the next node address). |
| `node + 0x04` | 0x180006691 | Start of node payload (helper sets `it->p1 = node+4`). |

The 24-byte **iterator/result triple** (pointed to by `rcx`/`r8`/`r10`):

| Offset | Address(es) | Meaning |
|---|---|---|
| `+0x00` p0 | 0x180006807 (read), 0x180006815/0x180006837 (write) | Current/found node pointer. |
| `+0x08` p1 | 0x180006818 (read), 0x18000681c/0x18000683a (write) | Base/offset carried for child-address computation (`+ (u16)node[2]`). |
| `+0x10` flag | 0x180006822/0x18000683e (write, =0) | Status/flag word; always cleared to 0 here. |

Magic constants:

| Constant | Address | Meaning |
|---|---|---|
| `0x1` | 0x180006830 | End/sentinel node-key value → terminates the descent as NOT-FOUND. |
| `0x1` (eax=1) | 0x180006826 | Return code for the exact-match / FOUND path. |
| `0x0` | 0x180006820, 0x180006835, 0x18000683e | Cleared flag / cleared empty iterator. |
| `0x2`, `0x4` | 0x1800067ad, 0x180006691 | Node header field offsets (child-link, payload start). |
| `0x58` / `0x48` | 0x180006800 / 0x1800067a0 | Stack frame sizes (shadow space + the two 24-byte locals). |

No fixed-point shifts (`>>16`, `*0x10000`, `0x8000` rounding), no `imul`/`cvtsi`/`sqrt`/
`atan2`, no matrix layout. This function is purely structural.

## Callees

- `0x1800067a0` — child-iterator builder: from current `it`, compute next node = `base(it->p1) + (u16)node[+0x2]`, wrap as a triple (see `func_1800067a0`, transcribed above). Calls `0x180006680`.
- `0x180006680` — make-iterator-from-node: zero a triple, and if node!=NULL set `p0=node`, `p1=node+4` (see above).
- `0x180006800` — **self / tail recursion** (at 0x18000687a) with the same `key` and `out`, advancing `it` to the child position. (The callgraph json only lists `1800067a0` as a callee and omits this self-edge.)

## GDB verification hooks

These let a Python re-implementation be checked step-by-step. All addresses are
absolute (module-base 0x180000000 assumed loaded at that VA; if ASLR-rebased, add
the same delta to every address).

1. **Entry — observe inputs**
   - `break *0x180006807` then dump:
     - `rcx` → the iterator triple. Dump `*(void**)rcx` (= node), `*(void**)(rcx+8)` (= base p1), `*(uint*)(rcx+0x10)` (= flag).
     - `edx` (low 16 bits) = search **key**.
     - `r8` = out pointer.
   - `break *0x18000680d` and read `WORD PTR [r8]` (after `mov r8,[rcx]`, r8=node) = **nodeKey** at this level.

2. **Compare / branch decision**
   - `break *0x180006811` (the `cmp edx,eax`): compare `edx` vs `ax`. Record whether match (→ FOUND path 0x180006815) or not.
   - `break *0x180006830` (`cmp eax,0x1`): `eax` (=nodeKey) — if 1 the descent stops NOT-FOUND.

3. **FOUND path — verify written triple**
   - `break *0x180006826` (just before setting eax=1): dump `*(void**)r10` (node), `*(void**)(r10+8)` (p1), `*(uint*)(r10+0x10)` (=0). This is the returned found element.

4. **NOT-FOUND path**
   - `break *0x180006842`: confirm the triple at `r10` is all zero.

5. **DESCEND — verify child computation** (the load-bearing step for porting the traversal)
   - `break *0x1800067b6` (inside helper, `add rdx,[r8+8]`): before the add, `rdx` = `(u16)*(node+2)` (child-link); after, `rdx` = `child-link + base(it->p1)`. Dump both → this is the **next node address/index**.
   - `break *0x1800067ba` (call to 0x180006680): `rdx` = computed next-node value. `rcx` = local out (rsp+0x20 of that frame).
   - `break *0x18000684f` (in main, the `call 0x1800067a0`) and `break *0x180006854` (right after): dump the child triple at `rsp+0x38` = `*(void**)(rsp+0x38)`, `*(void**)(rsp+0x40)`, `*(uint*)(rsp+0x48)`.
   - `break *0x18000687a` (the recursive call): dump the new `it` at `rsp+0x20` (`*(void**)(rsp+0x20)`, `+8`, `+0x10`) and `edx` (=key, must equal the original). Each hit = one level deeper in the traversal; counting hits gives the path length.

To trace a full lookup, set hooks 1–5 and let it run; the sequence of `nodeKey`
values at 0x18000680d and child addresses at 0x1800067b6 reconstructs the exact path.

## Confidence & open questions

**Solid (high confidence):**
- Control flow is exact: three cases — exact key match (return node, eax=1), sentinel
  key `1` (return empty, eax=0), otherwise build child iterator and tail-recurse.
- The 24-byte triple layout `{p0@0, p1@8, flag@0x10}` and the node header reads
  (`u16@0`, `u16@2`, payload `@4`) are directly from the disasm.
- This function performs **no** geometry / fixed-point / transform math. It is a
  generic ordered-container `find` and is relevant to sec0_pre only as the *lookup
  primitive* the geometry code uses to fetch elements by key/index, not as the place
  transforms are computed.

**Inferred / open:**
- Exact container kind: the `(u16)node[+0x2] + base` child addressing looks like an
  index-into-array (slab/arena) tree or a relative-offset linked map rather than raw
  pointers; whether it is a red-black tree, a sorted vector with a sentinel, or a
  trie can't be decided from this function alone. The sentinel value `1` strongly
  suggests an STL-style end/header node.
- The meaning of `it->p1` (`+0x8`) as the arena base is inferred from how
  `sub_1800067a0` adds it to the child-link word; confirm by dumping it at runtime
  (hook 5).
- `sub_180006680` has a second entry at `0x1800066a0` that *writes* a node header
  (`WORD[node]=r8w`, `WORD[node+2]=0`) — i.e. an insert/init path — but it is not
  reached from `sub_180006800`; noted for completeness only.
- Whether callers rely on the `eax`-return (1=found) vs the out-triple contents is
  caller-specific; both are produced consistently here.
