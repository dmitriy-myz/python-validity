# sub_180003150 — atan2(y, x) wrapper (quadrant resolver), Q16 radians

## Signature

```c
// Returns the angle of the 2D vector (x, y) in RADIANS, fixed-point Q16
// (i.e. radians * 65536). Range is [0, 2*pi) * 65536  ==  [0, 0x6487e).
// Both inputs are SIGNED 32-bit integers (raw coordinate deltas dx, dy).
//
// This is the full-circle / signed-quadrant front-end for the
// first-quadrant atan core sub_1800030a0(|y|, |x|).
int32_t sub_180003150(int32_t x /*ecx*/, int32_t y /*edx*/);
```

Argument meaning (inferred, high confidence from caller `sub_1800041d0`):

| reg | name  | meaning |
|-----|-------|---------|
| ecx | `x`   | x-component of a vector / coordinate delta `dx` (signed) |
| edx | `y`   | y-component of a vector / coordinate delta `dy` (signed) |

At the call site `0x18000420e–0x180004215` the caller does
`edx = *(int*)(r15+4)` (a `dy`) and `ecx = *(int*)(r15)` (a `dx`), then
`call sub_180003150`, and immediately multiplies the result by `0xb4` (=180).
So the convention is `sub_180003150(dx, dy) = atan2(dy, dx)` in Q16 radians.

The core `sub_1800030a0` does the heavy lifting: it computes the angle of
`(arg0, arg1)` in **degrees * 65536** using a polynomial atan approximation,
then converts to radians*65536 with the tail `(deg_q16 >> 8) * 71 >> 4`
(≈ deg * 1136, vs. exact rad-Q16/deg = 1143.8). `sub_180003150` only feeds it
the absolute values `(|y|, |x|)` and reconstructs the signed quadrant itself.

## Pseudocode

//                       TWO_PI_Q16 = 0x6487e = 2*0x3243f = round(2pi*65536)
//
// core(a,b) == sub_1800030a0(a /*ecx*/, b /*edx*/)
//           == first-quadrant atan of the magnitudes (returns ~[0, pi/2)*65536
//              when called as core(|y|,|x|)).

        // 0x180003162 add rsp,0x28

L_q4:                                          // 0x18000316b

    {                                          // 0x18000316d  mov ecx,eax    (ecx = |y|)

        int32_t r = 0x6487e - a;               // 0x180003174 mov ecx,0x6487e ; 0x180003179 sub ecx,eax

        return r;                              // 0x180003181  ret    ( 2*pi - core )

    int32_t core_edx2 = x;                     // 0x180003186  mov edx,ecx    (edx = |x|)

    //       holds the entry value y at that point), so the branch is "y < 0".

        // 0x180003198 mov eax,ecx ; 0x18000319a add rsp,0x28
        return r;                              // 0x18000319e  ret    ( pi - core )
    }

    // ---- Quadrant 3: x<0, y<0 ----  result in (pi, 3pi/2)*65536
L_q3:                                          // 0x18000319f

        // 0x1800031af add rsp,0x28

### Net behaviour (the important part for porting)

Let `a = core(|y|, |x|)` ∈ `[0, pi/2)*65536` (first-octant/quadrant atan of the
absolute values, i.e. `atan(|y|/|x|)` in Q16 radians):

| quadrant | condition      | returned value        | radians range          |
|----------|----------------|-----------------------|------------------------|
| Q1       | x>=0, y>=0     | `a`                   | `[0, pi/2)`            |
| Q2       | x<0,  y>=0     | `PI_Q16 - a`          | `(pi/2, pi]`           |
| Q3       | x<0,  y<0      | `a + PI_Q16`          | `(pi, 3pi/2)`          |
| Q4       | x>=0, y<0      | `TWO_PI_Q16 - a`      | `(3pi/2, 2pi)`         |

So the function is exactly **atan2(y, x) normalised to [0, 2*pi)** in Q16
radians. (Standard math `atan2` returns `(-pi, pi]`; this one adds `2*pi` to
the negative half, i.e. `result = atan2(y,x) mod 2pi`.)

A faithful Python port (matching the *shape*; bit-exactness needs the core):
```python
def atan2_q16(x, y):                  # returns radians*65536 in [0, 0x6487e)
    a = core_atan_q16(abs(y), abs(x)) # == sub_1800030a0(|y|, |x|)
    if x >= 0 and y >= 0: return a
    if x >= 0 and y <  0: return 0x6487e - a
    if x <  0 and y >= 0: return 0x3243f - a
    return a + 0x3243f                # x<0, y<0
```

## Confidence & open questions

**Solid (high confidence):**
- Control flow, quadrant routing, and the four return formulas are transcribed
  directly from the disasm and verified above.
- `0x3243f = pi*65536` and `0x6487e = 2pi*65536` are confirmed numerically
  (205887 ≈ 205887.4; ratio exactly 2.0).
- The function returns `atan2(y, x)` normalised to `[0, 2pi)` in Q16 radians;
  arg order is `(x, y)` per the caller `sub_1800041d0` and the
  multiply-by-180 follow-up at `0x18000422a`.
- This function does no memory access.

**Inferred / to confirm separately:**
- Exact bit-level value of the core `a` depends entirely on `sub_1800030a0`'s
  polynomial (coeffs `-2601, 0x23a7, 0x4aac, 0xe522`) and its `(deg>>8)*71>>4`
  scaling. The `* 1136`-per-degree tail is ~0.7% below the exact
  `* 1143.8`-per-degree, so this atan2 is a deliberately cheap fixed-point
  approximation — a bit-exact Python port MUST replicate `sub_1800030a0`
  arithmetic exactly (same shifts/idiv truncation), not call `math.atan2`.
- The `test edx,edx` at `0x180003184` reads `edx` which still holds the entry
  `y` (it has not been overwritten on the x<0 path before this test) — hence
  the branch is genuinely "y < 0". Confirmed by register liveness; worth a
  one-shot gdb check (hook 2) if porting Q2/Q3 disagrees.
- Whether downstream code expects `[0,2pi)` vs `(-pi,pi]`: the immediate caller
  multiplies by 180 then by `0x517ccc83`/`>>` (a divide-by-constant), i.e. it
  rescales the angle into some bucket index — it does not appear to care about
  the half-turn sign convention, but that is outside this function's scope.
