# sub_1800031e0 — aligned/unaligned block copy (inlined `memcpy`-style helper)

This is **not** transform math. It is a small, hand-rolled / compiler-inlined block-copy
routine: a "fast path" that copies 4 bytes at a time when both pointers are 4-byte aligned
and the length is a multiple of 4, and a "slow path" that copies 1 byte at a time otherwise.
It has **no callees**, no fixed-point arithmetic, no trig, no matrix/affine ops, and writes
to no struct fields. It is the kind of helper the transform code *calls* to move data, not
the place where coordinates are computed.

## Signature

```c
// rcx = dst, rdx = src, r8d = byte_count (signed 32-bit, sign-extended to 64)
// Returns rcx unchanged? No — eax/rax holds the last copied element on the fast path,
//   or the last byte on the slow path. The return value is effectively garbage / ignored;
//   callers treat this as void. The two `ret` sites differ only in stack-clean amount.
void *sub_1800031e0(void *dst /*rcx*/, const void *src /*rdx*/, int n /*r8d*/);
```

Argument meanings (best effort):

| reg  | name        | meaning                                                              |
|------|-------------|----------------------------------------------------------------------|
| rcx  | `dst`       | destination pointer                                                  |
| rdx  | `src`       | source pointer                                                       |
| r8d  | `n`         | number of **bytes** to copy (signed 32-bit; `movsxd` to 64-bit `r10`)|

Notes:
- `n <= 0` copies nothing (both paths guard with a signed `jle`).
- The "alignment & multiple-of-4" test is done on the low 2 bits of `dst`, `src`, and `n`.

## Pseudocode

```c
void *sub_1800031e0(void *dst /*rcx*/, const void *src /*rdx*/, int n /*r8d*/)
{
    // --- entry / alignment test --------------------------------------------- 0x1800031e0
    int64_t  r10 = (int64_t)(int32_t)n;     // movsxd r10, r8d ; signed n -> 64-bit  // 0x1800031e3
    void    *r9  = src;                      // mov r9, rdx                            // 0x1800031e6

    // If dst is NOT 4-byte aligned -> byte path
    if ((uintptr_t)dst & 0x3) goto L_byte;   // test cl,3 ; jne 0x180003232            // 0x1800031e0 / 0x1800031e9
    // If src is NOT 4-byte aligned -> byte path
    if ((uintptr_t)src & 0x3) goto L_byte;   // test dl,3 ; jne 0x180003232            // 0x1800031eb / 0x1800031ee

    // --- check that n is a multiple of 4 (using signed arithmetic) ---------- 0x1800031f0
    // Computes (n / 4) with C truncation toward zero, and verifies n % 4 == 0.
    {
        int32_t eax = (int32_t)r10;          // mov eax, r10d   (= n)                  // 0x1800031f0
        int32_t edx = eax >> 31;             // cdq             (sign bits of n)       // 0x1800031f3
        edx &= 0x3;                          // and edx,3       (= correction term)    // 0x1800031f4
        eax += edx;                          // add eax,edx     (n + correction)       // 0x1800031f7
        int32_t r8d = eax;                   // mov r8d,eax                            // 0x1800031f9
        eax &= 0x3;                          // and eax,3       (= (n+corr) & 3)        // 0x1800031fc
        r8d >>= 2;                           // sar r8d,2       (= n / 4, signed)       // 0x1800031ff  -> dword_count
        if (eax != edx) goto L_byte;         // cmp eax,edx ; jne 0x180003232          // 0x180003203 / 0x180003205
        //   ^ This whole block is the standard signed "n % 4 == 0?" idiom.
        //     If n is NOT divisible by 4, fall back to the byte path.

        // --- fast path: copy dword_count 32-bit words --------------------------- 0x180003207
        int32_t dword_count = r8d;           // = n/4
        if (dword_count <= 0) goto L_ret_a;  // test r8d,r8d ; jle 0x180003252 (signed) // 0x180003207 / 0x18000320a

        r9 = (char*)src - (char*)dst;        // sub r9, rcx ; r9 = src-dst (byte delta) // 0x18000320c
        int64_t cnt = (uint32_t)dword_count; // mov edx, r8d (zero-extended counter)    // 0x18000320f
        // 0x180003212..0x18000321c: multi-byte NOP padding (loop alignment), no effect.

    L_dword_loop:                            //                                        // 0x180003220
        eax_word = *(int32_t*)((char*)dst + r9); // mov eax,[r9+rcx]  (= *src)          // 0x180003220
        dst = (char*)dst + 4;                // add rcx,4                              // 0x180003224
        cnt -= 1;                            // sub rdx,1                              // 0x180003228
        *(int32_t*)((char*)dst - 4) = eax_word;  // mov [rcx-4],eax  (= *dst)          // 0x18000322c
        if (cnt != 0) goto L_dword_loop;     // jne 0x180003220                        // 0x18000322f
        return; /* eax = last word */        // ret                                    // 0x180003231
    }

L_byte:                                      //                                        // 0x180003232
    // --- slow path: copy r10 (= n) bytes ------------------------------------
    if ((int32_t)r10 <= 0) goto L_ret_b;     // test r10d,r10d ; (rdx=r10) ; jle 0x180003252 (signed) // 0x180003232 / 0x180003235 / 0x180003238
    int64_t bcnt = r10;                      // mov rdx, r10 (counter = n)             // 0x180003235
    r9 = (char*)src - (char*)dst;            // sub r9, rcx ; r9 = src-dst (byte delta) // 0x18000323a
    // 0x18000323d: NOP padding.

L_byte_loop:                                 //                                        // 0x180003240
    al = *(uint8_t*)((char*)dst + r9);       // movzx eax,byte [rcx+r9]  (= *src)      // 0x180003240
    dst = (char*)dst + 1;                    // add rcx,1                              // 0x180003245
    bcnt -= 1;                               // sub rdx,1                              // 0x180003249
    *(uint8_t*)((char*)dst - 1) = al;        // mov [rcx-1],al  (= *dst)               // 0x18000324d
    if (bcnt != 0) goto L_byte_loop;         // jne 0x180003240                        // 0x180003250
    /* fall through */

L_ret_b:
    return; // ret 0  (ret 0x0)              //                                        // 0x180003252

L_ret_a:
    return; // reached from 0x18000320a; control flow joins ret at 0x180003252
}
```

### The `src - dst` pointer trick

Both loops first do `r9 = src - dst` (e.g. `sub r9, rcx` at `0x18000320c` / `0x18000323a`).
Thereafter the source address is computed as `dst + r9` (`[rcx + r9]`). As `dst` (`rcx`) is
advanced, `dst + r9` stays equal to the corresponding `src` address. This lets the loop use a
single advancing register (`rcx`) for both reads and writes — a common compiler optimization.
So `*(dst + r9)` reads from `src`, and `*(dst - 4)` / `*(dst - 1)` writes to `dst`.

## Struct fields & constants

No struct (`[reg+0xNN]` field) accesses. All memory accesses are array/pointer element
accesses of the copy buffers themselves (`[r9+rcx]`, `[rcx-4]`, `[rcx-1]`).

| value     | meaning                                                                 |
|-----------|-------------------------------------------------------------------------|
| `0x3`     | low-2-bits mask: used for 4-byte alignment test (`cl&3`, `dl&3`) and for the signed `n % 4` idiom (`and edx,3`, `and eax,3`). |
| `0x2`     | `sar r8d, 2` → divide by 4 (compute dword count from byte count).        |
| `0x4`     | dword stride (`add rcx,4`).                                              |
| `0x1`     | byte stride / loop decrement.                                           |
| `ret 0x0` | `0x180003252` is `ret` with imm16 = 0 (stdcall-style 0-byte cleanup); `0x180003231` is plain `ret`. Both effectively return. |

Magic-constant verdict: there are **no** fixed-point constants here (`0x10000`, `0x8000`,
`65536`), no rounding adds, no trig tables. The only constant arithmetic is alignment masking
and a `>>2` for dword counting.

## GDB verification hooks

This routine has no transform/coordinate/score computation to verify, but to confirm a Python
re-implementation moves the same bytes you can hook the entry and loop:

- `break *0x1800031e0` — **entry**. Dump the three arguments:
  - `rcx` = dst pointer, `rdx` = src pointer, `r8d` = byte count `n`.
  - From these you can predict which path is taken: fast (dword) path iff `(rcx&3)==0 && (rdx&3)==0 && (n%4)==0 && n>0`; otherwise byte path; nothing copied if `n<=0`.
- `break *0x18000320c` — fast path is being taken. Dump `r8d` (= `n/4`, the dword count) and `rcx`/`rdx` (dst/src). Confirms divisibility branch chose the word loop.
- `break *0x180003220` — **dword loop body**. Dump `eax` after the `mov eax,[r9+rcx]` to see each 32-bit word copied; dump `rcx` for the current dst and `rdx` for the remaining count. Set a temporary breakpoint or `commands`+`continue` to log the stream.
- `break *0x180003232` — byte path is being taken (unaligned or non-multiple-of-4). Dump `r10d` (= `n`).
- `break *0x180003240` — **byte loop body**. Dump `al` (`eax & 0xff`) for each byte copied and `rcx`/`rdx` for dst / remaining count.
- `break *0x180003231` and `break *0x180003252` — the two return sites; confirm which exit fired.

To verify a port, the simplest end-to-end check is: at `0x1800031e0` record `(rcx, rdx, r8d)`,
let it run to its `ret`, then dump `r8d` bytes at the captured `dst`; they must equal `r8d`
bytes at the captured `src`.

## Confidence & open questions

**Solid (high confidence):**
- This is a byte/dword block copy equivalent to `memcpy(dst, src, n)` for `n > 0`, with two
  internal paths chosen by alignment + length divisibility. Behaviorally identical to `memcpy`.
- The signed `n % 4 == 0` test (`cdq; and edx,3; add; and eax,3; cmp`) and the `sar …,2`
  dword-count are textbook compiler idioms.
- No transform/geometry/fixed-point math; no callees; no struct field writes.

**Inferred / minor open questions:**
- **Return value:** the function leaves the last-copied element in `eax`/`al`, which is almost
  certainly an artifact, not a meaningful result; callers most likely treat it as `void` (or
  `void *` returning `dst` is *not* what happens here — `rax` is clobbered by the loop). Mark
  the return type as effectively ignored.
- The two distinct `ret` encodings (`ret` at `0x180003231` vs `ret 0x0` at `0x180003252`)
  suggest this was assembled/inlined from a source where one exit used an explicit imm16; both
  pop 0 bytes, so calling convention is unaffected.
- Because `n` is treated as **signed** in both guards (`jle`), a negative `n` is a safe no-op.
- Relevance to `sec0_pre` / rigid-transform math: **none directly** — this is plumbing. It may
  be the copier used to splat transform structs or table rows around, but it computes no
  geometry itself.
