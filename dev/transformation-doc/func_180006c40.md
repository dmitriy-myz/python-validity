# sub_180006c40 — 2D vector normalization to a fixed-point unit vector

This function takes a 2D vector `(x, y)` passed by reference (two `int*`), and
rewrites it **in place** as a unit-vector in Q-format scaling. It is the
elementary building block used to turn a raw gradient / direction delta
`(dx, dy)` into a normalized cosine/sine pair — exactly the `(a, b)` pair that
seeds the `R = [[a, -b], [b, a]]` similarity-transform used in `sec0_pre`.

The single callee `0x180003060` is an **integer square root (isqrt)** routine
(restoring/Newton-style bit algorithm), so this routine computes
`mag = sqrt(x'^2 + y'^2)` and divides the components by it.

---

## Signature

```c
// Normalizes the 2D vector (*px, *py) in place to fixed-point unit length.
// px, py are read+written. No return value (return reg is garbage/unused).
//
// Inputs:
//   rcx = px  -> int* : X / cosine-like component (Q-fixed)
//   rdx = py  -> int* : Y / sine-like   component (Q-fixed)
void sub_180006c40(int *px /*rcx*/, int *py /*rdx*/);
```

Notes / guesses:
- The function returns nothing meaningful; `eax` holds leftover from the last
  `idiv`/`mov` but the prologue/epilogue restore non-volatiles and the result
  is delivered purely through the two pointers. (GUESS, but strongly supported:
  every store is to `*px` / `*py`.)
- `px`/`py` are signed 32-bit (`mov e..,DWORD PTR`; later `cdq`/`idiv` = signed).
- The "halving" (`sar ...,1`) on the inputs before squaring is an
  overflow-guard so that `x'^2 + y'^2` fits in a signed 32-bit `int` before it
  is fed to the isqrt — the math is scale-invariant for a *direction*, so
  halving both components does not change the resulting unit vector (the final
  `<<14` divide-by-`mag>>1` compensates the scale exactly; see derivation
  below).

## Pseudocode

```c
void sub_180006c40(int *px /*rcx*/, int *py /*rdx*/)
{
    // ---- prologue: save rbx,rbp,rsi,rdi; reserve 0x20 shadow ----
    //   0x180006c40  mov [rsp+0x8], rbx
    //   0x180006c45  mov [rsp+0x10], rbp
    //   0x180006c4a  mov [rsp+0x18], rsi
    //   0x180006c4f  push rdi
    //   0x180006c50  sub rsp, 0x20

    int x  = *px;                       // ebx = *rcx                 0x180006c54
    int y  = *py;                       // edi = *rdx                 0x180006c56
    int *pbp = px;  // rbp = rcx (saved ptr to X)                     0x180006c58
    int xh = x >> 1; // SIGNED (sar)    ebx = x>>1                    0x180006c5b
    int yh = y >> 1; // SIGNED (sar)    edi = y>>1                    0x180006c5d
    int *psi = py;  // rsi = rdx (saved ptr to Y)                     0x180006c5f

    //   0x180006c62  mov ecx, edi          ; ecx = yh
    //   0x180006c64  mov eax, ebx          ; eax = xh
    int sumsq = yh*yh + xh*xh;          // ecx = yh*yh; eax = xh*xh; ecx += eax
    //   0x180006c66  imul ecx, edi         ; ecx = yh*yh
    //   0x180006c69  imul eax, ebx         ; eax = xh*xh
    //   0x180006c6c  add  ecx, eax         ; ecx = xh*xh + yh*yh

    // mag = isqrt(sumsq)     (callee 0x180003060: unsigned integer sqrt)
    unsigned mag = isqrt((unsigned)sumsq);     // eax = isqrt(ecx)    0x180006c6e (call 0x180003060)
    unsigned r11 = mag >> 1;            // r11d = mag >> 1            0x180006c73 / 0x180006c76

    if (r11 == 0) goto L_zero;          // je 0x180006c97             0x180006c79

    // ---- nonzero magnitude: scale each component to a unit vector ----
    // cx = (x << 14) / r11      ; SIGNED idiv
    int tx = (int)((unsigned)x << 14);  // eax = x; eax <<= 14        0x180006c7b / 0x180006c7e
    // cdq; idiv r11d  -> eax = tx / r11 ; remainder in edx (discarded)
    int nx = tx / (int)r11;             // ecx = eax(=tx)/r11         0x180006c81 / 0x180006c82 / 0x180006c85

    int ty = (int)((unsigned)y << 14);  // eax = y; eax <<= 14        0x180006c87 / 0x180006c89
    *px = nx;                           // mov [rbp+0x0], ecx         0x180006c8c   (store X first)
    // cdq; idiv r11d  -> eax = ty / r11
    int ny = ty / (int)r11;             //                            0x180006c8f / 0x180006c90
    *py = ny;                           // mov [rsi], eax             0x180006c93
    goto L_done;                        // jmp 0x180006c9c            0x180006c95

L_zero:                                 //                            0x180006c97
    // degenerate (mag>>1 == 0): write back the HALVED inputs as-is
    *px = xh;                           // mov [rbp+0x0], ebx         0x180006c97
    *py = yh;                           // mov [rsi], edi             0x180006c9a

L_done:                                 //                            0x180006c9c
    // ---- epilogue: restore non-volatiles, return ----
    //   0x180006c9c  mov rbx, [rsp+0x30]
    //   0x180006ca1  mov rbp, [rsp+0x38]
    //   0x180006ca6  mov rsi, [rsp+0x40]
    //   0x180006cab  add rsp, 0x20
    //   0x180006caf  pop rdi
    //   0x180006cb0  ret
}
```

### Math derivation (fixed-point reasoning)

Let `xh = x>>1`, `yh = y>>1` (so `xh ≈ x/2`, `yh ≈ y/2`).

```
mag      = isqrt(xh^2 + yh^2)  ≈ sqrt(x^2 + y^2) / 2
r11      = mag >> 1            ≈ sqrt(x^2 + y^2) / 4
nx       = (x << 14) / r11     = (x * 16384) / (|v|/4)
                               = (x * 16384 * 4) / |v|
                               = x * 65536 / |v|
                               = (x / |v|) * 65536      = cos(θ) in Q16
ny       = (y << 14) / r11     = (y / |v|) * 65536      = sin(θ) in Q16
```

So the output `(*px, *py)` is the **unit vector `(x,y)/|v|` expressed in Q16.16
fixed point** (i.e. ×65536). This is precisely the `(a = cos·65536,
b = sin·65536)` form noted in MEMORY for the `R=[[a,-b],[b,a]]` similarity
transform. The two halvings (`>>1` on inputs, `>>1` on the sqrt result) net to
a `/4` in the denominator, which is the factor that turns the `<<14`
(=×16384) numerator into an effective ×65536 (Q16) scale. The halvings exist
to keep `xh^2+yh^2` inside signed-32 range before the isqrt.

## Callees

- `0x180003060` — **unsigned integer square root (isqrt)**. Takes `ecx` =
  radicand, returns `eax` = `floor(sqrt(ecx))`. Bitwise restoring-sqrt
  (`0x40000000 = 1<<30` start bit, `shr ...,2` step). Leaf, no further calls.
  (Verified by reading `/tmp/func_180003060.S`.)

## GDB verification hooks

To verify a Python re-implementation produces byte-identical intermediates,
set these breakpoints. (Windows x64: 1st arg `rcx`, 2nd arg `rdx`.)

1. **Entry — inputs** `break *0x180006c40`
   - `x/wd $rcx`  → input X (`*px`)
   - `x/wd $rdx`  → input Y (`*py`)
   Also dump `$rcx`,`$rdx` (the pointer addresses) so you can re-read at exit.

2. **After halving + sum of squares, just before isqrt** `break *0x180006c6e`
   - `p/d $ebx`   → `xh = x>>1`
   - `p/d $edi`   → `yh = y>>1`
   - `p/d $ecx`   → `sumsq = xh*xh + yh*yh` (the radicand passed to isqrt)

3. **Right after isqrt returns / after the shift** `break *0x180006c79`
   - `p/d $eax`   → `mag = isqrt(sumsq)` (read just after the call, before shr —
     set an extra bp at `0x180006c73` if you want `mag` pristine)
   - `p/d $r11d`  → `r11 = mag >> 1` (the divisor). If `0` → degenerate branch.

4. **Nonzero branch, after X is normalized** `break *0x180006c8c`
   - `p/d $ecx`   → `nx = (x<<14)/r11` = `cos·65536` (the value being stored to `*px`)
   - `x/wd $rbp`  → confirm `*px` now equals `nx`

5. **Nonzero branch, after Y is normalized** `break *0x180006c95`
   - `p/d $eax`   → `ny = (y<<14)/r11` = `sin·65536` (just stored to `*py`)
   - `x/wd $rsi`  → confirm `*py` now equals `ny`

6. **Degenerate branch (only hit when r11==0)** `break *0x180006c97`
   - confirms inputs were near-zero; outputs become `xh`,`yh`.

7. **Exit — final outputs** `break *0x180006cb0`
   - Using the pointer addresses captured at entry: `x/wd <px_addr>` and
     `x/wd <py_addr>` → final normalized `(cos·65536, sin·65536)`.
   - Sanity: `nx*nx + ny*ny` should be ≈ `65536^2` (= `0x100000000`) within
     integer rounding.

Priority hooks for the transform port: **#4 and #5** (the actual cos/sin Q16
writes) and **#2/#3** (radicand + magnitude) to catch any sqrt/rounding drift.

## Confidence & open questions

**Solid (read directly from disasm):**
- Control flow, all addresses, the in-place writes to `*px`/`*py`, store order
  (X stored at 0x180006c8c *before* Y's divide).
- Signedness: inputs squared via signed `imul`; `cdq;idiv` = signed division.
  The `<<14` uses `eax` (treated as the dividend for a signed idiv).
- `0x180003060` is an integer square root (confirmed by reading its body).
- Net scaling = Q16 (×65536) unit vector, from the `<<14` numerator combined
  with the `/4` denominator (two `>>1` halvings).

**Inferred / GUESS:**
- The semantic naming "cosine/sine" (`a`/`b`) for X/Y — inferred from the
  surrounding `sec0_pre` transform context in MEMORY, not provable from this
  leaf alone. Functionally it is just "normalize a 2D vector to Q16 unit length."
- No return value is used (the pointers carry the result).

**Open questions:**
- Whether callers feed *gradient* deltas `(dx,dy)` or *point* deltas
  `(x2-x1, y2-y1)` here. Determined by callers, not by this function. Worth
  grepping the callgraph for who calls `0x180006c40` to confirm it seeds the
  `(a,b)` rotation pair vs. being a generic helper.
- The degenerate branch writes the *halved* inputs (`xh,yh`), NOT zero — so a
  zero-length vector yields `(x>>1, y>>1)`, which for truly-zero input is
  `(0,0)`. A small-but-nonzero input where `mag>>1==0` would leak a tiny halved
  vector rather than a unit vector; callers presumably never hit this.
