# sub_1800046e0 — RANSAC rigid/similarity transform fitter (sec0_pre inter-frame registration)

This is **one of the two root functions** that build the enrollment template geometry. It takes two
sets of keypoint correspondences (a "from" frame and a "to" frame), runs a **RANSAC-style
hypothesis-and-verify loop** to find the Q16 fixed-point **2D similarity transform**
`R=[[a,-b],[b,a]], t=(tx,ty)` that best aligns them, refits the transform from the inlier set, and
writes the result (plus an inlier count and an average-error/quality score) into a `sec0_pre`-style
output record (`rbp`) and a separate score slot (`r14`).

The actual transform arithmetic lives in the callees:
- **2-point minimal solve** → `sub_180006e10` (via `sub_180007390`)
- **apply Q16 transform to a point** → `sub_180006bc0` (via `sub_180007450`)
- **N-point least-squares refit** → `sub_180006f20` (via `sub_1800073f0`)
- **the whole hypothesis search / inlier voting** → `sub_180007480`
- **a final descriptor/feature refit on the winning model** → `sub_1800043d0`

> Frame note: prologue saves rbx and r9/r8/rdx into the *caller's* shadow space
> (`[rsp+0x08/0x10/0x18/0x20]`), pushes rbp,rsi,rdi,r12–r15 (7 qwords = 0x38), then
> `sub rsp,0x320`. So a value the caller passed at `[rsp+0x28+k]` is read here at
> `[rsp+0x320+0x38+0x08+0x28+k] = [rsp+0x388+k]` (the two stack-arg pointers are read at
> `[rsp+0x380]` and `[rsp+0x388]`). All large-offset stack reads below were derived from that.

## Signature

```c
// All semantics best-effort; widths are certain.
int sub_1800046e0(
    void   *ctx,        // rcx  -> r12  : context/object whose fields hold the WINNING transform
                        //                (a,b,tx,ty at +0x00,+0x04,+0x08,+0x0c) + counts (+0x08? see note)
    void   *kp_from,    // rdx  -> rbx  : "from"/source keypoint list header; +0x08 = count N
    void   *kp_to,      // r8   -> r13  : "to"/destination keypoint list header; +0x08 = count
    void   *arg4,       // r9          : pointer threaded into the three sub_180003320 "copy 0x30"
                        //                preludes (a 6-qword / 0x30-byte descriptor blob is cloned)
    // ---- stack args (read at [rsp+0x388+k]) ----
    /* [rsp+0x28] */ void *out_rec,   // -> rbp (rsp+0x388) : OUTPUT record (sec0_pre entry):
                                      //   +0x04=a +0x08=tx +0x0c=b +0x10=ty (the rigid transform)
                                      //   +0x5c=score +0x60=n_inliers +0x64=n_used
                                      //   +0x68.. = refined transform from sub_1800043d0
    /* [rsp+0x20] */ int  *out_score  // -> r14 (rsp+0x380) : OUTPUT avg-squared-error / quality u32
);
// returns eax = status flag (0 on the degenerate / too-few-points path; 1 once a model is committed)
```

The first three `sub_180003320` calls each copy a **0x30-byte (6-qword) blob** out of `arg4`/derived
pointers into a stack scratch at `rsp+0xc0`, leaving its result pointer in `rsp+0x90` and harvesting
two sub-pointers into `rsp+0x70`/`rsp+0x78`/`rsp+0x68` (these become the **x-array** and **y-array**
base pointers of the two keypoint sets — see the per-point loop). This is the standard "container
accessor" idiom for this DLL (`sub_180003320` returns a 0x30-byte view onto a list).

### What the math actually is (from the callees)

The transform is a **Q16 fixed-point 2D similarity** `(a, b, tx, ty)` with
`x' = (a·x − b·y + tx) >> 16`, `y' = (b·x + a·y + ty) >> 16` (rounding `+0x8000`).
This is confirmed in `sub_180006bc0` (the point-apply primitive) and is the same convention used in
`sec0_pre`.

- **Minimal 2-point solve** (`sub_180006e10`, via `sub_180007390`): given two source points
  `p0,p1` and two dest points `q0,q1`, it forms `u = p1−p0`, `v = q1−q0`, computes
  `mag = isqrt(cross² + dot²)` via `sub_180003060` (integer sqrt seeded at `0x40000000`), then
  `a = (dot<<16)/mag`, `b = (cross<<16)/mag` (the normalized rotation+scale), and finally the
  translation from the point midpoints (`sar …,1` averages the two equations). Output struct
  `{b@+0x00, a@+0x04, tx@+0x08, ty@+0x0c}` — note the **a/b are swapped vs. apply order**, which is
  exactly why this function re-shuffles them when copying ctx→rbp (see 0x180004a90 block).
- **Inlier test threshold**: in `sub_180007480` an inlier requires squared residual
  `(Δx)²+(Δy)² ≤ *(int*)(rsp+0xe8)` (a caller-supplied threshold), and candidate point pairs are
  pre-filtered by `|Δcoord| ≤ 0x10` (16) before even estimating a model.
- **N-point LSQ refit** (`sub_180006f20`, via `sub_1800073f0`) re-estimates `(a,b,tx,ty)` from all
  inliers once the best 2-point hypothesis is chosen.
- **Geometry sanity test** `sub_180004680(ctx)`: reads the just-fitted transform from `ctx` and
  rejects it if it is too large/odd: `(tx>>12)²+(ty>>12)² ≥ 0x7d0`, or `(a>>4)² ≥ 0x2260`, or
  `(0x1000 − (b>>4))² ≥ 0x2260`. (i.e. translation within ~√2000·4096 LSB, scale·cos near 1.0=0x1000
  ±~38·16.) Returns 1 only if the model is "small/clean"; otherwise the model is flagged degenerate
  and inliers reset to 0.

## Struct fields & constants

### `ctx` (rcx → r12) — holds the WINNING minimal model
| Access | Field | Meaning |
|---|---|---|
| `*(int*)(ctx+0x00)` | model `b` (Q16) | rotation sin·scale term (set 0x10000 in identity path) |
| `*(int*)(ctx+0x04)` | model `ty` (Q16) | translation y (copied to rbp+0x10) |
| `*(int*)(ctx+0x08)` | model `a` (Q16) | rotation cos·scale term (copied to rbp+0x04) |
| `*(int*)(ctx+0x0c)` | model `tx` (Q16) | translation x (copied to rbp+0x08) |

(Field naming follows `sub_180006e10`'s output layout `{b,a?,tx,ty}`; the apply primitive
`sub_180006bc0` reads `[+0x00]=b-row scale, [+0x04]=a-row, [+0x08]=tx, [+0x0c]=ty`. The exact
a↔b labelling is the one open question — see below.)

### `out_rec` (rbp, from `[rsp+0x388]`) — the sec0_pre-style OUTPUT record
| Access | Meaning |
|---|---|
| `rbp+0x04` | transform term `a` (= ctx+0x08) |
| `rbp+0x08` | transform `tx` (= ctx+0x0c) |
| `rbp+0x0c` | transform term `b` (= ctx+0x00; = 0x10000 in identity) |
| `rbp+0x10` | transform `ty` (= ctx+0x04) |
| `rbp+0x5c` | **score** = mean(aux[inliers]) or 0x7fff if too few |
| `rbp+0x60` | **n_inliers** (esi, best hypothesis inlier count) |
| `rbp+0x64` | **n_used** = min(N, 25) |

Receives `sum(aux[inliers])` then `/= n_inliers` → **mean per-inlier aux** (a confidence/score), or
`0x7fff` when fewer than 4 inliers.

## Callees

- `0x180003320` — container/list **accessor**: returns a 0x30-byte view struct over a list, fills an
  out-ptr (`r9`) with the data base pointer. Called 5×. (callees: `1800032c0`) — see func_180003320.md
- `0x180003880` — **populate parallel x/y keypoint arrays** for the two frames from the correspondence
  records; sets the working count at `rsp+0x60`. (callees: `180003320`,`180003640`) — see func_180003880.md
- `0x1800095c0` — large list build/**sort** helper (677 instrs); here called with stride `0x1c` and
  comparator `0x180004600` (sorts correspondences). — see func_1800095c0.md (deep helper)
- `0x180004620` — **circular angle distance mod 180** of two orientation bytes → angle_dist[]. (leaf) —
  see func_180004620.md
- `0x180007480` — **THE RANSAC EVALUATOR**: triple loop over correspondence pairs, pre-filters by
  `|Δ|≤0x10`, estimates a 2-point model (`sub_180007390`→`sub_180006e10`), applies it
  (`sub_180007450`→`sub_180006bc0`), counts inliers by squared-residual ≤ `[rsp+0xe8]`, keeps the
  best (max-inlier) pair, then exports the inlier set and LSQ-refits (`sub_1800073f0`→`sub_180006f20`).
  Returns the best inlier count. (callees: `180007390`,`1800073f0`,`180007450`) — KEY transform math.
- `0x180004680` — **transform sanity / degeneracy test** on the fitted `ctx` model (translation &
  scale bounds; thresholds 0x7d0, 0x2260, base 0x1000). Returns 1 if acceptable. (leaf)
- `0x1800043d0` — **final feature/transform refinement** orchestrator run on the winning model;
  writes into `out_rec+0x68`. (deep: `180003320`,`180003ac0`,`180003b50`,`180003ea0`,`180004060`,`1800041d0`) —
  see func_1800043d0.md
- `0x180004600` — sort comparator passed to `sub_1800095c0` (callback, not directly called here).

Transitive math primitives (reached through `sub_180007480`):
- `0x180006e10` — 2-point minimal similarity solve (Q16; uses isqrt `0x180003060`). Output `{b,a,tx,ty}`.
- `0x180006bc0` — apply Q16 similarity transform to one (x,y) point (`+0x8000` round, `>>16`).
- `0x180006f20` — N-inlier least-squares similarity refit.
- `0x180003060` — integer square root (bit-by-bit, `0x40000000` seed).

## GDB verification hooks

(Module base assumed `0x180000000`; rebase if relocated. These pin every intermediate a Python port
must reproduce.)

1. **Entry / arg capture** — `break *0x180004709`
   - `$rcx`=ctx, `$rdx`=kp_from, `$r8`=kp_to, `$r9`=arg4.
   - `x/1gx $rsp+0x388` → out_rec (rbp), `x/1gx $rsp+0x380` → out_score (r14).
   - `p/d *(int*)($rdx+0x8)` = N_from, `p/d *(int*)($r8+0x8)` = N_to.

2. **Count & cap** — `break *0x180004888`
   - `p/d $ebx` → working correspondence count N.
   - `p/d $r15d` → `min(N,25)` (the count actually used). If `< 4` we bail to identity.

3. **Per-correspondence extraction (orientation+aux)** — `break *0x1800049c8`
   - `p/d $eax` → `angle_dist[i]` (sub_180004620 result) — verify the mod-180 metric.
   - dump after the loop: `x/25wx $rsp+0xf0` (orient_from), `x/25wx $rsp+0x1d0` (orient_to),
     `x/25wx $rsp+0x2b0` (aux), `x/25wx $rsp+0x240` (angle_dist; remember the +4 offset → first
     written slot is `rsp+0x240`).
   - point arrays: `x/25gx *(void**)($rsp+0x70)` (from xs), `x/25gx *(void**)($rsp+0x78)` (to ys).

4. **Before RANSAC** — `break *0x180004a49`
   - `$rcx`=ctx; `x/16gx $rsp+0x20` → the full stacked arg block to sub_180007480.
   - `p/d *(int*)($rsp+0xe8)` → the **inlier squared-distance threshold** (load-bearing for the port).
   - `p/d *(int*)($rsp+0xe0)` → the point count the evaluator iterates.

5. **After RANSAC** — `break *0x180004a4e`
   - `p/d $esi` → **best inlier count** returned.
   - dump `ctx`: `x/4wx $r12` → the winning minimal model `{[0],[4],[8],[c]}` =
     `{b, ty, a, tx}` (Q16). These are the raw transform terms before reshuffle.
   - `x/25wx $rsp+0x160` → best-hypothesis FROM index list (signed ints, only first `esi` valid).

6. **Degeneracy test** — `break *0x180004a5c` then `break *0x180004a61`
   - on return `p/d $eax` → sub_180004680 verdict (1=accept). Confirms the 0x7d0/0x2260/0x1000 bounds.

7. **Transform written to out_rec** — `break *0x180004ab7` (after the 4 reshuffled stores)
   - `x/1wx $rbp+0x04` = a, `x/1wx $rbp+0x08` = tx, `x/1wx $rbp+0x0c` = b, `x/1wx $rbp+0x10` = ty.
   - These four u32 are the **sec0_pre rigid transform** — the exact values to diff against the
     decoded template (`dev/decode_sec0_pre.py`).

8. **Score computation** — `break *0x180004b44` (sum) and `break *0x180004b53` (after divide)
   - `p/d $edi` at b44 → `sum(aux[inliers])`; `p/d $eax` at b53 → mean = `*out_score`.

9. **Score/count commit** — `break *0x180004b96`
   - `x/1wx $rbp+0x5c`=score, `x/1wx $rbp+0x60`=n_inliers, `x/1wx $rbp+0x64`=n_used,
     `x/1wx $r14`=out_score. Snapshot the whole record header.

10. **Final refit** — `break *0x180004be9`
    - `$rcx`=&out_rec[0x68], `$r9`=ctx; on return dump `x/32bx $rbp+0x68` to capture the refined
      model. Compare with the captured chip template if matching the refined branch.

11. **Identity fallback** — `break *0x180004b58`
    - Only hit when `<4` inliers. Confirms identity `{b=0x10000, a=ty=tx=0}` and score `0x7fff`.

## Confidence & open questions

**Solid (directly from disasm + verified callees):**
- Overall structure: accessor setup → populate x/y arrays → sort → per-correspondence orientation/aux
  extraction → RANSAC hypothesis-and-vote (`sub_180007480`) → degeneracy test → copy transform to
  out_rec → score = mean(aux over inliers) → optional LSQ/feature refit.
- The transform is a **Q16 2D similarity** `(a,b,tx,ty)` with the apply rule from `sub_180006bc0`,
  estimated minimally by `sub_180006e10` (with integer sqrt) and refit by `sub_180006f20`.
- Constants: cap 25, min 4, stride 0x1c, Q16 1.0=0x10000, sentinel 0x7fff, threshold at `[rsp+0xe8]`,
  prefilter `|Δ|≤0x10`, sanity bounds `0x7d0/0x2260/0x1000`.
- Output record offsets `+0x04/+0x08/+0x0c/+0x10` (transform) and `+0x5c/+0x60/+0x64` (score/counts),
  plus the `+0x68` refit region.
- The score is **mean of the +0x18 aux field over inliers** (or 0x7fff fallback).

**Inferred / GUESS:**
- **Exact a↔b (cos↔sin) labelling.** `sub_180006e10` writes `{[0]=b-ish, [4]=a-ish, [8]=tx, [c]=ty}`
  but `sub_1800046e0` reshuffles to `rbp` as `+0x04=ctx[8]`, `+0x0c=ctx[0]`, `+0x08=ctx[c]`,
  `+0x10=ctx[4]`. Which physical slot is the cos term vs sin term must be pinned by hook #5/#7 against
  a known frame pair. The reshuffle strongly implies out_rec uses **`+0x04=a(cos), +0x0c=b(sin),
  +0x08=tx, +0x10=ty`**, i.e. the same `[a,b,tx,ty]` order `sec0_pre` expects, but confirm.
- The `kp_from`/`kp_to` "point" qword is assumed to pack (x,y); `sub_180006e10` reads them as
  `[+0]=x0,[+4]=y0,[+8]=x1?,[+c]=y1?` per pair — confirm the packing with hook #3.
- `sub_1800095c0` is assumed to be a sort (stride+comparator signature); not transcribed here.
- The `[rsp+0xe8]` threshold and `[rsp+0xe0]` count are set up by the caller above this function's
  visible code (they live in this frame but are written before the `sub_180007480` call by stores not
  all shown in this listing window) — verify their provenance with hook #4 (they are load-bearing).

**Open questions:**
1. Does the `sub_1800043d0` refit (out_rec+0x68) overwrite/supersede the `+0x04..+0x10` transform, or
   is it an independent descriptor block? (Hook #10.)
2. What exactly is the `*(int*)(rsp+0x3d0)` flag tested at 0x180004a4e, and the `rsp+0x3c8` out-flag —
   these gate the degeneracy/reject path; trace where the caller sets them.
3. The two `view` pointers stored at `rsp+0x48/0x50` and passed to the evaluator — their internal use
   is inside `sub_180007480` (the `rsp+0xb0/0xb8/0xc0` reads). Decompile that arg-block fully if a
   byte-exact RANSAC port is needed.
