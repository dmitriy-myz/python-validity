# sub_180006890 — guarded forwarder: fetch element-0 from a container, copy a 24-byte record onto the stack, then dispatch on an index

A tiny dispatcher / wrapper. It reads a container object (arg0), bails out if the container is empty, otherwise grabs the address of its first 24-byte element (via `sub_180006680`), copies that 24-byte record (3 × 8 bytes) into a stack temporary, and forwards it together with an integer index (arg1) to `sub_180006800`. The 24-byte record copied here is almost certainly a transform descriptor / row triple (e.g. a `(qword,qword,qword)` such as `{a, b, t}` or a `{ptr,len,cap}`-style view) consumed by the real worker `sub_180006800`.

## Signature

```c
// rcx = self/container object
//   *(void**)(rcx + 0x00) -> hdr      (pointer to header/control block)
//      *(u32*)(hdr + 0x04) = count/size  (loop/empty guard)
//   *(void**)(rcx + 0x08) = base/handle passed to sub_180006680
// edx = index (zero-extended into r9d, then re-passed as edx to callee)
//
// Returns 0 (eax) on the empty-container fast path; otherwise returns
// whatever sub_180006800 returns (return value is in eax/rax, tail-ish).
uint64_t sub_180006890(void *self /*rcx*/, uint32_t index /*edx*/);
```

Notes / guesses:
- `count` lives at `hdr+0x04` and the guard is `cmp ...,0 ; ja` → **unsigned** "count > 0" test (so it is a `u32` size field). (solid)
- The 24-byte payload at `*(rax)`, `*(rax+8)`, `*(rax+0x10)` returned by `sub_180006680` is copied verbatim; its semantics are defined by `sub_180006680`/`sub_180006800` (inferred to be a transform/record triple — verify there). (inferred)
- `index` is moved through `r9d` only as scratch register juggling; the value actually delivered to the callee is the original `edx`. (solid)

## Pseudocode

```c
uint64_t sub_180006890(void *self /*rcx*/, uint32_t index /*edx*/)
{
    // ---- entry / prologue ----                              // 0x180006890
    // sub rsp,0x58  (frame; holds two stack temporaries: [rsp+0x20] and [rsp+0x38])

    void *hdr = *(void**)((char*)self + 0x00);                 // 0x180006894  mov rax,[rcx]
    uint32_t saved_index = index;                              // 0x180006897  mov r9d,edx  (stash arg1)

    if (*(uint32_t*)((char*)hdr + 0x04) == 0)                  // 0x18000689a  cmp [rax+4],0
        // (ja => unsigned >0; fall through here means count == 0)
    {                                                          // 0x18000689e  ja 0x1800068a7
        // ---- empty-container fast path ----                 // 0x1800068a0
        return 0;                                              // xor eax,eax ; add rsp,0x58 ; ret  (0x1800068a0..0x1800068a6)
    }

L_nonempty: // 0x1800068a7
    // sub_180006680(out=&stack_rec_inner /*rcx=[rsp+0x38]*/, base=*(self+8) /*rdx*/)
    //   -> returns rax = pointer to a 24-byte record (element 0 / current element)
    void *base = *(void**)((char*)self + 0x08);                // 0x1800068a7  mov rdx,[rcx+8]
    void *tmpA = &stack[rsp+0x38];                             // 0x1800068ab  lea rcx,[rsp+0x38]
    void *rec  = sub_180006680(tmpA, base);                    // 0x1800068b0  call 0x180006680  (rax=rec)

    // ---- copy 24 bytes (3 qwords) rec[0..0x17] -> stack temp [rsp+0x20] ----
    void *dst = &stack[rsp+0x20];                              // 0x1800068b5  lea rdx,[rsp+0x20]
    uint64_t q0 = *(uint64_t*)((char*)rec + 0x00);             // 0x1800068ba  mov rcx,[rax]
    *(uint64_t*)((char*)dst + 0x00) = q0;                      // 0x1800068bd  mov [rdx],rcx
    uint64_t q1 = *(uint64_t*)((char*)rec + 0x08);             // 0x1800068c0  mov rcx,[rax+8]
    uint64_t q2 = *(uint64_t*)((char*)rec + 0x10);             // 0x1800068c4  mov rax,[rax+0x10]
    *(uint64_t*)((char*)dst + 0x08) = q1;                      // 0x1800068c8  mov [rdx+8],rcx
    *(uint64_t*)((char*)dst + 0x10) = q2;                      // 0x1800068cc  mov [rdx+0x10],rax

    // ---- forward (record-view, index) to the real worker ----
    // sub_180006800(rec_view=&stack[rsp+0x20] /*rcx*/, index=saved_index /*edx*/)
    void *view = &stack[rsp+0x20];                             // 0x1800068d0  lea rcx,[rsp+0x20]
    uint32_t idx = saved_index;                                // 0x1800068d5  mov edx,r9d
    uint64_t r = sub_180006800(view, idx);                     // 0x1800068d8  call 0x180006800

    // ---- epilogue ----                                      // 0x1800068dd
    return r;                                                  // add rsp,0x58 ; ret (0x1800068dd..0x1800068e1)
}
```

### Control-flow summary
- **Block A (0x180006890–0x18000689e):** prologue, load header, stash index, empty-guard branch.
- **Block B (0x1800068a0–0x1800068a6):** empty → `return 0`.
- **Block C (0x1800068a7–0x1800068e1):** call `sub_180006680`, copy 24B record to `[rsp+0x20]`, call `sub_180006800`, return its result.

## Callees

- `0x180006680` — record/element accessor. Takes `(out=[rsp+0x38], base=*(self+8))`, returns in `rax` a pointer to a 24-byte record (likely "get element 0 / current iterator value" or a small view-builder). See `func_180006680.md`.
- `0x180006800` — the real worker; receives the 24-byte record-view (by address) plus the integer `index` and produces the result this function returns. Likely where the actual coordinate/transform computation lives. See `func_180006800.md`.

## GDB verification hooks

To verify a Python re-implementation produces identical intermediate values, set breakpoints (`break *0x<addr>`) and dump:

1. **`break *0x18000689a`** (just after loading header, before guard)
   - `x/1wx ($rax+4)` → element **count** (the empty-guard value). Confirms whether the fast path (`return 0`) is taken.
   - `p/x $rcx` → `self`; `x/2gx $rcx` → `[self+0]=hdr` and `[self+8]=base`.

2. **`break *0x1800068b0`** (immediately before `call sub_180006680`)
   - `p/x $rcx` → `&[rsp+0x38]` (out buffer).
   - `p/x $rdx` → `base` = `*(self+8)` (the argument that selects which record is fetched).

3. **`break *0x1800068b5`** (immediately after `sub_180006680` returns)
   - `p/x $rax` → **pointer to the 24-byte record** (`rec`).
   - `x/3gx $rax` → the three qwords `rec[0], rec[1], rec[2]` (the raw record contents — compare these byte-for-byte against the Python port; if these are Q16 transform fields, decode as `int32` lo/hi halves).

4. **`break *0x1800068d8`** (immediately before `call sub_180006800`)
   - `x/3gx $rcx` → the 24-byte copy at `[rsp+0x20]` (must equal the `rec` dump above).
   - `p/d $edx` → the `index` actually passed to the worker (should equal the original arg1).

5. **`break *0x1800068dd`** (after `sub_180006800` returns, before epilogue)
   - `p/x $rax` → the **return value** forwarded to the caller. This is the function's overall output (0 only via the fast path at 0x1800068a0).

Priority: hooks #3 and #4 carry the actual record bytes that feed the transform worker; capture them first.

## Confidence & open questions

**Solid:**
- Exact control flow, the empty/`count==0` → `return 0` fast path, and that the guard reads `*(u32*)(hdr+0x04)` with an unsigned `>0` test.
- The 24-byte (3-qword) copy from the `sub_180006680` return into `[rsp+0x20]`, and that this stack view + the original `index` are passed to `sub_180006800`.
- `index` (arg1/`edx`) is preserved through `r9d` and re-delivered unchanged; the value in `r9d` is pure register juggling.
- This function itself contains **no** arithmetic/transform/fixed-point/trig logic — it is a guard + marshal + forward.

**Inferred / to verify in callees:**
- The semantic identity of the 24-byte record. It is plausibly a similarity-transform triple or a `{ptr,len,cap}` view; the field meaning must be read from `sub_180006680` (producer) and `sub_180006800` (consumer).
- Whether `sub_180006680` always returns element 0 or an iterator/current element depends on what `base = *(self+8)` encodes (offset/cursor vs. plain base pointer).
- The return type: treated here as `uint64_t` because the result of `sub_180006800` flows straight to `ret`; could be a narrower int or pointer.
