# sub_180004680 — rigid-transform plausibility / "is this transform sane?" predicate

A tiny leaf predicate (84 bytes, 25 instrs, no callees). It takes a pointer to a
4×int32 transform descriptor and returns `1` if all of its components fall inside
hard-coded tolerance windows, else `0`. In the sec0_pre / frame-registration
context this is almost certainly a **sanity / acceptance gate** on a candidate
rigid 2D similarity transform: it bounds the translation magnitude, the rotation
(off-diagonal) magnitude, and the scale deviation from unity before the transform
is accepted into the geometry pipeline.

It does NOT itself fit a transform — it only validates one. The math is pure
fixed-point integer arithmetic (Q-shifts + squared-magnitude comparisons), no
floats, no trig, no calls.

---

## Signature

```c
// Returns 1 (accept) if the candidate transform passes all three windows, else 0 (reject).
// 'p' points to a 4-int32 packed transform descriptor.
int  sub_180004680(const TransformDesc *p /* rcx */);

// Inferred layout of *p (all int32, signed):
struct TransformDesc {
    int32_t f00;   // +0x00  scale/diagonal-ish term, used as (4096 - (f00>>4))  -> "scale error" measured in Q? units
    int32_t f04;   // +0x04  off-diagonal / rotation term  -> (f04>>4)            -> "rotation/shear" component
    int32_t f08;   // +0x08  translation X (Q12)           -> (f08>>12)           -> dx in some coarse unit
    int32_t f0c;   // +0x0c  translation Y (Q12)           -> (f0c>>12)           -> dy in some coarse unit
};
```

Notes / guesses:
- The two `>>12` fields (f08,f0c) are treated as a **vector** (sum of squares),
  i.e. a squared translation/displacement magnitude. Threshold `0x7d0` = **2000**.
- `f04>>4` is squared and compared on its own to `0x2260` = **8800**.
- `f00` is folded as `0x1000 - (f00>>4)` = `4096 - (f00>>4)` BEFORE squaring,
  i.e. it measures **deviation from a reference value of 4096** (4096 == 1.0 in
  Q12). So `f00` is the diagonal/scale element expressed so that `f00>>4 == 4096`
  means unit scale, and `(4096 - f00>>4)^2 < 8800` bounds the scale error. The
  square root of 8800 ≈ 93.8, so the allowed deviation is ±~93 in `>>4` units
  (≈ ±0.023 in Q12 scale, i.e. roughly ±2.3% scale, very approximate).
- All shifts are `sar` (arithmetic) on signed dword reads → **signed** throughout;
  squaring makes sign irrelevant for the comparison, but the `4096 - x` and the
  `>>` rounding-toward-negative-infinity behaviour are signed-sensitive when
  porting (use Python `>>` on a sign-extended int32, NOT `//`).

## Pseudocode

```c
int sub_180004680(int32_t *p /* rcx */)
{
    // ---- entry / load all four fields ----                         // 0x180004680
    int32_t r8 = p[2];                       // r8d = *(int*)(rcx+0x8)  // 0x180004680  (translation X, Q12)
    int32_t dx = p[3];                       // edx = *(int*)(rcx+0xc)  // 0x180004684  (translation Y, Q12)
    int32_t ax = p[0];                       // eax = *(int*)(rcx+0x0)  // 0x180004687  (scale/diag term)
    int32_t r9 = p[1];                       // r9d = *(int*)(rcx+0x4)  // 0x180004689  (off-diag/rot term)

    dx = dx >> 12;                           // sar edx,0xc            // 0x18000468d  signed >>12
    r8 = r8 >> 12;                           // sar r8d,0xc            // 0x180004690  signed >>12
    ax = ax >> 4;                            // sar eax,0x4            // 0x180004694  signed >>4
    int32_t cx = 0x1000;                     // mov ecx,0x1000 (=4096) // 0x180004697  reference = 1.0 in Q12
    r9 = r9 >> 4;                            // sar r9d,0x4            // 0x18000469c  signed >>4

    dx = dx * dx;                            // imul edx,edx           // 0x1800046a0  (ty>>12)^2
    r8 = r8 * r8;                            // imul r8d,r8d           // 0x1800046a3  (tx>>12)^2
    dx = dx + r8;                            // add edx,r8d            // 0x1800046a7  |t|^2 (coarse)
    cx = cx - ax;                            // sub ecx,eax            // 0x1800046aa  scale_err = 4096 - (f00>>4)

    // ---- gate 1: squared translation magnitude ----                // 0x1800046ac
    if (dx >= 0x7d0 /*2000*/) goto FAIL;     // cmp edx,0x7d0 ; jge    // 0x1800046ac / 0x1800046b2

    // ---- gate 2: squared off-diagonal/rotation term ----           // 0x1800046b4
    r9 = r9 * r9;                            // imul r9d,r9d           // 0x1800046b4  (f04>>4)^2
    if (r9 >= 0x2260 /*8800*/) goto FAIL;    // cmp r9d,0x2260 ; jge   // 0x1800046b8 / 0x1800046bf

    // ---- gate 3: squared scale-error term ----                     // 0x1800046c1
    cx = cx * cx;                            // imul ecx,ecx           // 0x1800046c1  scale_err^2
    if (cx >= 0x2260 /*8800*/) goto FAIL;    // cmp ecx,0x2260 ; jge   // 0x1800046c4 / 0x1800046ca

    return 1;                                // mov eax,1 ; ret        // 0x1800046cc / 0x1800046d1

FAIL:
    return 0;                                // xor eax,eax ; ret      // 0x1800046d2 / 0x1800046d4
}
```

Control flow is fall-through with three forward `jge` branches that all merge at
the single `FAIL` label `0x1800046d2`. There are no loops, no calls, no memory
writes — pure read + compute + boolean return.

Equivalent boolean form:

```c
return  ( (tx>>12)^2 + (ty>>12)^2          <  2000 )   // 0x7d0
     && ( (f04>>4)^2                        <  8800 )   // 0x2260
     && ( (4096 - (f00>>4))^2               <  8800 );  // 0x2260
```

## Struct fields & constants

| Access            | Reg   | Inferred meaning                                                        |
|-------------------|-------|-------------------------------------------------------------------------|
| `*(int*)(rcx+0x0)`| eax   | scale / diagonal element (R[0][0]-ish). Used as `4096 - (v>>4)` → scale error vs unit (4096 == 1.0 Q12) |
| `*(int*)(rcx+0x4)`| r9d   | off-diagonal / rotation element (R[1][0] or shear). Bounded after `>>4` and squaring |
| `*(int*)(rcx+0x8)`| r8d   | translation X, Q12 fixed-point (`>>12` to coarse units)                 |
| `*(int*)(rcx+0xc)`| edx   | translation Y, Q12 fixed-point (`>>12` to coarse units)                 |

| Constant   | Decimal | Role                                                                 |
|------------|---------|----------------------------------------------------------------------|
| `0xc` (12) | 12      | right-shift for f08/f0c → these fields are **Q12** (1.0 == 4096)      |
| `0x4` (4)  | 4       | right-shift for f00/f04 → coarse units before squaring               |
| `0x1000`   | 4096    | reference value (== 1.0 in Q12); `4096 - (f00>>4)` = scale-error term |
| `0x7d0`    | 2000    | max allowed squared translation magnitude `(tx²+ty²)`; √2000 ≈ 44.7  |
| `0x2260`   | 8800    | max allowed squared rotation term AND squared scale-error; √8800 ≈ 93.8 |

Sign/fixed-point porting cautions:
- All field reads are 32-bit signed; all shifts are **arithmetic** (`sar`).
  In Python sign-extend to int32 first, then use arithmetic `>>` (Python `>>`
  on a negative int already floors toward −∞, matching `sar`); do **not** use
  `//` (which behaves differently for the `4096 - x` then square step only at the
  shift, but the square removes sign, so the only sign-sensitive step is the
  floor direction of the shift itself).
- `imul ...,...` here is 32-bit; products of the post-shift magnitudes are small
  (max meaningful operand ≈ a few hundred), so no 32-bit overflow concern in
  practice, but a faithful port should mask/wrap to 32-bit if mirroring exactly.

## GDB verification hooks

Single-arg leaf, so verification is trivial — capture the input struct and the
return value:

- `break *0x180004680` — **entry**. Dump the 4 input fields:
  - `x/4dw $rcx` → `[f00, f04, f08, f10]` (signed dwords). These are the raw
    transform components fed to the predicate. Log alongside the candidate
    transform your Python port produces for the same frame pair.
- `break *0x1800046ac` — after the squared-translation sum is formed.
  - `p/d $edx` → `(f08>>12)^2 + (f0c>>12)^2`  (squared translation magnitude;
    compare to threshold 2000).
  - `p/d $ecx` → `4096 - (f00>>4)`  (scale-error term, **pre-square**).
- `break *0x1800046b8` — after `r9d` is squared.
  - `p/d $r9d` → `(f04>>4)^2`  (squared rotation term; compare to 8800).
- `break *0x1800046c4` — after `ecx` is squared.
  - `p/d $ecx` → `(4096 - f00>>4)^2`  (squared scale error; compare to 8800).
- `break *0x1800046d1` (accept) and `break *0x1800046d2` (reject) — which path
  was taken. Or simply `break *0x180004680` and read `$eax` after `finish`:
  `1` = accepted transform, `0` = rejected.

Suggested one-shot dump at entry to drive a Python equality test:
```
break *0x180004680
commands
  printf "in: f00=%d f04=%d f08=%d f0c=%d\n", *(int*)$rcx, *(int*)($rcx+4), *(int*)($rcx+8), *(int*)($rcx+0xc)
  finish
  printf "out=%d\n", $eax
  continue
end
```

Python reference to check against the dumps:
```python
def sub_180004680(f00, f04, f08, f0c):
    import ctypes
    s32 = lambda v: ctypes.c_int32(v).value
    t  = (s32(f08) >> 12)**2 + (s32(f0c) >> 12)**2          # vs 2000
    rot = (s32(f04) >> 4)**2                                # vs 8800
    sc  = (0x1000 - (s32(f00) >> 4))**2                     # vs 8800
    return int(t < 0x7d0 and rot < 0x2260 and sc < 0x2260)
```

## Confidence & open questions

**Solid (directly from disasm):**
- Exact arithmetic, shifts (all `sar`/signed), the three thresholds
  (2000, 8800, 8800), the 4096 reference, the field offsets, the
  return-1/return-0 boolean semantics, and the address of every block.
- It is a leaf predicate (no calls, no writes, no loops).

**Inferred (interpretation, not certain):**
- The *labels* "translation X/Y", "rotation/off-diagonal", "scale/diagonal".
  The shift amounts strongly suggest f08/f0c are a Q12 translation pair (summed
  as a vector → magnitude gate) and f00 is a scale/diagonal term measured against
  4096==1.0 in Q12. f04 being the rotation/off-diagonal element is the natural
  remaining slot. The `R=[[a,-b],[b,a]]`, `t=(tx,ty)` similarity-transform shape
  from the wider sec0_pre context fits: f00≈a (diag), f04≈b (off-diag), f08=tx,
  f0c=ty. But the disasm alone does not prove which packed slot is `a` vs `b`.
- Whether the input struct is exactly the Q16 sec0_pre transform or a derived
  reduced descriptor. Note f00/f04 use `>>4` while f08/f0c use `>>12`, so the
  four fields are NOT all the same fixed-point scale in this struct — the diag/
  off-diag terms appear coarser (or pre-scaled) than the translation terms.
  Confirm by inspecting the caller `sub_1800046e0` and the actual byte layout it
  passes in `rcx`.

**Open questions for the caller (`sub_1800046e0`):**
- Exactly how the 4-int32 descriptor is assembled (is f00 already `a*scale`, or a
  residual?). The `4096 - (f00>>4)` form implies f00 is centered on 4096 in `>>4`
  units (i.e. f00 ≈ 65536 == 1.0 in Q16, since `65536>>4 == 4096`). That strongly
  hints **f00 and f04 are Q16** (a,b in `R=[[a,-b],[b,a]]`, a==65536==1.0) while
  **f08,f0c are Q12** translations — worth confirming, since it pins down the
  fixed-point format of the matrix vs translation in sec0_pre.
