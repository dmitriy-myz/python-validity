# sub_1800030a0 — fixed-point `atan2` (vector angle / orientation, integer-only)

Leaf function (no callees). Pure integer fixed-point math. Given two signed
integer components `(a1, a2)` it returns the **angle of the vector**, computed as
`atan2(a1, a2)` (note the swapped argument order vs. the C convention
`atan2(y, x)`), expressed in the driver's internal angle unit
(**1136 units per degree → 408960 units = full circle**).

It is a minimax/Horner polynomial atan approximation on the reduced ratio
`min(|a1|,|a2|) / max(|a1|,|a2|)`, followed by octant/quadrant reflection
fix-ups using the signs and the magnitude comparison. The intermediate value
just before the final scale is the angle in **degrees·65536 (Q16 degrees)**,
range `[0, 0x1680000)` i.e. `[0°, 360°)`.

This is the angle primitive used to build per-keypoint orientation and the
rotation component of the rigid/similarity transforms (the `cos·65536` /
`sin·65536` style `a`,`b` values) that feed `sec0_pre`.

## Signature

```c
// Returns vector angle in driver angle-units (1136 per degree, 0..408960 == 0..360deg).
// Computed as atan2(a1, a2) measured from the a2 axis toward the a1 axis.
//   a1 (ecx): first vector component  (X-like; sign selects 0/360-deg reflection)  [GUESS: dx]
//   a2 (edx): second vector component (Y-like; sign selects 180-deg reflection)    [GUESS: dy]
int32_t fixed_atan2(int32_t a1 /*ecx*/, int32_t a2 /*edx*/);
```

Notes / inference:
- The function is `__fastcall`-style: `ecx = a1`, `edx = a2`. No stack args, no
  callee-saved registers touched, no memory accessed → a pure scalar helper.
- "a1 = X, a2 = Y" is a guess for naming; what is *certain* is that the returned
  angle equals `atan2(a1, a2)` (verified numerically against `math.atan2(a1,a2)`
  to within the polynomial's ~0.3–0.5° error). The sign tests confirm: a2<0 →
  reflect about 180°, a1<0 → reflect about 360°.

## Pseudocode

```c
int32_t fixed_atan2(int32_t a1 /*ecx*/, int32_t a2 /*edx*/)
{
    // ---- entry: save originals, take absolute values --------------------- 0x1800030a0
    //   r10d = a2 (kept for sign test), r11d = a1 (kept for sign test)
    int32_t a2_orig = a2;                       // r10d = edx           // 0x1800030a2
    int32_t a1_orig = a1;                       // r11d = ecx           // 0x1800030a5
    int32_t abs_a2  = a2;                        // r8d  = edx          // 0x1800030a8
    if (a2 <= 0) abs_a2 = -abs_a2;               // jg / neg r8d        // 0x1800030ab / 0x1800030ad
    int32_t abs_a1  = a1;                        // r9d  = ecx          // 0x1800030b2
    if (a1 <= 0) abs_a1 = -abs_a1;               // jg / neg r9d        // 0x1800030b5 / 0x1800030b7

    // ---- order so that num=smaller magnitude, den=larger magnitude ------- 0x1800030ba
    int32_t num, den;                            // cmp r8d,r9d         // 0x1800030ba
    bool a2_ge_a1 = (abs_a2 >= abs_a1);          // jge 0x1800030c7     // 0x1800030bd
    if (!a2_ge_a1) {                             // |a2| <  |a1|
        num = abs_a2;  den = abs_a1;             // eax=r8d; ecx=r9d    // 0x1800030bf / 0x1800030c2
    } else {                                     // |a2| >= |a1|
        num = abs_a1;  den = abs_a2;             // eax=r9d; ecx=r8d    // 0x1800030c7 / 0x1800030ca
    }                                            // jmp 0x1800030cd     // 0x1800030c5

    // ---- reduced ratio t = (num<<8)/(den+1) <<8  (Q? fixed-point ratio) -- 0x1800030cd
    den += 1;                                    // add ecx,1           // 0x1800030cd  (avoid /0)
    int32_t eax = num << 8;                      // shl eax,8           // 0x1800030d0
    // cdq + idiv: SIGNED 32-bit divide; num>=0 here so quotient >= 0
    eax = (int32_t)(eax / den);                  // cdq; idiv ecx       // 0x1800030d3 / 0x1800030d4
    eax = eax << 8;                              // shl eax,8           // 0x1800030d6   eax now ~ ratio<<16-ish
    int32_t t = eax;                             // ecx = eax           // 0x1800030d9

    // ---- build two working terms from t ---------------------------------
    int32_t x  = t >> 4;                         // sar eax,4   (x  = linear term)   // 0x1800030db
    int32_t x2 = t >> 6;                         // sar ecx,6                         // 0x1800030de
    x2 = x2 * x2;                                 // imul ecx,ecx  (square)            // 0x1800030e1
    x2 = x2 >> 4;                                // sar ecx,4                          // 0x1800030e4
    x2 = x2 >> 4;                                // sar ecx,4   -> x2 ~ t^2 scaled     // 0x1800030e7
    //   x2 is the "squared ratio" used as the polynomial variable (call it s).

    // ---- Horner polynomial in s (=x2), all Q12 (>>0xc) accumulation ------ 0x1800030ea
    int32_t p = x2;                              // edx = ecx (= s)                    // 0x1800030ea
    p = p * (int32_t)0xFFFFF5D7;                 // imul edx,edx,-0x0A29  (= -2601)    // 0x1800030ec
    p = p >> 12;                                 // sar edx,0xc                        // 0x1800030f2
    p = p + 0x23A7;                              // add edx,0x23A7  (= +9127)          // 0x1800030f5
    p = p * x2;                                  // imul edx,ecx                       // 0x1800030fb
    p = p >> 12;                                 // sar edx,0xc                        // 0x1800030fe
    p = p - 0x4AAC;                              // sub edx,0x4AAC  (= -19116)         // 0x180003101
    p = p * x2;                                  // imul edx,ecx                       // 0x180003107
    p = p >> 12;                                 // sar edx,0xc                        // 0x18000310a
    p = p + 0xE522;                              // add edx,0xE522  (= +58658)         // 0x18000310d
    //   p = ((( -2601*s>>12 + 9127)*s>>12 - 19116)*s>>12 + 58658)
    p = p * x;                                   // imul edx,eax  (multiply by linear) // 0x180003113
    p = p >> 6;                                  // sar edx,6                          // 0x180003116
    //   p == atan( num/den ) in Q16 DEGREES, i.e. value in [0, 45*65536].

    // ---- octant / quadrant reflections (build full 0..360 angle) --------- 0x180003119
    if (!a2_ge_a1) {                             // cmp r8d,r9d; jge 0x180003127       // 0x180003119
        // |a2| < |a1|: we computed atan(|a2|/|a1|); complement to 90deg
        p = 0x5A0000 - p;                        // 0x5A0000 == 90deg<<16              // 0x18000311e
    }
    if (a2_orig < 0) {                           // test r10d; jns 0x180003135         // 0x180003127
        // a2 negative -> reflect about 180deg
        p = 0xB40000 - p;                        // 0xB40000 == 180deg<<16             // 0x18000312c
    }
    if (a1_orig < 0) {                           // test r11d; jns 0x180003143         // 0x180003135
        // a1 negative -> reflect about 360deg
        p = 0x1680000 - p;                       // 0x1680000 == 360deg<<16            // 0x18000313a
    }
    //   p is now the angle in Q16 degrees, in [0, 0x1680000) == [0deg, 360deg).

    // ---- convert Q16-degrees -> internal angle unit (1136 per degree) ---- 0x180003143
    p = p >> 8;                                  // sar edx,8                          // 0x180003143
    p = p * 0x47;                                // imul edx,edx,0x47  (*71)           // 0x180003146
    p = p >> 4;                                  // sar edx,4   (/16) -> *71/4096 *256 // 0x180003149
    return p;                                    // eax = edx; ret                     // 0x18000314c / 0x18000314e
    //   scale = (>>8)*71>>4 == deg_q16 * 71/4096; full circle 0x1680000 -> 408960.
}
```

Note for the porter: the polynomial coefficients (`-2601, +9127, -19116, +58658`)
and the shift schedule are an *approximation* — to be byte-exact you must
reproduce the **integer truncating** `idiv` and arithmetic `sar` (floor toward
negative infinity for negatives, but here all operands feeding shifts are
non-negative until the reflection subtractions) exactly. Do **not** substitute a
floating `atan2`.

- `break *0x1800030a0` — **entry**. Dump `ecx` (= a1) and `edx` (= a2). These are

- `break *0x1800030d6` — right **after the divide**, before `shl eax,8`. Dump

  `idiv`/rounding). Also dump `r8d`(=|a2|), `r9d`(=|a1|).
- `break *0x1800030ea` — polynomial variable ready. Dump `ecx` (= `s`, the
  squared-ratio var, written to `edx` next) and `eax` (= `x`, the linear term).
- `break *0x180003116` — **after `*x; >>6`** (instruction at `0x180003113`/`6`).
  Dump `edx` = the raw `atan(num/den)` in **Q16 degrees, range [0,0x5A0000]**
  (i.e. ≤ 90°). This is the core polynomial output before any octant reflection —
  the single most important value to match.
- `break *0x180003143` — **after all reflections**, before the unit scale. Dump
  `edx` = full-circle angle in **Q16 degrees, [0,0x1680000)**. Divide by 65536.0
  to read as degrees and compare with `math.atan2(a1,a2)`.
- `break *0x18000314c` (and `0x18000314e` ret) — **final**. Dump `edx`/`eax` =
  return value in internal angle units (`degrees×1136`). This is what callers
  store; match it exactly.

- `0x1800030a0`: inputs `(a1=ecx, a2=edx)`
- `0x180003116`: `atan_q16deg = edx`  (0..0x5A0000)

## Confidence & open questions

**Solid (high confidence):**
- Function is a pure leaf integer `atan2`. Verified numerically: pre-scale value
  equals `atan2(a1, a2)` in Q16 degrees across all 8 octants (table above).
- Argument order is swapped vs. C `atan2`: result = `atan2(a1=ecx, a2=edx)`,
  measured from the `a2` axis. (At `a1=0,a2=+` → 0°; at `a1=+,a2=0` → 90°.)
- Fixed-point/signedness facts: `cdq;idiv` is a **signed** divide; all `sar` are
  arithmetic; `0x...5D7` is the **negative** coeff −2601 (sign-extended `imul`).
- Constants `0x5A0000/0xB40000/0x1680000` are exactly 90/180/360 × 65536, and the
  final `(>>8)*71>>4` gives a `1136-per-degree` unit (full circle 408960).
- No struct/memory access; no callees.

**Inferred / open:**
- Naming `a1=dx`, `a2=dy` is a guess from typical orientation usage; the code only
  fixes the *relationship* `atan2(a1,a2)`. Confirm at call sites which physical
  quantity is passed first.
- The exact intermediate scaling of `s`/`x` (the `>>4/>>6/>>4/>>4` schedule) is
  transcribed faithfully but its individual "meaning" (which Q-format `s` lives
  in) is only meaningful as a whole; the polynomial was clearly fit to that
  schedule. Port the shift schedule verbatim — do not "simplify" it.
- Why `1136/degree` rather than a power-of-two BAM unit is unexplained; likely a
  legacy/source-units choice. The downstream consumer (orientation field /
  transform builder) presumably uses the same unit; verify there.
