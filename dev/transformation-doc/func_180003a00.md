# sub_180003a00 — clipped rectangle (box) fill into a byte image buffer

This is a **leaf function** (no callees). It is a small integer-only rasterizer: given an
element index into a 32-byte struct array, it reads that element's (x, y) center, builds an
axis-aligned box `[x-delta .. x+delta] × [y-delta .. y+delta]`, clips it to the image bounds
`[0..width] × [0..height]`, and memset-fills that box in a 1-byte-per-pixel `width`-stride buffer
with a constant byte value.

It is **not** rigid/similarity-transform math (no Q16 fixed point, no >>16, no trig, no matrix).
It looks like a "paint a square mask around keypoint N" helper (e.g. suppression/occupancy mask
or a debug/visualisation splat) used elsewhere in the pipeline. Recorded here for completeness of
the call-graph sweep.

## Signature

```c
// All coordinates are signed 32-bit ints; width/height/fill arrive as bytes (zero-extended).
void sub_180003a00(
    uint32_t idx,         // rcx  : element index; scaled ×32 → byte offset into the struct array
    int32_t  delta,       // rdx  : half-extent / radius of the box around the center (signed)
    uint8_t  fill,        // r8b  : the byte value written into every covered pixel (only low 8 bits used; via ebx/bl)
    uint8_t  width,       // r9b  : image width AND row stride (clamp ceiling for x; 0..255)
    uint8_t  height,      // [rsp+0x28] : image height (clamp ceiling for y; 0..255)
    uint8_t *buf,         // [rsp+0x30] : output image buffer, 1 byte/pixel, stride = width
    void    *elem_base);  // [rsp+0x38] : base pointer of the 32-byte-stride struct array
```

Notes / guesses:
- `width` is used both as the x-clamp ceiling and as the row stride (`offset = y*width + x`), so the
  buffer is exactly `width × height` bytes, row-major. (solid — see 0x180003a67 stride mul)
- `delta` is read as a signed 32-bit value (`sub edi,edx` etc., compared with `cmovs`), even though
  it is almost certainly small/positive in practice. (inferred)
- `fill` / `width` / `height` are loaded with `movzx`/`movzx esi,r9b` / `movzx eax,BYTE PTR [rsp+0x28]`
  → only the low byte matters. (solid)
- Return type `void` (eax is not set on the return path; nothing meaningful returned). (solid)

## Pseudocode

```c
void sub_180003a00(uint32_t idx, int32_t delta, uint8_t fill,
                   uint8_t width, uint8_t height, uint8_t *buf, void *elem_base)
{
    // ---- prologue: save callee-saved regs (home-area spills) ----      // 0x180003a00
    // [rsp+0x08]=rbx, [rsp+0x10]=rsi, [rsp+0x18]=rdi                      // 0x180003a00..0x180003a0a

    void *elem_base = *(void**)(rsp + 0x38);    // rax = arg6             // 0x180003a0f
    uint32_t W      = (uint8_t)width;            // esi = movzx r9b        // 0x180003a14  (image width / stride)
    uint64_t off32  = (uint64_t)idx << 5;        // r10 = idx * 32         // 0x180003a18..0x180003a1b
    uint8_t  fill_b = (uint8_t)fill;             // ebx = r8d (only bl used later) // 0x180003a1f
    // r8d = 0  -> a reusable "zero" constant for the cmovs clamps        // 0x180003a22

    // read this element's center coordinates from the 32-byte struct
    int32_t cx = *(int32_t*)(elem_base + off32 + 0x14);   // r11d         // 0x180003a28  (X center)
    int32_t cy = *(int32_t*)(elem_base + off32 + 0x18);   // ecx          // 0x180003a2d  (Y center)
    uint32_t H = (uint8_t)height;                          // eax = [rsp+0x28] // 0x180003a32 (image height)

    int32_t x0 = cx;                  // edi                              // 0x180003a37
    int32_t y1 = cy + delta;          // r9d = lea [rcx+rdx]              // 0x180003a3a   (bottom, pre-clip)
    int32_t y0 = cy;                  // r10d                            // 0x180003a3e

    // ---- clip the box to [0..W] x [0..H] ----
    x0 = cx - delta;                  // sub edi,edx                      // 0x180003a41
    if (x0 < 0) x0 = 0;               // cmovs edi, 0                     // 0x180003a43   (left edge >= 0)
    y0 = cy - delta;                  // sub r10d,edx                     // 0x180003a47
    if (y0 < 0) y0 = 0;               // cmovs r10d, 0                    // 0x180003a4a   (top edge >= 0)

    int32_t x1 = cx + delta;          // add r11d,edx                     // 0x180003a4e
    if (x1 > (int32_t)W) x1 = W;      // cmp r11d,esi; cmovg r11d,esi     // 0x180003a51..0x180003a54  (right clamp to width)
    if (y1 > (int32_t)H) y1 = H;      // cmp r9d,eax;  cmovg r9d,eax      // 0x180003a58..0x180003a5b  (bottom clamp to height)

    // empty box? (rows)  NOTE: signed values, unsigned compare 'jae'
    if ((uint32_t)y0 >= (uint32_t)y1) goto done;  // cmp r10d,r9d; jae    // 0x180003a5f..0x180003a62

    // ---- set up row walk ----
    // base byte offset of the first pixel to write = y0*W + x0
    uint32_t cur = W * y0 + x0;       // r8d = esi*r10d ; add r8d,edi     // 0x180003a64..0x180003a6b
    uint32_t rows = y1 - y0;          // r9d -= r10d                      // 0x180003a6e
    uint32_t rowcnt = rows;           // r10d = r9d  (loop counter)       // 0x180003a71
    uint8_t *out = buf;               // r9 = [rsp+0x30]                  // 0x180003a74
    // (0x180003a79/0x180003a7c are NOP padding for loop alignment)

    // ---- outer loop over rows ----
    do {                                                                   // L_row: 0x180003a80
        if ((uint32_t)x0 >= (uint32_t)x1) goto next_row;  // cmp edi,r11d; jae 0x180003a9f // 0x180003a80..0x180003a83
        int32_t  width_px = x1 - x0;          // edx = r11d - edi          // 0x180003a85..0x180003a8b
        uint32_t p        = cur;              // ecx = r8d                 // 0x180003a88
        int64_t  n        = width_px;         // rdx = (sign-extended) count // 0x180003a85/0x180003a8b

        // ---- inner loop: fill the row span [x0..x1) with fill_b ----
        do {                                                               // L_col: 0x180003a90
            uint32_t a = p;                   // eax = ecx                 // 0x180003a90
            p++;                              // add ecx,1                 // 0x180003a92
            n--;                              // sub rdx,1                 // 0x180003a95
            out[a] = fill_b;                  // mov [rax + r9], bl        // 0x180003a99  *** PIXEL WRITE ***
        } while (n != 0);                     // jne L_col                 // 0x180003a9d

    next_row:                                                              // 0x180003a9f
        cur  += W;                            // add r8d, esi (advance one row) // 0x180003a9f
        rowcnt--;                             // sub r10, 1                // 0x180003aa2
    } while (rowcnt != 0);                    // jne L_row                 // 0x180003aa6

done:
    // ---- epilogue: restore callee-saved regs ----                       // 0x180003aa8
    // rbx=[rsp+0x08]; rsi=[rsp+0x10]; rdi=[rsp+0x18]                       // 0x180003aa8..0x180003ab7
    return;                                                                // 0x180003ab7
}
```

Behavioral notes:
- The inner-loop bound `n` is sign-extended (`sub rdx,0x1` on the 64-bit register after `mov edx,...`),
  but the loop is `do{}while(n!=0)`, so it always writes at least one byte whenever the row is entered.
  The row is entered only when `x0 < x1` (the `jae` guard), guaranteeing `width_px >= 1`. (solid)
- Likewise the outer loop is `do{}while`, entered only after the `y0 >= y1` guard fails, so `rows >= 1`. (solid)
- The fill value is taken from `bl` (low byte of the saved `r8d`/`ebx`). (solid)
- The pixel address is computed purely in 32-bit (`r8d`/`eax`) then used as `[rax + r9]`; i.e.
  `buf[ (y*W + x) ]`. No 2D pointer arithmetic beyond the linear offset. (solid)

## GDB verification hooks

Target a port-verification harness that reproduces the same pixel writes. Break and dump:

1. `break *0x180003a32` — **after the center is loaded, before clipping.**
   - `r11d` = cx (X center, signed)
   - `ecx`  = cy (Y center, signed)
   - `edx`  = delta (the box half-extent, arg1)
   - `esi`  = W (image width / stride)
   - `eax`  = H (image height) *(loaded on this very instruction; read after stepping it)*
   - `ebx`  = fill byte (low 8 bits = bl)
   - Also dump `idx` indirectly: `r10 >> 5` (since `r10 = idx<<5`).

2. `break *0x180003a64` — **right after the empty-box guard passes; all four clipped edges are final.**
   - `edi`   = x0 (clipped left)
   - `r11d`  = x1 (clipped right)
   - `r10d`  = y0 (clipped top)
   - `r9d`   = y1 (clipped bottom)
   - Verify: `0 <= x0`, `x1 <= W`, `0 <= y0`, `y1 <= H`, and `y0 < y1`.
   - This is the cleanest single point to confirm the clip math matches a Python re-implementation.

3. `break *0x180003a6b` — **after the start offset is computed.**
   - `r8d` = `cur` = `W*y0 + x0` (first byte offset written). Compare to Python `y0*W + x0`.

4. `break *0x180003a99` — **the actual pixel write (hot; conditional logging recommended).**
   - `eax`        = byte offset being written this iteration
   - `r9`         = `buf` base pointer
   - `bl`         = fill value
   - To verify the *set* of written offsets without stopping per-byte, instead inspect the buffer
     once at `0x180003aa8` (`done`): dump `*(uint8_t[H*W]*)$buf` and diff against the Python mask.

5. `break *0x180003aa8` — **function exit.** Dump the full `buf` region (`W*H` bytes from `[rsp+0x30]`)
   to compare the final filled rectangle byte-for-byte. This is the end-to-end check.

## Confidence & open questions

**Solid:**
- Overall shape: clipped axis-aligned rectangle fill of a `width`-stride, 1-byte/pixel buffer. The
  stride multiply (`imul r8d,r10d` with `esi`=W), the `+= W` per row, and the byte store `[rax+r9]=bl`
  are unambiguous.
- Struct stride 0x20, center fields at +0x14 (x) and +0x18 (y).
- Clamp semantics: left/top floored to 0, right/bottom capped at W/H; empty-box early-out via unsigned
  `y0 >= y1`.
- Leaf function — no callees.

**Inferred / open:**
- Field *names* (cx/cy) and what the 32-byte struct actually is (keypoint record? candidate box?).
  Offsets +0x14/+0x18 are consistent with the keypoint/candidate structs seen elsewhere in this RE
  effort, but that should be cross-checked against the producer of `elem_base`.
- Whether `delta` can legitimately be negative. The code is written defensively (signed subs + cmovs),
  but in practice it is presumably a small positive radius.
- Purpose in the larger pipeline: most likely an occupancy/suppression/visited mask splat (paint a
  square around keypoint N), or a debug-visualisation splat. **It does not participate in the Q16
  rigid/similarity-transform computation** that feeds `sec0_pre`; flag it as out-of-scope for the
  transform-math hunt.
- Unsigned vs signed compare at `0x180003a62` (`jae`): if any clipped edge were ever negative it would
  behave oddly, but the prior cmovs clamps guarantee `x0,y0 >= 0`, so the unsigned compare is safe.
